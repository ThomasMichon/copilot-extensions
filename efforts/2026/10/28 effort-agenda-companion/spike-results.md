# Initial Paired Spike - Results

Evidence for [Phase 1S of the canonical effort](README.md), following the
[predeclared protocol](paired-spike.md). This is one feasibility pair, not a
claim of statistically established improvement.

## Setup and exposure

- Two managed fixture worktrees started from the identical pinned fixture
  commit, with independent Git clones/offline origins and isolated journals.
- Both general-purpose attempts received the same task, facts, ordinary effort
  contract, permissions and requested defaults. No model override was used.
  The resolved provider model/version and credit/token usage were unavailable.
- Both had a cooperative 15-minute/60-tool-call limit, not a provider-enforced
  hard budget. They ran concurrently, with no mid-attempt coaching.
- Only treatment received the reviewed skill/reference beside its journal,
  copied from the guidance delivered in
  [#9421](https://github.com/ThomasMichon/copilot-extensions/pull/9421).
  Its journal explicitly records reading both documents fully; it did not
  need the example assets. No candidate was installed globally.
- The task was exact category filtering of CSV records, a prerequisite parser
  repair, and an assigned category-counts follow-up. A CLI wishlist was
  explicitly nonblocking. Existing checks passed in both starting copies;
  the independent acceptance packet failed before implementation as intended.

## Observed outcomes

| Measure | Control | Treatment |
|---------|---------|-----------|
| Independent predeclared acceptance | 8/8 passed | 8/8 passed |
| Prerequisite and parent return | Parser repaired, filter resumed and validated | Saved child return, verified parser, popped once and resumed filter |
| Assigned follow-up | Counts completed | Queued counts root selected after parent gate, then completed |
| Scope | CLI idea parked, no publication or services | CLI idea parked, no publication or services |
| Completion record | Canonical fixture effort Done and journal | Canonical effort Done, journal plus completed-root/detour cursor history |
| Agent-reported local suite at initial completion | 13 passed | 17 passed |
| Receipt elapsed observation | About 157 seconds | About 256 seconds |

Receipt elapsed values are coarse harness observations, not a controlled
performance benchmark. The treatment produced additional process artifacts;
token/credit data is unknown, not zero. Both met the original eight-case packet,
so no functional superiority is inferred from this pair or the test-count
difference.

The treatment retained its personal agenda and cursor beside the journal,
recorded the parser return at revision 2, switched from the completed parent
to the already-assigned counts root, and completed at revision 6 with an empty
active stack/queue and preserved completed roots. This demonstrates that the
manual work-stack procedure was usable in this fixture.

## Post-measurement compatibility observation

The reports exposed a further ordinary-input case: a leading blank line before
the CSV header. A separate, equal check on both completed outputs found a
control `KeyError` and a treatment pass. This was **not** in the predeclared
eight-case packet and is not retroactively used as the paired score or a causal
guidance-effect claim.

The control then received a clearly separated remediation request, added a
focused regression and reported 14 tests passing. Its original journal/results
were preserved with an appended post-spike entry. Raw control source files now
reflect that remediation; the initial result is evidenced by the earlier
independent checks and logs rather than a frozen original source snapshot.
Future repetitions should freeze each output before any post-measurement fix.

## Helper decision

The successful manual treatment used additional state/history fields and omitted
the example's cursor version while remaining legible. This is format friction,
not failure of the original task. There is no evidence here requiring an
automatic transition engine, scheduling or new journal provider.

The admitted helper slice is therefore **read-only next/check inspection**:
derive the active answer deterministically from the journal-local snapshot,
diagnose wrong/stale references, budgets and parent-return shape, preserve
unknown/history fields by never writing, and accept the initial manual
version-less cursor with an explicit compatibility note.

Scaffolding remains copy/edit of examples; no advance/call/return/reset writer,
CAS transaction or automatic external-effect evaluation is introduced. The
standalone manual process remains usable without the helper.

## Limits and next action

No randomization, matched interruption, deep nested execution or statistical
replication was performed. Configuration was matched as requested, but actual
provider model versions were not independently observed. Functional checks were
identical and outside editable worktrees; trajectory review was not blinded.
These limits rule out a general comparative efficacy claim.

The next slice is bounded helper and manual-contract qualification, including
invalid snapshot/return cases, explicit journal-home placement and Windows/
Linux behavior. Continue through the effort's remaining validation and review
gates; do not treat this successful pair as the root effort completing itself.
