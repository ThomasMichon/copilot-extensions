## Subject-owned bootstrap and repository restore

The driven subject must carry out the original ordered outcome:

1. Install Copilot **through WinGet** from the minimal starting state.
2. Register the configured external marketplace and install the **one declared
   seed plugin through that marketplace**, not a preassembled suite.
3. **AND establish that plugin's runtime** through its declared installation/
   setup owner, using the Python/uv installed by the bootstrap. Installing the
   plugin and setting up its runtime are BOTH required, not alternatives.
   Record bootstrap-installed prerequisites separately from seed-installed
   runtime and later resources.
4. Run repository-scoped `agent-machines plan`, `validate` and `restore --apply`
   for **the checked-out repository only**, then verify its actual postconditions.
   Do not apply unrelated repositories, machine inventories or private defaults.

The historical "seed plugin provisions its runtime" requirement means the
seed's documented setup/install path, not implicit installation from loading,
session startup or readiness inspection. Preserve
[independent installation ownership](../../../visions/plugin-services/README.md#connector-only-plugin-payloads)
and [authoritative runtime replacement](../../../visions/installer/README.md#authoritative-runtime-replacement):
incoming readiness and all applicable selections define installation success,
with outgoing recovery/cleanup and protected resources handled independently.
Do not restore an obsolete self-provisioning mechanism merely to imitate an
old example, or credit plugin visibility as runtime readiness.
