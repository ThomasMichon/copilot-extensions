Back to the [canonical effort](../../README.md).

## Review corrections

The ordinary send/read/wait default slice missed two existing consumers. The
root project guard still required an explicit `--bridge` for observations.
It now uses the effective selector, while legacy and specialized observations
still reject unsupported project scope before constructing a client.

Dispatch's fleet continuation used plain send syntax without the startup
options that its local continuation already supplied. Both paths now use one
pure argument producer for the existing startup-bound continuation form.
This keeps the hosting fence, original stdin, wait choice and SSH wall timeout.
It adds no help probe, transport call, retry or new selector flag on older
executables. A read-only older CLI help check confirms the startup options
exist there and the new compatibility selector does not.

## Remaining startup and observation producers

The controller's project is not proof of its worker's project. The ordinary
and acquisition observation producers previously emitted unscoped waits.
They retain their existing wait operation through child-scoped
`AGENT_BRIDGE_LEGACY_OBSERVATION=1`. The new CLI reads that configuration inside
its existing operation; an older CLI ignores it and already uses that same
operation. Explicit exact selection still wins. Arguments, output, cursor
identity, parent environment and subprocess deadline remain unchanged, with
no capability probe, extra process or retry.

Worktree startup and reclaim now use the same startup-bound send producer.
Their caller identities and original prompt input remain intact. Missing
session identity refuses before send or end. The existing reclaim guards and
every prior test assertion remain; generic and fixture annotations let the
whole changed files pass strict checking. The skill and linked CLI reference
make profile, venue and implicit-resume selection explicit.

all original source/coverage entries and the 300-second budget. The contained
