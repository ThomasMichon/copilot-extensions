## Delivered source and corrected boundaries

- Optional payload-local managed initialization negotiates the selected existing
  allocator, explicitly allocates a fresh home and accepts the same declared
  store identity. Requests are detached before provider waits. Shared writer
  preparation checks generated state, records, result and caller-metadata
  bounds before allocation; no deterministic oversized request strands a lane.
- Exact retries retain the original accepted result even after later agenda
  updates. Schema/policy checks occur under the write lock, so overlapping
  initializers cannot reuse a stale zero-version observation and rewrite
  database bytes while reporting an unaccepted retry.
- Unrelated home contents require a readable matching accepted store.
  An empty or interrupted database alone is not acceptance evidence.
  Existing standalone/legacy behavior remains; no active lane is migrated.
- Placement DTOs canonicalize only the admitted project root and verify its
  device/inode scope before appending validated children. Root aliases work
  without weakening child-path checks or changing descriptor bytes, identity
  or generation.
- The efforts owner supplies a complete read-only SQLite snapshot and manifest,
  preserving every declared accepted operation, original request/result,
  immutable context/evidence record, metadata and delivery state. Bounded history
  pages and rendered summaries are not credited as complete exports.
- New delivery projections use the captured acceptance time. Complete older
  observations remain compatible at bounded owner-projection frontiers without
  inventing their actual projection times or rewriting accepted bytes.
- Export/readback reuses the writer's pure request, initialization and typed
  operation grammar. Malformed stored requests refuse even after recomputing
  transport/table hashes. This does not replay movement or prove permission,
  productive judgment, historical semantic admission or an external outcome.
