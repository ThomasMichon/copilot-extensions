## Paired elapsed-clock investigation

The retained failed trace reaches the second selected snapshot's first row
check after SQL work, not the initial empty authority snapshot. It has no
historical paired-clock or per-stage evidence.

CPython 3.12's Windows monotonic implementation uses `GetTickCount64`, while
`perf_counter` uses `QueryPerformanceCounter`; both measure elapsed time,
including scheduling and sleep. Quantization is a hypothesis, not an
established explanation of the earlier failure.

The optional actual-seed diagnostic now brackets original budget creation and
checks with the high-resolution elapsed clock while leaving the original
check, limits, result and exception unchanged. It reports clock metadata,
VM steps and bounded last-check samples. All instrumentation time still counts
toward the existing deadline. Portable controls distinguish a quantized early
refusal from true elapsed work and verify one call, original failure and
factory restoration. A separate bounded native control reports whether actual
clock disagreement was observed; a pass with no disagreement is explicitly
not a reproduction. Native measurements and any production remedy remain
pending normal source publication and qualification.
