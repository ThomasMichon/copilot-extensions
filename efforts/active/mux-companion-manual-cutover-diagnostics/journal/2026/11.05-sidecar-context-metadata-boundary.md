# Current-context RPC is not pre-compaction evidence

Parent: [canonical effort](../../README.md), Step 7, and
[live Sidecar S3](../../sidecar-live-timeline.md#s3---bridge-relationships-and-problem-evidence).

## Read-only findings

The public SDK at `99d90edf504f824c77dcdf0faa978f4b35848a87` exposes
experimental `session.metadata.contextInfo`. Its
[usage guide](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/docs/features/usage-and-billing.md#on-demand-breakdown-with-sessionmetadatacontextinfo)
describes an on-demand current-context breakdown, nullable before initialization,
and recommends pinning both SDK and CLI runtime.

The actual client path was traced, not inferred from that example:

- TypeScript's [session getter](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/nodejs/src/session.ts#L738-L745)
  constructs the session-scoped RPC wrapper using its existing connection and
  session ID. The [generated method](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/nodejs/src/generated/rpc.ts#L48843-L48851)
  sends `session.metadata.contextInfo` through that connection.
- Python's [session getter](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/python/copilot/session.py#L2116-L2121)
  constructs `SessionRpc` over the existing client and session ID. Its
  [generated method](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/python/copilot/generated/rpc.py#L74152-L74156)
  overrides the request's session ID and delegates to the same runtime RPC.

These are client dispatch paths, not the serving runtime's measurement
implementation. Their existence does not establish actual optional-field
population, selected-runtime support or a pre-compaction ordering guarantee.
An incomplete source-search result is not proof that no runtime implementation
exists.

The complete generated
[request](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/java/sdk/src/generated/java/com/github/copilot/generated/rpc/SessionMetadataContextInfoParams.java)
and [result](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/java/sdk/src/generated/java/com/github/copilot/generated/rpc/SessionMetadataContextInfoResult.java)
describe model/provider selection and current token/capacity breakdowns.
Zero input limits request session-derived defaults; nonzero limits and an
explicit model affect the computation. The result distinguishes the advertised
selected-tier prompt allowance (`limit`) from the effective input budget
(`promptTokenLimit`) and output/buffer reservation. `mcpToolsTokens` is a subset,
not another total to add.

The complete
[compaction-start type](https://github.com/github/copilot-sdk/blob/99d90edf504f824c77dcdf0faa978f4b35848a87/java/sdk/src/generated/java/com/github/copilot/generated/SessionCompactionStartEvent.java)
separately describes an optional direct `currentTokens`, an attempt identity,
the **target** `tokenLimit`, model and switch-target metadata. Neither these
client methods nor the inspected request/result establishes an atomic
producer-linked pre-event capacity or context-epoch relationship.

## Consequence for the existing source

No evidence adapter or runtime behavior changes follow from this research.
Bridge continues preserving actual start/target fields and unknown active
pre-capacity. Calling the getter after receiving a start event, pairing a cached
adjacent sample, assuming no switch from missing fields, or equating a target
budget with pre-window capacity would not satisfy the existing observation
contract.

S3 therefore remains open. Its next qualifying input must be an admitted
producer/runtime relationship for the same session and pre-event context, with
actual population and correlation controls. Only then can a source adapter
exercise the existing strict unrounded threshold classifier. This investigation
ran no SDK actor, live-session query, compaction, installation or rollout, and
does not authorize any of them.
