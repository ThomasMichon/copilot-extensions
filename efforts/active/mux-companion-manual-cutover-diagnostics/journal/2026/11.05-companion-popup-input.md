# Actual private popup input and clean exit

Parent: [complete effort](../../README.md).
Lane: the parent's direct Companion app-input/dismissal acceptance from #2696.

## Scope and implementation

The original paused popup fixture failed before app startup: it accepted only
the `no sessions` error while an empty foreground tmux server actually reports
success with empty stdout/stderr. A bounded private probe confirmed that
response; the corrected fixture accepts it as readiness, preserving failure
diagnostics and caller-owned cleanup.

The source packet opens unmodified `mux_companion.py` in a privately constructed
source prefix through `display-popup -E`. An attached real tmux client PTY
dispatches the private Ctrl+K binding and subsequent app input; it does not
inject `send-keys` into the underlying CLI pane. Synthetic wire-valid owning
data and an inert original CLI keep the exercise model-free and isolated.

The Manager guide records the existing policy without changing runtime
behavior: explicit Escape clean exit, inherited Ctrl+Q clean quit, keyboard
button activation and Ctrl+C's non-exiting quit hint. Nine cases combine
Escape, Ctrl+Q or keyboard activation of Exit with ready, blocked and failed
source reads. Each observes Ctrl+C leaving the app alive, zero exit closing the
popup without another key, and subsequent input reaching the original CLI.
Pane/PID and native session incarnation remain unchanged; an actual held
reader must retire by its original process birth. No cutover command is called.
The existing client fixture now retains only a bounded recent-output buffer.

## Validation and limits

The initial ready/Escape case passed. The combined existing app/pane and
six-case ready/blocked popup packet passed 15 cases; all three added
source-failure cases passed separately. All three bounded runs confirmed
cleanup. The earlier paused six-case readiness failure remains failure
evidence, not a popup pass. No production app fix was needed.

The final combined popup/app/pane packet passed all 18 cases and confirmed
cleanup. Ruff, whitespace, the 13-runtime install contract, documentation
consistency and the admitted Linux/Windows strict typing cohort passed.
Documentation scanning overlapped temporary test-environment reconstruction
and initially saw disappearing third-party Markdown paths; its single
post-run retry passed. This was not a repository-document defect or a reason
to change scanner scope.

Independent review found that the original observation-only call log could
miss a rejected cutover attempt. The fixture now logs every owner invocation
before dispatch, including blocked, failed and unsupported commands. A
negative control invokes the fake owner's rejected cutover command and
requires it in the complete log while the observation log remains absent.
The corrected combined packet passes 19 cases with exact owned cleanup.
The earlier 18-case result did not establish the absence of rejected attempts.

These are native POSIX tmux/client source controls, not installed operator
acceptance, native Windows/PSMux, headed pixels, frame/input-ready latency,
SDK/model actors or manual cutover. The original observations remain retained;
the source results do not retroactively qualify an older installed build.
Required unit-only CI is unchanged.
