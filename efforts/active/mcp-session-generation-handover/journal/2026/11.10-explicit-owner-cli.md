# 2026-11-10 - Explicit originating-owner CLI handoff

Parent: [MCP Session Generation Handover](../../README.md).

This slice closes part of the existing originating-owner acquisition item toward
[authoritative runtime replacement](../../../../../visions/installer/README.md#authoritative-runtime-replacement).
The selected design is an explicit controlled-launcher handoff, not ancestor
guessing or discovery through another plugin's session files.

`bridge` and `forward` now accept a paired PID/native-birth input and reuse the
existing native pin before incoming or custody startup. Incomplete, invalid or
unverifiable ownership refuses without ordinary fallback or replay. Serve startup
opt-outs remain effective. Callers without the pair retain their existing path;
no controlled production launcher supplies it automatically yet.

The focused Windows source packet passes 51 tests in 4.55 seconds, including
actual CLI parsing and native owner-death settlement with stdin still held open
for both commands. The bounded runner reports success in 23.12 seconds including
preparation and cleanup. The backend link is substituted in that focused
real-process control; it is not caller-Job or physical-replacement evidence.
F/E9 lint, install contracts and the four source AST guards pass. Canonical
producer regeneration retains footprint revision 36.

The hosted lifetime fixture now launches the real `forward` CLI through its
existing attributed stdio/daemon owner, rather than calling the internal function
through its actor script. That changed packet still requires fresh hosted
qualification. Earlier hosted internal-entrypoint evidence remains distinct.

Review, required CI, promotion, controlled-launcher capture/integration and
authorized installed-consumer acceptance remain open. The effort stays Active;
this is not full adopted-wrapper reattachment or a full-update performance pass.
