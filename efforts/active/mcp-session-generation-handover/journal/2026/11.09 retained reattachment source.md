## Ordered attachment foundation

The first selective port adds an inert private custody wire implementation,
without changing production attachment, launch, installer or retirement paths.
Sequence allocation and publication share the writer lock. Cancellation before
publication consumes no sequence; cancellation after publication retains its
receipt and bounded admission credit until settlement. Connection loss reports
an unknown accepted outcome rather than replaying application work.

The focused source packet passes 12 cases, with zero skips and verified
contained-process cleanup. It covers late receipts, cancellation while waiting
for publication and during drain, invalid receipt identities, partial UTF-8
framing, duplicate sequence refusal, disconnect uncertainty, buffered work after
closure and concurrent ordered publication.

This is protocol-foundation evidence only. No running peer advertises custody
support from these changes, and no existing client is reattached. Checkpoint
binding must reuse the current complete caller-context owner rather than the
prototype's partial environment identity. Fresh physical-generation execution,
bounded application pressure with independent control traffic, backend import,
native transport/process qualification and installed acceptance remain open.

## Current-backend connector admission

The internal connector now qualifies authenticated readiness and backend
admission on one connection. It checks the current installation selector,
custody/configuration-context contracts, runtime root and complete caller
context; the returned epoch, generation and root must match, and selection is
checked again before custody receives streams. The backend still performs
independent physical-generation checks before preparation and activation.
Caller configuration roots are not replaced with the installation root.

The connector uses the adoption owner's known installation root. It does not
consult an older keeper's generation-specific startup path, and missing legacy
launch metadata does not veto an admitted incoming backend. It does not launch,
replace or retire a daemon. The handshake has an aggregate deadline; failure or
cancellation closes only the uncommitted connection, without starting an
upstream or replaying application work.

The combined connector, custody, checkpoint, IPC, incoming-admission and
resident-configuration packet passes 124 tests with no skips and verified

## Bounded client intake and independent controls

The internal reader now queues application and control input with independent
count and byte budgets, without awaiting application dispatch or an admission
receipt. Application admission remains ordered. A cancellation whose target
is still queued waits for that target's admission, while bounded independent
control workers can still deliver server responses.

Custody's capacity/fence wait releases the input lock. A handover can therefore
settle server requests and commit before releasing queued application work.
Overflow and malformed input are terminal and explicit; notification loss,
intake restart and automatic replay are not recovery mechanisms. EOF joins
publication, and intake cancellation preserves already-published work and the
retained upstream for its actual lifetime owner.

The expanded combined packet passes 135 tests with no skips and verified
cleanup. It includes a full notification window, application saturation,
independent byte/control capacity, delayed admission receipts, queued-target
cancellation ordering, real custody peers across a handover fence and
malformed/overflow/EOF controls. Focused lint, module-size, install-contract
and documentation consistency checks remain required before publication.

This closes neither shared-host/conduit integration nor native separate-process
and installed acceptance. Production routes remain unchanged, and the effort's
Plan and Validation Plan remain open.

## Shared custody provider and conduit source integration

The serve provider now expands its backend route and advertises the custody
contract only from an actually admitted physical generation. A separate shared
custody host composes the connector, retained-session owner and bounded client
intake. Its lease and publication namespace are separate from the central
backend, and it publishes no central lifecycle control route. Actual caller
context remains mandatory; no cwd normalization manufactures sharing.

One host watcher schedules independent session migrations. A client's pending
mutation cannot block another client's handover. Repeated failure against the
same selection/endpoint backs off. A successful connection alone does not
advance adopted-generation bookkeeping: failed checkpoint preparation must
remain retryable while the outgoing epoch is still owned.

The synchronous conduit verifies custody identity and contracts with a total
handshake deadline, without imposing its keeper's old generation on backend
admission. It consumes only handshake acknowledgments and then reuses the
existing stdio pump. Attach acknowledgment precedes early notifications.
Client EOF joins an active handover before teardown, and a lost quiescence
receipt cannot skip exact retained-transport cleanup or justify replay.

## Explicit launcher boundary

The internal launcher requires a qualified current backend and known
installation before using custody. It preserves live incompatible keepers,
performs at most one attributed startup for an unreachable keeper, bounds
subsequent connection attempts, and rechecks selection after attachment.
Keeper failure cannot become authority to reclaim the backend handle.
Custody/backend publication parents cannot alias the same directory.

The new explicit internal provider entrypoint uses a separate
`agent-mcp-custody` daemon identity. Startup requires an actually compatible
stable cwd and never rewrites caller context. Production startup refuses an
inherited caller-Job fallback instead of claiming durable independence;
explicit contained-test lifetime remains owned by the shared primitive.

The expanded combined packet passes 239 tests with two existing platform
