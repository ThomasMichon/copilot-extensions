# POSIX configuration-owner helper retention

## Reconciled source

The existing #10799 defect and #10810 proposal cover an independent producer
gap, not a change to the #10951 resident caller-context protocol. A completed
POSIX MCP runtime can lack both the executing slot's retained resolver and
the older root-level resolver. A valid delivered projection then fails with
`delivered configuration has no matching qualified owner` before backend access.

The original proposal's opt-in shared shell adapter is already present in
current Dev. PowerShell MCP completion already requests retained helpers;
the MCP POSIX completion caller still omits that option. The reconciled
change therefore enables the existing option rather than reverting or
republishing older shared-helper copies.

The implementation and constructor-backed controls retain the original
proposal's authorship. The consumer packet now builds the nested `.venv`
layout used by the POSIX MCP installer. Explicit and named bridge loading
consume the qualified preference from a real private Git worktree. Separate
producer controls exercise fresh construction, exact reuse, missing or
changed completed helpers and invalid options. Completed bytes remain
unchanged on refusal; no reader or owner-matching guard is weakened.

## Qualification

- Baseline POSIX behavior: both constructor-backed consumer cases fail because
  the retained resolver is absent; the manually assembled reference still passes.
- Corrected Linux configuration packet: 37 passed, including both constructor
  consumers and the five completed-helper controls. The bounded runner reports
  verified cleanup.
- Windows configuration packet: 30 passed, seven POSIX-only cases skipped,
  with verified cleanup. Existing PowerShell production behavior is unchanged.
- Source install contract: all 13 adopters pass after the completed test jobs.
  An earlier concurrent scan encountered a disappearing temporary build input;
  that failure is not counted as a passing first attempt.

The consumer assembles isolated package fixtures and uses a synthetic qualified
owner report. It does not qualify authentic installed wheels, a production
configuration owner, credentials, an external backend or preserved sessions.
Source review, current-head CI, promotion and authorized installed-consumer
acceptance remain required. No runtime installation or deployment is claimed.

This closes a gap toward
[authoritative runtime replacement](../../../../../visions/installer/README.md#authoritative-runtime-replacement)
without changing the original incoming-execution and original-session
reattachment completion gate.

## Implementation-review correction

The current review identified that the fixture's three Git commands inherited
repository selectors; `-C` does not override `GIT_DIR`, `GIT_WORK_TREE` or
`GIT_INDEX_FILE`. Each command now receives an environment copy with every
`GIT_*` variable removed. A constructor-backed consumer runs with deliberately
poisoned selectors pointing at a separate private fixture path and verifies that
the unselected location remains absent. The process environment is restored
after fixture construction.

The corrected Linux configuration packet passes 38 cases; Windows passes
30 with eight POSIX-only skips. Strict whole-file checking passes both Linux
and win32 targets. These controls fix the review's fixture-isolation defect;
they do not explain or accept the independent original ten-second Windows
registered-policy timeout tracked in #11175. That failed occurrence remains
failed, and current-head independent review and required CI remain mandatory.
