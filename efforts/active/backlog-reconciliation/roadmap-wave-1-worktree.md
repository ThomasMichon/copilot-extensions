## Current-source distinctions

These are source/test-text findings at `d77783f0a10b067a249dd39cee09f48f9dc6024b`,
not live reproductions. All selected source/test blobs match the earlier research
pin. The four classifications apply to the stated predicates, not whole issues.

### Scoped credential refusal (#5791)

**Classification: `reported-fixed`.** [Account selection][a-selection] freezes explicit policy; [credential acquisition][a-credential] raises `AccountCredentialError` when that selected identity cannot mint a token. The [environment builder][a-env] propagates it and the [actual dispatcher][a-dispatch] returns before `subprocess.run`. Its remaining ambient warning is compatible derived/unconfigured behavior, not evidence that explicit failure still falls through.

[Existing dispatcher tests][a-auth-tests] cover repo/map and short/qualified targets with ambient tokens present, successful scoped injection and derived-owner behavior. [Lookup-policy tests][a-auth-policy] retain the selected policy when configuration changes during lookup. No selector was run here.

**Planning consequence:** do not duplicate this patch. Retain its source claimant and recover actual review/release/selected-installation evidence; inherited stale/401, provider, binding and non-GitHub acceptance remains at its original scope. One guarded function is not whole-issue closure.

### Authored destination collision (#2861)

**Classification: `source-supported-defect`.** In the [actual hoister][a-hoist], `existing_output_files()` limits stale deletion to banner-bearing outputs, but `sync()` independently writes differing expected paths with `path.write_bytes(content)`. A hand-authored file at the expected plugin filename is therefore unguarded; a later disable can remove the generated replacement. The [CLI consumer][a-hoist-cli] calls this same `sync`.

Credit the [unmarked-sibling and disabled-generated regressions][a-hoist-tests]. Their reviewer-versus-widget names do not establish same-name protection; two plugins claiming one name is also a different collision.

**Conditional change / exit:** guard protected destinations before any write, preserve authored bytes after disable, report conflicts honestly and retain legitimate generated refresh/cleanup. Add the same-name authored case in the existing test owner. A mixed conventional directory is not wholly disposable, but a designated disposable generated namespace need not gain a new per-file cryptographic proof.

### Endpoint ownership uncertainty (#5904)

**Classification: `source-supported-defect`.** [Canonical cleanup][a-endpoint] holds the existing mutation transaction but unlinks unless a tolerant read returns a known different PID. [The reader][a-endpoint-read] maps absence, unreadable/invalid UTF-8, malformed and unsupported-schema records to `None`; missing-PID records also bypass that guard. The [Dispatch][a-endpoint-dispatch], [Index][a-endpoint-index] and [Vault][a-endpoint-vault] copies retain it.

Actual consumers include [Dispatch shutdown][a-dispatch-cleanup], [Index failure cleanup][a-index-cleanup] and [Vault cleanup][a-vault-cleanup]. Credit the existing lock, atomic publication, successor checks, [serialization test][a-endpoint-concurrency] and [copy-parity test][a-endpoint-parity]; do not rebuild the delivered race repair.

**Conditional change / exit:** retain present unvalidated ownership as UNKNOWN under that transaction across canonical plus all three copies/callers, while preserving true absent no-op and valid own/successor behavior. The [old non-UTF8 test][a-endpoint-tests] explicitly expects deletion and needs an intentional requirement-preserving change. Use finite real-file/caller controls, not a live-service race, another external lock or a new PID scheme; #5940 admission remains separate.

### Ordinary claim acceptance (#5842)

**Classification: `source-supported-defect`.** The [ordinary local/remote accept path][a-accept] invokes source acceptance before consumer completion. [Source acceptance][a-release] removes claims and records terminal `accepted`; [consumer completion][a-consumer] can still reject missing/conflicting records or leases, or fail later saves. [Terminal filtering][a-terminal] then excludes that bundle from the [actual finalize handoff gate][a-finalize]. Other ordinary finalization gates remain independent.

Credit [receiving-project/execution-space preflight][a-receiving], existing actor/kind/fence/owner proofs and separately delegated producer handling. The [later-child-failure/happy-path tests][a-accept-tests] do not prove source restoration or a nonterminal failure outcome; the [source-only idempotence test][a-source-test] intentionally asserts terminal acceptance with an empty source ledger.

**Conditional change / exit:** review a recoverable nonterminal protocol using existing registry/locks/fences. Keep source authority and its finalize block until consumer claims and resource-side owners/leases durably commit; merely reversing two calls cannot solve mixed-ledger/remote failure. Cover missing consumer and every later save/lease/crash transition, retry and exact remote reservation. Preserve all #1602 actual-consumer readiness, all-entry-path, refusal/later-binding alternatives separately; producer restrictions do not supply ordinary atomicity.
