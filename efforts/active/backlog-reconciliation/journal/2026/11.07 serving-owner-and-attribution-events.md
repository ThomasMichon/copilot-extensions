The original's possible #10847 relationship remains unverified: current

The witness retained previously tracked incumbent process identities and

Preserve foreign-listener/native-owner safeguards and unknown-outcome

This distinction between successful construction/direct diagnostics and

## Complete attribution-event contract

The qualified #11348 original reports a merged `dev` PR description edit
triggering required source attribution and failing with a retry-current-check
diagnostic because the live PR is no longer open. The example #11329 is
independently verified MERGED before this issue was filed; its description,
checks, failed run and implementation were not read or retried.

Post-merge edits must not be presented as repairable open-PR attribution
failures. Preserve fail-closed current-metadata validation for open PRs,
including an open event whose PR closes during validation. Required contexts
are commit-scoped: skipping or succeeding a closed-PR job must not clear an
open same-head peer's required check. Keep inactive-event contexts separate,
departed-head reevaluation and shared-head refusal.

Retain all three original tests: closed/merged description edits, an open
same-head peer, and an open event whose PR closes during validation.
This is a repository workflow defect, not invalidation of pre-merge passing
checks or permission for a bypass. Its finite next source question is the
event/context separation preserving those three invariants.
