## Proposed source completion: passive current-roster freshness

#11298 requests implementation and regression coverage for the passive
`worktrees-current` provider and its consumers. It does not require keeping
every project warm, starting a monitor from a passive read, or demonstrating
an installed/native performance campaign before its finite source request can
be complete.

The complete qualified original and both discussions were compared with
merged #11433 and selected current causal functions and regression controls
at public source
[`e7e9c136`](https://github.com/ThomasMichon/copilot-extensions/tree/e7e9c136f969e69ceed66ac795d42c69757a9407).
Twenty-seven named current file publications were independently qualified;
this is not a claim that every line of those files or the repository was read.

| Requested guarantee | Actual source and regression correspondence |
|---|---|
| Per-project publication age, not shared heartbeat or sweep freshness | `worktrees_runtime.py` binds the monotonic collection start to each publication and checks its age on the read path. `worktrees_producer.py` supplies that collection clock. Other-project activity cannot renew it; unpublished, failed, stalled and re-elected generations fail closed. Runtime/producer controls cover controlled clocks, a real temporary store, slow collection and another project remaining alive. |
| Passive reads never create demand or wake an unavailable provider | The public passive client rejects incompatible follow/glance/refresh modes, records no list demand and uses one resident attempt with recovery disabled. Missing or older peers produce advisory/error behavior without a demanding fallback. Actual front-door/transport controls cover absent, live and old peers without ensure, sleep or demand. |
| Consumers refuse unproved, expired or malformed snapshots | Delegate validates finite, nonnegative, non-Boolean age fields, current reachability/availability, local elapsed probe time and complete unique source cardinality. Its fleet snapshot is passive; it revalidates before each finalization call. Fleet labels preserve stale/saved availability rather than inventing a missing worktree. Controls include old/missing fields, Boolean/NaN/negative inputs, a slow later host and expiry before the second action. |
| Record, finalization and native-session changes republish without project demand | Tracking save/tombstone and both post-unlink retirement paths notify the existing receiver. Deferred notifications run after holds release. Hook IPC and managed-mux state callbacks feed the resident change queue; the monitor unions changed-project publication with, but does not turn it into, external demand. Vanished direct sessions notify before pruning. |
| Bounded missed-event recovery and idle behavior | The runtime keeps a bounded 256-event queue, marks overflow/unresolved work for all published projects and uses its three-sweep retry without creating project demand. In-process monitor/handler and mux IPC controls cover retry, idle expiry, non-heartbeat callbacks and receiver failure without replaying effects. |
