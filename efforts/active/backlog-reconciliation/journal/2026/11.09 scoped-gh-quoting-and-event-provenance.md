## Selected outcome

The original #810 explicitly accepts either a native literal-argument route
or point-of-use comma-quoting guidance when the PowerShell script entry remains.
The selected correction implements the latter, smaller documentation alternative.
It does not replace the Windows shim, repair already-split arguments or claim
that unquoted comma lists now work.

The repository-management skill now warns at the scoped-account entry about
quoting comma-joined `--json` and `--label` values. It links to the CLI reference,

and a correctly quoted spaced `--search` combined with `--json`.

The examples use a synthetic repository. The original report's account and
repository strings are not copied. The supported account-scoped wrapper remains
the route; a confusing shell error is not a reason to fall back to another
ambient GitHub identity.

## Why documentation is a complete allowed alternative

PowerShell parses an unquoted comma expression before invoking a `.ps1` entry.
Forwarding the resulting argument array cannot reconstruct lexical grouping.
The original therefore asks, at minimum, for explicit guidance if script
semantics are intentional; a heuristic warning is optional, not a required
parser redesign.

This correction addresses that exact minimum. It does not import a new native
qualification matrix from broader launch hardening, claim a native shim exists,
or certify all Windows argument cases. Any completed disposition must link the
actual reviewed delivery and clearly name the documentation alternative rather
than claim the native parsing behavior changed.
