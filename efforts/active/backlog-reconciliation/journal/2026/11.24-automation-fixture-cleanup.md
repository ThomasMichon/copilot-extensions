### JSONL recursion fixture: #5712

The reported `test_excessively_nested_json_does_not_hide_later_records`
failure came from assuming that
JSON nested beyond `sys.getrecursionlimit()` necessarily raises in the active
decoder. CPython's C decoder accepted that fixture, returning the nested record
instead of the expected following record.

[#5718](https://github.com/ThomasMichon/copilot-extensions/pull/5718), merged as
`1f2ff3ab9ebbc3810a402e128ec565e5d1888ce9`, replaces that
interpreter-dependent assumption with a deterministic module-local decoder
substitute that raises `RecursionError` for the nested line and uses the real
decoder for valid neighbors. The regression explicitly verifies that rejection
occurred and that the following valid record survives. Production
`_decode` already catches both `ValueError` and `RecursionError`; the
specific correction is to the test fixture, not removal of that error boundary.

The qualified complete repair description reports 112 passing family cases and
the exact regression passing under Python 3.12.10. Its exact source head
`d8d6f0f1a8befc2585ae07a2436eb72e5743091c` has Copilot approval and successful
required PR-gate and workflow-lockdown checks. The current published source
retains both the corrected regression and production rejection boundary.
