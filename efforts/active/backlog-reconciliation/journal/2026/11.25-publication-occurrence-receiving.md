## A different route, not a newly inferred repair

The earlier study correctly left eighteen cleanup-only publication reports
open: matching job names and a later successful publisher do not establish
their individual causes or technical fulfillment. That judgment is retained.

The newly proposed route is instead requirement-preserving **tracking
aggregation**. All eighteen originals are verified repository-owned automated
status reports with no edits, human discussion, assignee or lock. Actual
workflow/job metadata identifies the same qualified-source publisher and
named publication/readback step. Complete originals and their literal
signatures/reported inputs were already researched; none supplies a distinct
human request.

Existing OPEN #7378 is a stronger receiving candidate than a new filing:
it already retains publication diagnostics and later admission follow-through.
Its complete original and five human comments were read, and current complete
authorship/edit/discussion metadata remains unchanged. It is not a
campaign-created duplicate. No incumbent text, source duty, assignment or
resource is replaced.

The [direct eighteen-row specification](../../publication-occurrence-receiving.md#proposed-append-only-receiving-contract)
retains each original, signature, exact reported commit, failed execution and
independently OPEN technical condition. It preserves current publication
integrity gates, every incumbent #7378 request, unknown causes and the rule
against applying one row's fix or a later green run across the matrix.
The future receiver owns those technical states; this campaign owns only
accepted intake and separately verified tracking dispositions.

## Authority and acceptance boundary

This uses the existing requirement-preserving aggregation charter and its
approved first-party automation-report/status class. It does not change the
policy for unfinished human or third-party requests. The cohort has none,
and the receiver was not filed by this campaign as a competing duplicate.

The source-qualified finite-consolidation guidance distinguishes completed,
redundant-tracking, obsolete and keep-open outcomes. The proposal follows
its complete receiving shape, rather than relabeling these unknown failures
as fixed or treating the old full-corpus retirement as applicable.

Required plan review, actual disclosed receiving-body addition, complete
readback, current receiving acceptance and validated recurrence routing
precede any leaf retirement.
Current eligibility, source revisions and actual claimant/hold conditions
then precede eighteen separate acknowledgments, `NOT_PLANNED` tracking
judgments and independent state/reason readbacks. None is automatic from a
plan, receipt, role description or numerical target.

The original reports remain historical evidence. No producer code, product
test, signature algorithm, CI gate, controller, runtime, claim or resource
is changed. The only possible source-label mutation is the explicitly staged
selector handoff in the receiving gates, with unrelated labels preserved.
This does not appoint an investigator or authorize rerunning old releases.
The existing observer is retained; no worker, service or extra scheduler
is introduced.

### Routing is an independent pre-retirement gate

Current source inspection shows the watchdog searches only OPEN
`ci-failure-signature` issues for `"Signature: <key>"` and selects the first
match. No match files a new issue and records its number for fix-attempt
dispatch. A match instead applies the configured issue-level cooldown or
comments without recording a newly filed number. The existing lookup,
creation, comment and cooldown controls were read, not executed.
The inspected producer and control modules match current Dev and Main.

Consequently, a bare-hash matrix or a link to a planned receiver cannot
authorize source closure. The updated specification retains exact lookup
markers in the receiver body, preserves its selector, and requires the same
read-only lookup to select that OPEN receiver before and after each source
transition. A staged source-selector withdrawal is allowed only after the
receiver is already an indexed match and while the source remains OPEN.
Search delay, lookup failure or another selected target keeps the source open.
Current receiver-level cooldown is retained, not replaced with a per-key
delivery guarantee or a new multi-case repair-agent contract.

This is a tracker-data route using the existing reader, not implementation
authority. If existing data and lookup behavior cannot satisfy the gate,
the affected originals remain OPEN under their existing owners. No reporter,
raw-log verifier, product test or fix-attempt workflow is run by this campaign.
