approved first-party automation-report/status class. It does not change the

The source-qualified finite-consolidation guidance distinguishes completed,

The original reports remain historical evidence. No producer code, product

selector handoff in the receiving gates, with unrelated labels preserved.
This does not appoint an investigator or authorize rerunning old releases.
The existing observer is retained; no worker, service or extra scheduler
is introduced.

### Routing is an independent pre-retirement gate

Current source inspection shows the watchdog searches only OPEN
`ci-failure-signature` issues for `"Signature: <key>"` and selects the first
match. No match files a new issue and records its number for fix-attempt
dispatch. A match instead applies the configured issue-level cooldown or
comments without recording a newly filed number. The existing lookup,
creation, comment and cooldown controls were read, not executed.
The inspected producer and control modules match current Dev and Main.

Consequently, a bare-hash matrix or a link to a planned receiver cannot
authorize source closure. The updated specification retains exact lookup
markers in the receiver body, preserves its selector, and requires the same
read-only lookup to select that OPEN receiver before and after each source
transition. A staged source-selector withdrawal is allowed only after the
receiver is already an indexed match and while the source remains OPEN.
Search delay, lookup failure or another selected target keeps the source open.
Current receiver-level cooldown is retained, not replaced with a per-key
delivery guarantee or a new multi-case repair-agent contract.

This is a tracker-data route using the existing reader, not implementation
authority. If existing data and lookup behavior cannot satisfy the gate,
the affected originals remain OPEN under their existing owners. No reporter,
raw-log verifier, product test or fix-attempt workflow is run by this campaign.
