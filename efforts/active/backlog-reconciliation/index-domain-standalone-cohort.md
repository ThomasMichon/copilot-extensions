## #4194 - Credit real authorization without substituting optional narrowing

Retain query-time compatibility/isolation so a search cannot mix incompatible
trust domains simply because the caller omitted optional source/repository
filters. Trust-domain metadata, ordinary source/repository filters, selected
store/FTS guards and the newer pre-retrieval authorized-family/Gateway path
are useful, real foundations. Source-aware grants are actual enforcement
and must not be described as absent.

Those foundations do not automatically supply the original compatibility
decision for every domain admitted to an ordinary query. The reported ordinary
search chain forwards optional filters; the reported architecture separately
identifies query-time domain enforcement as unimplemented. Cross-process
CONTENT-domain provider machinery is not itself security trust-domain policy.

Preserve existing source authorization and explicit unavailable/refusal
behavior. Missing domain selection or unreadable policy must not become
permission to search everything. This documentary outcome grants no new policy,
live corpus query, endpoint/security probe or credential access.

## #5768 - Credit completed planning and staged distribution; retain lifecycle

The original proposal-first independently packaged service goal has accepted
Phase 2 distribution/lifecycle and Phase 3 portable adapter follow-through.
The initial vision/architecture/recovery work completed and reached an actual
healthy native deployment with worker and warm-engine continuity. Later
independent API/controller distribution, pinned descriptor and wheel/RECORD
verification, and immutable candidate staging were merged.

The temporary implementation/deployment pause was explicitly lifted before
later source work. Do not call this still paused, planning-only, wholly
unimplemented or complete merely because packages/staging exist. Resumption
did not grant unrestricted canary migration, restart or corpus/queue mutation.

Retain the complete accepted residual: health/passive activation, immutable
version-slot lifecycle and validated rollback, durable configuration/data and
queue/schema-safe transitions, supported Darwin staging/supervision, release
reconciliation and independently assigned component/container/fleet interfaces
and deployment gates. Candidate/RECORD validation is not activation or live
standalone migration proof.

Preserve the lightweight client and non-container native host paths, existing
worker/engine continuity and explicit operator-owned external controller.
Credit base-only primary CLI with explicit owning-host runtime, opt-in legacy
stdio MCP and bounded statistics without claiming those dependency changes
close lifecycle acceptance.

The standalone service, native canary and warm engine retain their existing
owner. Gateway routing/auth, fleet placement/client lifecycle, image/client/
source-credential integration and shared artifact helpers retain their separate
named owners. Do not create another controller or silently inherit obsolete
plugin-managed default responsibilities.

The reported hook-transience mismatch is qualified to the admitted native/
legacy host lane: inactive/client repositories do not take that path. It is
not proof that a supported Dispatch companion behaves the same way, nor a
reason to invalidate the reviewed heavy-companion exception.
