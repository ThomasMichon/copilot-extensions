## #6752 - A truthful, finite send diagnostic

The original reports a deliberately stopped/non-live worktree handle producing
an unknown-target failure followed by "Starting session for agent"; it expressly
says NO session actually started. Do not turn alarming wording into a proven
spawn, termination request or authorization to reproduce a real launch.

Preserve the accepted alternatives: refuse an unresolved non-live handle
cleanly with nonzero exit and ONE clear failure, OR start only through explicit
intent/a legitimate registered-agent identity. A new `--start` flag is not
mandatory if the supported registered-agent alternative suffices; neither is
a universal prohibition on agent addressing. Generic zero-match start fallback
and prevalidation progress wording are the reported seams, not an unrelated
listener bug. No universal native/installed gate is added.

## #8776 - Parentage is descriptive, not effect authority

Retain an optional caller-asserted creator/parent relation for live registrations,
similar to ACP's existing `caller_session_id`, returned by both list and detail.
The extension/launcher may supply it from known creation metadata or environment;
a worktree-level creator link is an accepted alternative.

The reported eighteen registrations had worktree IDs but no creator relation;
null `role`/`driven_by` observations are context, not proof those fields must
become an authority mechanism. Preserve the #4119 distinction: caller assertion
is NOT authenticated origin, ownership transfer, ancestry-derived permission
or evidence of same-native continuation. Existing ACP support alone does not
implement live-session parity. Consumers should not have to infer parentage
from timing/names/dispatch guesses across machines and restarts.
