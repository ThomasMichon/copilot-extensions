mutation. The reported supported non-contextual source-checkout route can infer
project integration from caller-directory naming and existing machine project
configuration. Preserving a different custom hooksPath is useful but does not
establish explicit integration permission.

under the repository's normal authority/contribution contract. Preserve project
registration, hook safety, supported source installation and intentional
separately authorized higher-level source-sync/integration orchestration.
This is not a blanket prohibition on intentional integration.

Credit the existing contextual and marketplace self-staging routes that move
to HOME; do not falsely describe them as inheriting arbitrary caller CWD.
Those routes do not by themselves prove the distinct supported source route
cannot reach ambient inference.

Retain synthetic adopted/unrelated/unknown CWDs, custom/managed/unset hooksPath
and explicit integration flows on Windows and POSIX. The adoption-time hygiene
capability and push-time hook/bypass concerns retain their separate owners;
neither replaces this installer-phase boundary or should be removed. Reported
source-effect auditing is reachability evidence, not observed live mutation

## #9574 - Unknown Git provenance is not a swallowed working-tree error

Only collect commit, branch and dirty state for working-tree payloads.
A complete payload beneath another repository's Git metadata, in a bare
repository or outside a repository must keep unknown Git provenance rather
than inherit a containing repository's unrelated revision. Verified source
identity remains authoritative.

Preserve genuine working-tree lookup/status failures as explicit provisioning
refusals; do not flatten them into unknown/success. Retain the native Git
regressions for metadata/bare/nonrepo payloads, ordinary/linked worktrees,
error preservation and an isolated real first install.

The original explicitly takes the repair and requests light review only.
Its reported draft and regression additions are real declared progress, not
permission for this campaign to assume implementation custody. The isolated
install reportedly reaches dependency construction but fails a dependency-fetch
TLS handshake; no passing install, source merge or rollout is claimed.
That finite validation blocker is neither abandonment nor authorization for
network/runtime remediation.
