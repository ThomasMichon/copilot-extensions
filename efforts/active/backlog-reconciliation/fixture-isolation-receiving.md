## Common actionable problem and non-goals

Ambient sibling installations or guest identity can make a fixture exercise
the wrong path. Fast early refusal, an unavailable executable or a different
partition can then be mistaken for faithful behavior or improved performance.
The common plan is to make each original fixture's execution world explicit,
preserve its real consumer boundaries and assertions, and compare only valid,
equivalent inventories.

This plan does not merge the two defects into one implementation, appoint a
new writer, create a test executor or CI lane, expand required PR testing,
authorize a workflow rerun, register a host, change production admission,
install anything, release a claim or authorize runtime operations.
