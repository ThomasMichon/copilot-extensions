# Acquired comment observation and original receipt correlation

Back to the [canonical effort](README.md),
[comment-identity contract](comment-identity.md) and
[original intent binding](comment-intent-binding.md).
This is an **agent-recommended, review-first C3 source refinement**, not
implemented support, protected writer enrollment or installed qualification.

## Separate the remaining evidence

The original prepared-receipt projection binds admitted identity and exact
body to the existing owner's native action outcome. It deliberately performs
no current acquisition. The existing workspace already acquires complete,
scoped ADO discussion generations and retains them in its generation cache.
Neither mechanism alone joins an original prepared action to that acquired
native object without relying on an untrusted body marker.

Deliver a finite read-only projection through those existing owners. It
selects one original operation/action and one acquired generation, returning
bounded body-free correlation evidence. It does not create another mapping
database, body archive, watcher, native query, credential source or effect.
The protected-writer prerequisite remains independently open: raw
`AzLoginSource` still lacks authoritative granted-access metadata, and the
Fleet verifier remains an explicit external custodian dependency.

## Receipt identity selects the object

Read the exact scoped operation/action through ReplayStore. Keep its original
prepared identity, body hash, state and receipt authoritative. Require the
executing owner to have adopted the existing prepared-intent contract;
legacy bodies do not gain structured preparation by parsing their tags.

Use the retained native thread/comment IDs to select an acquired object.
Never search for a GUID or equal body to discover a replacement object.
The generation must have the same provider, endpoint, project, repository,
native principal and PR scope as that operation; the existing cache and
authenticated workspace route supply this scope, not caller policy labels
or comment text. The namespace remains the same ReplayStore owner's.

A positive current-content correlation requires an originally confirmed
prepared comment/reply/edit, complete usable discussion evidence, the exact
retained native target, the same native author, a live text comment and exact
prepared content. Preserve selected reply/edit target constraints. Missing,
deleted, partial, duplicated native IDs, changed author/type/target/content,
or inconsistent identity remain explicit unavailable or conflict results.
Copied, quoted or stripped tags cannot redirect this join. Do not merge two
native objects or rewrite another owner's identity from matching metadata.

Unattempted and unknown actions retain their original states and any partial
IDs. Even complete current evidence with matching content/markers cannot
confirm an unknown effect, authorize another send or replace the executor's
qualified original-response/unknown-reconciliation contract. Bodyless votes
and legacy actions without admitted preparation report unavailable.

## Current content is not original-version proof

Return the selected generation ID and its original observation interval,
native target/actor IDs, bounded current-object digest and the result of the
join. Do not return or retain another comment body. Read the immutable cached
generation rather than fetching the forge to make this projection appear
fresh. Caller-selected generation IDs cannot bypass actual cache/scope checks.
Do not label a cached observation as current wall-clock evidence: preserve its
original time, completeness and availability for the consumer's freshness rule.

The original receipt may remain confirmed after a later edit or deletion.
Report current divergence without downgrading that original confirmation.
Conversely, an exact current-content match does not prove that the original
version survived intervening edits. A digest of today's normalized native
object is only an identity for today's observation, not an original native
write/version receipt. Existing B3/B4 capture, original-version and
interest-specific echo owners remain authoritative and unchanged.

This read cannot advance handled positions, refresh pending age, ACK events,
emit Dispatch, change PR/source ownership, admit execution or update receipts.
It performs no migration, retention compaction or state replacement. Existing
pending/unknown keeper obligations remain unchanged.
