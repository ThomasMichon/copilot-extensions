# Trusted comment-producer enrollment

Back to the [canonical effort](README.md) and
[existing-owner intent binding](comment-intent-binding.md).
This is an **agent-recommended, review-first source contract** under #11128.
It does not enroll a host, grant forge effects or qualify installed adoption.

## Actual boundary

The optional receiver and CLI/Gateway consumers can retain prepared selections,
but their tested `selection_preparer`, `comment_preparer` and protected
`write_context` are trusted embedding inputs. They are not normal-host wiring.
`WorkspaceTools()` is unbound by default. The standalone
`WorkspaceConfig.operations()` constructs only native readers; its credential
command authorizes observation, not review submission. The
[native read-only host contract](native-workspace-host-slice.md) remains intact.

Likewise, `AdoReviewContext` consumes an existing credential-pinned request
transport; constructing that class does not supply such a transport or authorize
it. Do not call a fixture factory a production owner, relabel native read
acquisition as protected write acquisition, or enable allocation/submission
merely because storage and capability declarations support their wire shapes.

## Finite source outcome

Compose one explicitly selected producer through the existing authenticated
workspace owner. Preserve watch-only and native read-only configurations and
their storage unchanged. Enrollment is default off and scoped to the existing
caller/target route, provider endpoint, repository and actual native principal.
The host must have the real preparation and protected submission dependencies
before advertising the corresponding optional operations.

Use the existing host, workspace, source, credential, replay and lifecycle
owners. No second listener, effect ledger, credential issuer, callback registry
or arbitrary import/command execution facility is introduced.

### Source and policy belong to the producer

Bind the selected producer to its actual managed source through the Worktrees
owner and resolve its effective AI profile through the attribution owner.
The service's own checkout, the PR author's worktree, a caller-supplied codename
or a hash-valid reviewed-code attachment cannot substitute for producer origin.
Delegated authorship keeps its existing source-custody rules.

Resolve destination visibility, disclosure obligations and anonymous/source
policy from the existing trusted owner, not remote `required`, `visibility`,
profile, configuration-path or source-identity labels. Missing or ambiguous
facts refuse the optional preparation path; do not silently claim stamping.
Keep required disclosure when predecessor context is absent or races. Do not
add a forge query solely to suppress a short repeated signature.

Use the actual shared preparer rather than copying its profile/marker logic.
Resolve IO-bearing source/profile inputs before the replay lock; only bounded
pure composition and original-selection allocation run in that transaction.
If independently installed components need a new preparation-context boundary,
review and expand its owning provider contract before using it. Do not load an
arbitrary Python factory from host JSON or run an external preparer under the
replay lock to make an injected callback appear deployable.

### Protected submission remains a separate prerequisite

The actual write owner must select the existing authorized credential and
transport, retain their private binding through current-principal/candidate
reads and native writes, and enforce current review policy at dispatch.
An observe credential, Gateway caller identity, source marker, prepared preview
or configured principal is not that write authority. Preserve the existing
exact-selection checks, selected native-target/author checks, original outcome
receipts, unknown-effect fences and finite request/drain custody.

Realize any missing protected native transport at its existing provider/
credential owner before enabling the host consumer; do not create an alternate
forge client or fall back to ambient authentication. Static configuration can
select supported trusted references, not manufacture a private binding or turn
an observation route into a writer. Actual live credential/backend enrollment
and native effects require their own applicable authorization.

#### Provider-first protected writer expansion

The current Fleet `ForgeScope` and Worktrees `ObservationCredentials` require
`permission == "observe"`. The worker, controller and sealed credential receipt
preserve that exact binding. Keep those types and their existing wire/config
forms observation-only; accepting a write permission in that form is not a
compatible expansion. `AdoReader` remains a reader, and the standalone host
continues to construct only its existing read handlers until the separate
writer dependency is available.

Expand the existing credential/provider owners with a separately identified,
optional protected-review contract. Its trusted selection must bind the actual
provider/HTTPS endpoint, repository/project, native PR and native principal,
permitted review action kinds, account/audience and finite credential lifetime.
The custodian must verify the actual acquired material against that selection;
copied scope fields, an opaque broad token or the Gateway's authentication of a
caller do not establish native write permission. Review permission never
includes merge, completion settings, another principal's vote or general HTTP.
Any broader underlying native credential remains behind the selected owner's
operation restrictions; do not describe routing restrictions as token
downscoping or permission verification.

Retain the existing acquisition, controller verification, encrypted delivery and
worker receipt checks rather than creating another issuer or delivery channel.
Every hop must retain the separate review binding, including renewal and result
verification. An observation binding cannot satisfy it, and a review binding
cannot silently satisfy an observation-only consumer. Old credential
configuration and signed receipt forms keep their existing meanings. Where a
strict reader needs a new field or variant, expand its owning versioned parser
first; never start sending an extension merely because it looks additive.

Advertise support through the actual selected provider's existing discovery
and authenticated session/response seams, separately from package versions.
Gateway receiver support alone does not establish support in the selected
controller, credential verifier, worker or native transport. Resolve the whole
selected path before requesting review material. A missing, old, withdrawn or
rolled-back dependency makes only protected review unavailable before credential
acquisition or native effects; preserve ordinary observation and original
operation recovery. No effectful compatibility probe or retry through ambient
authentication is permitted.

The native ADO provider owns the concrete finite protected request path.
Compose its existing HTTPS/deadline/response-bound machinery with the selected
credential owner, rather than wrapping legacy ambient CLI/curl authentication
or adding a parallel forge client. The factory acquires one immutable private
material generation and pins that exact reference through
`connectionData.authorizedUser`, candidate/policy reads and selected writes.
Check current owner admission, expiry/revocation and that same reference at
dispatch; renewal or account changes cannot replace it within an operation.
A generation mismatch during preflight leaves the action unattempted. Once the
durable attempt fence is entered, preserve unknown effects and original receipt
recovery even if dispatch subsequently refuses; do not infer an unattempted
action from a transport error. Never retry a write with freshly acquired
material to conceal that loss.

The factory supplies the actual owner's action-relevant review-policy guard
and finite request/drain lifetime to `AdoReviewContext`. There is no permissive
default guard. Validate native identity/target and current candidate evidence
through that same transport before writes. Bound method/route/body selection
to the existing native review adapter; a serialized host reference cannot
install an arbitrary request function. Keep the original replay store,
pre-effect unknown fence and post-effect settlement rules; credentials,
authorization headers and private material references never enter prepared
intent, receipt JSON or logs.

Deliver this expansion before its host consumer. Qualify actual parser and
transport seams with contained synthetic credentials: old/current callers and
providers, provider rollback, missing/withdrawn support, observe/review
substitution, wrong endpoint/repository/PR/principal/action, expiry/revocation,
rotation between identity read and dispatch, malformed/oversize/late responses,
and response loss after an entered write. Prove refusal before acquisition for
unsupported paths, no writes from default/read-only configuration, no credential
leakage and no replay after unknown effects. Source controls are not installed
controller support, actual native permission verification or live enrollment.

#### Current authority and request-local material

The existing Fleet `RelayCredentialProvider` calls the mandatory custodian
verifier with the raw relay response and its selected `RelayPolicy`; it does
not implement that verifier. The credential-relay server's similarly named
`RelayPolicy` only filters relay actions/hosts. Neither policy supplies native
review permission. Keep the two owners distinct rather than using the relay
allowlist as the missing verifier.

Verification has separate inputs: the selected credential source's
authoritative account, audience, granted-access and expiry information; native
effective permissions for the exact target/principal; and the current
custodian's admission/revocation state. Bind them to the actual acquired
material, not copied request fields. The existing raw Azure relay response
alone does not supply all those facts. Unsupported source formats remain
unavailable; do not infer grants by decoding an unverified token, from a
successful read, from `.default` in the acquisition request, or from the
requested action list. Broader native grants may remain behind the finite
request restrictions; those restrictions are not token downscoping.

For the existing `AzLoginSource`, this is an actual acquisition-format gap,
not an unfinished token decoder. Microsoft's
[access-token guidance](https://learn.microsoft.com/en-us/entra/identity-platform/access-tokens)
requires clients to treat Microsoft API access tokens as opaque and use token
response metadata for granted scopes and expiry. Azure CLI's public
[`get_access_token`](https://github.com/Azure/azure-cli/blob/dev/src/azure-cli/azure/cli/command_modules/profile/custom.py)
returns token type, access token, expiry, tenant and optional subscription.
Its underlying
[`Profile.get_raw_token`](https://github.com/Azure/azure-cli/blob/dev/src/azure-cli-core/azure/cli/core/_profile.py)
already discards granted-scope metadata from the MSAL acquisition result.
Neither calling that method directly nor parsing the relay's key/value
response recovers the missing evidence. The relay's existing supported source
contract returns that response, not an authoritative acquisition record.
Keep this raw source unsupported for protected-review verification. Do not
decode an API token or reach into an account's private cache as a substitute,
label requested scopes as granted scopes, add an alternative issuer, or probe
real credentials to conceal the gap. A future acquisition-owner expansion
must preserve authoritative response metadata and actual account/material
custody through a reviewed supported boundary before enabling this writer.

The current relay's `CredentialSource.resolve` interface returns framed text,
and `HttpSourceRegistry` adds only routing references and scope selection.
Neither exposes a metadata-preserving acquisition record. The raw MSAL result
exists inside Azure CLI's credential implementation before
`Profile.get_raw_token` transforms it; an internal method or test inspection
hook is not a supported relay acquisition boundary. Preserve this dependency
as unavailable until the acquisition owner supplies that supported contract.
Independent journal, read and consumer work may continue; none enables the
protected writer or closes this prerequisite.

Use the native provider's read-only permission evaluation for effective
principal permission, with the same pinned material and finite IO owner.
For ADO, the documented
[Has Permissions GET](https://learn.microsoft.com/en-us/rest/api/azure/devops/security/permissions/has-permissions?view=azure-devops-rest-7.1)
evaluates the caller against security tokens. Resolve the relevant native
namespace/action semantics through the supported provider contract, select
the exact repository/target token, and require complete positive results with
no administrator shortcut. A positive result is not OAuth grant or token
audience verification. Missing, denied, ambiguous or unsupported permission
information refuses review; never use a write as a permission probe.

Current local ownership remains with the admitted credential custodian.
`LaunchScope.check()` only establishes that the service process has not
withdrawn; neither it nor `ReviewScope` is native authorization. The native
factory's mandatory `checkpoint(material)` must recheck the selected
custodian's current admission and the same material generation at each
existing dispatch boundary. Do not substitute host readiness, an unexpired
Gateway session or a permanently successful callback. This is not a new
credential lease registry or an additional operator sign-off ceremony.

The workspace also needs an explicitly selected **request-local factory
resolver** before normal-host enrollment. Its current
`lambda: write_context(number)` invokes the embedding again for each action
and feedback reconciliation; constructing `ado_review_context_factory` there
would reacquire credentials inside one submission. Instead resolve that
factory lazily once on the first protected-context request, then reuse it for
all contexts in that workspace execution, including feedback. Retain the
existing per-context embedding unchanged as a separate compatibility path;
select at most one path and never silently downgrade the request-local one.
The resolver receives the selected native scope and the enclosing request's
checkpoint/deadline. It cannot extend the budget or cache material across
concurrent requests or the host lifetime.

Do not acquire review credentials for capabilities, preparation, original
selection/receipt lookup, or a confirmed-operation replay needing no protected
readback. A later execution may acquire material for read-only reconciliation
of an unknown action, but may not resend that action or replace its original
attempt/receipt. Within each execution, expiry, rotation, withdrawal or denial
cannot trigger replacement acquisition. Current authorization gates access
without rewriting approved content.

Deliver and qualify this finite workspace lifetime seam before extending the
strict standalone host parser. Native verifier/source adoption remains its
own prerequisite, not something an injected resolver completes. Focused
controls must prove one acquisition across multiple actions and feedback,
zero acquisition on storage-only recovery, independent concurrent requests,
denial/rotation without reacquisition, unchanged legacy embedding, and
unknown-action reconciliation without resend. Missing or withdrawn whole-path
support refuses before acquisition; all network work retains the existing
bounded transport and drain owner.

### Recovery, compatibility and lifecycle

Continue the existing original-operation key and final prepared selection.
Lost responses, restart and later source/profile changes return the first
committed bytes without redecoration or replacement IDs. Current authorization
may refuse access or submission; it cannot rewrite retained approved content.
Explicit preview/approval, execution admission and native delivery stay separate.

Keep the existing fresh-selection contract, separate owned-edit extension,
explicit-ID preparation and v1/v2 submission semantics. Select the actual
executing provider's support, not a package version. Missing dependencies,
withdrawn enrollment or rollback make the optional path unavailable before
effects; no effectful probe/fallback or blanket legacy rejection is allowed.

Use the current storage/lifecycle owner for explicit prepared-intent and
selection adoption, excluding incompatible readers. Serving never provisions,
adopts, downgrades or discards existing state. A new host option cannot migrate
a read-only volume or erase unresolved native outcomes.

## Serial delivery and qualification

### Preparation without writer enrollment

This **agent-recommended, review-first refinement** separates the existing
no-effect preview from the unavailable protected writer. It does not relax
the writer prerequisites above. The current receiver requires a writer even
for `allocate`; that is an implementation coupling, not evidence that
preparing a retained preview needs native write credentials.

First qualify an explicitly selected preparation-only embedding at the
existing workspace owner. It must use the actual source/profile resolver,
existing exact source/generation/target checks, prepared-selection storage
adoption and immutable original-operation recovery. Retain the current
`allocate` payload, exact v2 prepared intent and explicit-approval requirement
where their meanings suffice. Advertise only operations the selected owner
can execute: preparation support never implies `submit` or a writer. Preserve
the existing strict capability shapes; if a consumer currently conflates
preparation and submission, expand its owning discovery contract first rather
than fabricate a writer or advertise an unsupported baseline.

Capabilities, allocation, original-preview recovery and receipt inspection
must acquire no protected credential. Do not introduce a success-returning
writer callback to pass the constructor, a new preview ledger, automatic disk
adoption, arbitrary import/command execution or a fallback to remote identity
labels. Defaults and prior writer-enabled embeddings keep their behavior.
Withdrawal of preparation prevents new allocation; already retained content
keeps its original bytes under the current access and recovery rules.
Submission remains unavailable without its real independently selected writer.

Then expand the strict standalone host configuration explicitly before its
consumer. Bind one trusted producer to an existing admitted caller/target and
actual managed source, through the supported source/profile owners. Their
test-only import paths are not installed support. Qualify actual packaging and
executing provider discovery before advertising normal-host preparation.
Old configurations remain read-only, strict old parsers reject the new
selection, and rollback refuses only the unsupported optional route without
rewriting storage. No host configuration may load an arbitrary Python factory,
borrow the service checkout's identity or turn an observe credential into a
writer. Host activation, credentials and installed/live-provider acceptance
remain separate.

Focused source controls must exercise the real CLI/client/Gateway receiver:
zero protected acquisitions or sends across allocation and restart/recovery;
actual source/profile composition outside the replay lock; wrong or withdrawn
producer and source/target binding; capacity and uncertain-retention recovery;
unchanged writer-enabled and default read-only behavior; current/prior
capability selection and provider rollback; and refusal of submission even
when a valid prepared preview exists. Preparation-only proof closes only that
finite source leaf, not normal protected submission or all-publisher adoption.

#### Canonical helper delivery and native source discovery

The next **agent-recommended, review-first source prerequisite** separates
independently installed preparation from test-only script imports. Keep the
attribution plugin payload-only. Deliver its canonical profile/preparation
implementation as self-contained service package assets through the existing
explicit build/resource and packaged-asset owners, not a second preparer or a
new attribution runtime. A declaration used only by release materialization
does not make an ordinary development wheel build complete.

Keep the direct wheel, sdist rebuild, development test snapshot and release
artifact input closures consistent. Include only the selected canonical
helpers and required notices; retain byte-identical source ownership rather
than hand-maintained copies. Package-local imports must not depend on sibling
plugin installation, an ambient top-level module, a checkout on `sys.path` or
global import-path mutation. Preserve the existing direct-script use of the
attribution helpers. The service's Python dependencies must not select or
replace its separately selected native Worktrees installation.

Expand the existing native `attribution-prepare` comment-origin operation
provider-first. Add an explicitly selected absolute producer root resolved by
the current exact-root source owner, plus versioned no-effect discovery from
the actual executing installation. Discovery must require neither a managed
CWD nor source/profile resolution, credentials or forge access. It does not
allocate identity, prepare a body or grant publication authority. Preserve the
existing PR-body and CWD-based comment-origin callers and their meanings.

The later host consumer selects the immutable native invocation and its
trusted configuration, resolves supported behavior once for that selected
generation, and requests origin for the actual producer root before the
replay transaction. It must not import Worktrees into the service, select a
command through `PATH`, or fall back to the service CWD, an enclosing tracked
root, the PR author or remote source labels. Missing/ambiguous managed mapping,
privacy refusal or source withdrawal refuses new preparation. Retain the
current finite captured-output, deadline, cancellation and cleanup owners;
no external command runs while the replay lock is held.

Old parsers may reject the new optional selection/discovery form. Treat that
as unsupported preparation, not permission to guess support or retry a
different identity path. Old commands remain usable, and a provider rollback
disables only the unsupported optional route without changing original-preview
recovery or storage. Deliver and qualify this provider before adding the
strict host option that consumes it.

Focused source controls must build and consume the real wheel outside a
checkout, rebuild its sdist without canonical siblings, compare the selected
helper bytes, and reject ambient-module substitution. Exercise actual native
parsing/discovery with no source CWD, unique exact-root resolution, ambiguous/
wrong roots, privacy failure, unchanged old calls, missing/prior providers and
rollback. Prove no credential acquisition, forge call, allocation or write
during discovery/origin resolution. These packaging/provider exits precede
normal-host qualification; they do not prove installed enrollment, protected
submission, all-publisher adoption or either parent's completion.

### Remaining writer and host qualification

1. Review this enrollment contract before changing normal-host behavior.
2. Deliver an actual source/profile resolver through the existing preparation
   owners and qualify its executing compatibility boundary. Do not count
   caller-provided fixture callbacks as this exit.
3. Supply the actual protected write-owner prerequisite through its existing
   provider/credential boundary, then explicitly bind the selected host route.
   Keep the default and separately configured observation-only routes read-only.
4. Qualify actual first preparation -> durable preview -> explicit exact
   submission -> original native receipt and restart/recovery through the
   normal parser/process/host seams. Keep source, installed and live-provider
   evidence separate, and update the publication inventory with only that
   finite surface's demonstrated status.

Focused contained controls must cover wrong producer, source/privacy/profile
failure, caller policy spoofing, observe-only and rotated/revoked credential
bindings, mismatched native principal/target, old/missing/withdrawn support,
changed profiles after a lost preview, cache-independent original recovery,
owned/legacy edit history, capacity/lifecycle refusal and withdrawal/drain.
Prove no native write occurs during preparation and no submit is reachable
from default or read-only host configuration. Preserve unknown native effects
without replay or false receipt/echo/handled progress.

This contract and synthetic source controls cannot close all-forge publishers,
acquisition/DB mapping, full provider/CLI/Dispatch/retention, installed adoption,
shadow/presentation or either parent effort. Activation, deployment, retained
hosts, retrospective edits and resource release are not authorized here.
