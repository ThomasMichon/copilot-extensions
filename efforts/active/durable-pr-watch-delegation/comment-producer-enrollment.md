# Trusted comment-producer enrollment

Back to the [canonical effort](README.md) and
[existing-owner intent binding](comment-intent-binding.md).
This is an **agent-recommended, review-first source contract** under #11128.
It does not enroll a host, grant forge effects or qualify installed adoption.

## Actual boundary

The optional receiver and CLI/Gateway consumers can retain prepared selections,
but their tested `selection_preparer`, `comment_preparer` and protected
`write_context` are trusted embedding inputs. They are not normal-host wiring.
`WorkspaceTools()` is unbound by default. The standalone
`WorkspaceConfig.operations()` constructs only native readers; its credential
command authorizes observation, not review submission. The
[native read-only host contract](native-workspace-host-slice.md) remains intact.

Likewise, `AdoReviewContext` consumes an existing credential-pinned request
transport; constructing that class does not supply such a transport or authorize
it. Do not call a fixture factory a production owner, relabel native read
acquisition as protected write acquisition, or enable allocation/submission
merely because storage and capability declarations support their wire shapes.

## Finite source outcome

Compose one explicitly selected producer through the existing authenticated
workspace owner. Preserve watch-only and native read-only configurations and
their storage unchanged. Enrollment is default off and scoped to the existing
caller/target route, provider endpoint, repository and actual native principal.
The host must have the real preparation and protected submission dependencies
before advertising the corresponding optional operations.

Use the existing host, workspace, source, credential, replay and lifecycle
owners. No second listener, effect ledger, credential issuer, callback registry
or arbitrary import/command execution facility is introduced.

### Source and policy belong to the producer

Bind the selected producer to its actual managed source through the Worktrees
owner and resolve its effective AI profile through the attribution owner.
The service's own checkout, the PR author's worktree, a caller-supplied codename
or a hash-valid reviewed-code attachment cannot substitute for producer origin.
Delegated authorship keeps its existing source-custody rules.

Resolve destination visibility, disclosure obligations and anonymous/source
policy from the existing trusted owner, not remote `required`, `visibility`,
profile, configuration-path or source-identity labels. Missing or ambiguous
facts refuse the optional preparation path; do not silently claim stamping.
Keep required disclosure when predecessor context is absent or races. Do not
add a forge query solely to suppress a short repeated signature.

Use the actual shared preparer rather than copying its profile/marker logic.
Resolve IO-bearing source/profile inputs before the replay lock; only bounded
pure composition and original-selection allocation run in that transaction.
If independently installed components need a new preparation-context boundary,
review and expand its owning provider contract before using it. Do not load an
arbitrary Python factory from host JSON or run an external preparer under the
replay lock to make an injected callback appear deployable.

### Protected submission remains a separate prerequisite

The actual write owner must select the existing authorized credential and
transport, retain their private binding through current-principal/candidate
reads and native writes, and enforce current review policy at dispatch.
An observe credential, Gateway caller identity, source marker, prepared preview
or configured principal is not that write authority. Preserve the existing
exact-selection checks, selected native-target/author checks, original outcome
receipts, unknown-effect fences and finite request/drain custody.

Realize any missing protected native transport at its existing provider/
credential owner before enabling the host consumer; do not create an alternate
forge client or fall back to ambient authentication. Static configuration can
select supported trusted references, not manufacture a private binding or turn
an observation route into a writer. Actual live credential/backend enrollment
and native effects require their own applicable authorization.

### Recovery, compatibility and lifecycle

Continue the existing original-operation key and final prepared selection.
Lost responses, restart and later source/profile changes return the first
committed bytes without redecoration or replacement IDs. Current authorization
may refuse access or submission; it cannot rewrite retained approved content.
Explicit preview/approval, execution admission and native delivery stay separate.

Keep the existing fresh-selection contract, separate owned-edit extension,
explicit-ID preparation and v1/v2 submission semantics. Select the actual
executing provider's support, not a package version. Missing dependencies,
withdrawn enrollment or rollback make the optional path unavailable before
effects; no effectful probe/fallback or blanket legacy rejection is allowed.

Use the current storage/lifecycle owner for explicit prepared-intent and
selection adoption, excluding incompatible readers. Serving never provisions,
adopts, downgrades or discards existing state. A new host option cannot migrate
a read-only volume or erase unresolved native outcomes.

## Serial delivery and qualification

1. Review this enrollment contract before changing normal-host behavior.
2. Deliver an actual source/profile resolver through the existing preparation
   owners and qualify its executing compatibility boundary. Do not count
   caller-provided fixture callbacks as this exit.
3. Supply the actual protected write-owner prerequisite through its existing
   provider/credential boundary, then explicitly bind the selected host route.
   Keep the default and separately configured observation-only routes read-only.
4. Qualify actual first preparation -> durable preview -> explicit exact
   submission -> original native receipt and restart/recovery through the
   normal parser/process/host seams. Keep source, installed and live-provider
   evidence separate, and update the publication inventory with only that
   finite surface's demonstrated status.

Focused contained controls must cover wrong producer, source/privacy/profile
failure, caller policy spoofing, observe-only and rotated/revoked credential
bindings, mismatched native principal/target, old/missing/withdrawn support,
changed profiles after a lost preview, cache-independent original recovery,
owned/legacy edit history, capacity/lifecycle refusal and withdrawal/drain.
Prove no native write occurs during preparation and no submit is reachable
from default or read-only host configuration. Preserve unknown native effects
without replay or false receipt/echo/handled progress.

This contract and synthetic source controls cannot close all-forge publishers,
acquisition/DB mapping, full provider/CLI/Dispatch/retention, installed adoption,
shadow/presentation or either parent effort. Activation, deployment, retained
hosts, retrospective edits and resource release are not authorized here.
