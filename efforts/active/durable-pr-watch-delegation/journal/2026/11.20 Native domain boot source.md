## Source boundary

The additive `update_driver.boot` API samples a version-1 execution-domain/boot
observation. Its initial native implementation uses the Windows VM Generation
Counter, whose [published semantics](https://uapi-group.org/specifications/specs/vmgenid/)
preserve the generation across ordinary guest reboot and change it for
clone/restore. Two device reads are bracketed by equal native boot observations;
changes, invalid records, unsupported venues, device absence and access denial
refuse without identity fallback or elevation.

The [owner documentation](../../../../../libs/update-driver/README.md#execution-domain-boot-observations)
records the fixed finite-read API, raw-byte encoding, administrator/SYSTEM
requirement, conforming-hypervisor assumption and container/mounted-home limits.
Linux/WSL and macOS have no implemented continuity provider. The existing
kernel-boot APIs and consumers remain compatible. The new API is unwired:
no watch-record adaptation, final import, isolated authority, ordinary entry or
map/cwd publication is enabled.
