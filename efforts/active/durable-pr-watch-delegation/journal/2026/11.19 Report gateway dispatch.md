# Report Gateway dispatch

The isolated PR-service run
[44661985158](https://github.com/ThomasMichon/copilot-extensions/actions/runs/44661985158)
exposed the separate report-path blocker #13585 while qualifying the deadline
leaf #13582. The existing Gateway dispatch cast evaluated a response class
imported only under `TYPE_CHECKING`, so both report route versions raised
`NameError` before the report owner could respond. Future annotations do not
defer the ordinary argument passed to `cast`.

The bounded correction defers that cast's type expression as a string. It adds
no runtime SDK import, listener, provider call, contract, state or policy
fallback. The existing optional response capability remains optional, and the
real handler retains its structured refusal for an unconfigured report owner.
This restores the documented report dispatch rather than changing the design
or completing the parent service acceptance.

- The final report dispatch/read/bounded/transport packet passes **109**
  controls, with **five existing skips**, under the contained Windows runner.
  The new controls also preserve replay-store bytes across the refusal.
- Whole-file strict MyPy passes the changed source and regression file at
  Python 3.10 for Linux and Windows analysis targets; no project-wide strict
  admission or native Linux execution is inferred.
- Ruff `F,E9`, the runtime install-contract gate and diff checks pass.
- The published candidate still owes independent review, required CI and
  the isolated Linux service lane. The original three terminal-event failures
  remain with their existing owner coordination on #13565; this leaf does not
  edit or supersede that work.

The small end-to-end regression executes `WatchGateway.handle` and the real
report route with a provisioned private replay store and trusted synthetic
caller. Existing report controls cover selected owners and bounded transport.
No live provider, credentials or retained installation is used. A clean-room
installation is unnecessary for this type-expression-only correction; it
changes no bootstrap, installer or stored layout. Source publication does not
authorize service activation, deployment or any additional live trial.

## Discovery refusal is not lookup evidence

The measured head passes full hosted native qualification and required CI in
runs `44678947019` and `44678918663`. Its review nevertheless identifies a
valid test gap: a discovery-time 503 could satisfy the negative control before
the retired-generation lookup occurs.

The fixture now deliberately returns one discovery 503 at its caller facade,
keeps that failure retryable, and accepts only a later actual `/lookup` 503
after successful discovery in the same attempt. It verifies the recorded
lookup request's PR number and original generation ID, the real structured
owner-refusal response, and its known outcome. A discovery failure alone
cannot produce the test's distinct expected-refusal result. This is a
deterministic caller-fault control; it does not claim an actual server-lock
interleaving from the injected response.

All seven existing installed scenarios using the shared helper pass together
with teardown in **335.96 seconds**, under the unchanged 420-second limit.
Whole-file strict checking for all three changed Python files passes on both
platform targets, as do Ruff and diff checks. Fresh review and exact-head
hosted checks remain necessary after this correction.
