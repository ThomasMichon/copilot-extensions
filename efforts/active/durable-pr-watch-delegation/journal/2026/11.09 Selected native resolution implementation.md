## Source boundary

Implemented the optional ADO-only Worktrees `pr-thread-resolve` receiver,
then the capability-selected native `resolve-thread` client. Existing
claimant/target/worker-policy admission, native principal and effective
repository/branch permission evaluation remain the owners. The legacy bulk
resolver and read-only routes retain their independent behavior.

The additive ADO report expectation binds endpoint, target/source identities,
refs, head/base/common commits and current source iteration. Missing count,
nested-comment, identity or stable-candidate evidence cannot supply it.
Selected resolution requires an active discussion with native iteration
association and an exact thread fingerprint.

The existing remediation transport performs only one selected status PATCH.
The existing locked ledger consumes the operation before dispatch and binds
target, actual actor, candidate/thread revision and requested status.
Interrupted or unknown operations reconcile read-only; a later closed thread
does not convert another participant's action into this operation's success.
Confirmation is preflight plus authoritative response/readback, not atomic CAS
or exclusive causal attribution.

## Review corrections

The native iteration records its historical target commit; a target-only
branch advance need not create a new source iteration. Candidate evidence now
retains the current PR base in its fingerprint and bracketed observations
without requiring equality to that historical iteration target. A focused
regression proves the old candidate refuses and a fresh, stable target-only
candidate can resolve.

Truncated HTTP responses can raise `http.client.HTTPException`, independently
of `OSError`. Both existing ADO read/write transports now normalize that family
to provider errors. Direct JSON callers retain an unknown envelope after a
truncated PATCH or readback; consumed-key reconciliation preserves the original
unknown result and performs no second PATCH. The final affected packet above
includes these six additional controls.
