# Bounded native inventory page sizing

Back to the [canonical effort](../../README.md) and

## Receiver-first source

This focused continuation under #6007 adds optional page sizing to the existing
native inventory operation. A rich 50-member PR page can exceed the existing
response capture even when an individual snapshot works. The source does not
raise that capture or add another discovery client.

The existing passive runtime declaration advertises the option and its
supported range/default. Ordinary callers retain 50; explicitly selected pages
use GitHub's `per_page` or Gitea's `limit`. Native Python callers receive the
same optional argument. A consumer must qualify its executing runtime before
emitting new syntax; this provider expansion switches no consumer.

Maximum pages/pulls, deadline, credential acquisition and transport bounds
retain their original meanings. A smaller page cannot grant another request.
A short nonempty page does not certify completeness. A response exceeding the
selected member count refuses, preserving earlier accepted pages as partial.
There is no automatic page-size retry or fallback.

## Focused source qualification

The final packet passes **126 tests** across native inventory, selected page
sizing, HTTP profiles and actor guards. Rich synthetic GitHub/Gitea pages
exercise both legacy and direct transports: the unchanged 50-member default
refuses an oversized response, while an explicit 20-member page discovers
45 PRs and an authoritative empty page within the same four-request limit.
Capture ceilings are unchanged. Page/pull exhaustion remains partial, larger
server pages refuse, invalid Python/CLI inputs are passive, and the declared
option reaches the actual parser and provider.

The existing packet also retains actual bounded child capture and captured
typed-credential command controls. The new cases introduce no live provider,
credential or service dependency. All three changed Python files pass the
strict whole-file ratchet for both Linux and Windows; lint passes.

These are local source controls, not independent review, required CI,
promotion, an installed capability or continuing provider coverage. The
full parent and later caller/installed acceptance remain open. No source
default, registration, writer, observation ledger or production service is
changed by this source-only leaf.
