## Delivered scope

The first implementation slice after #13277 keeps the existing unversioned
list encoding and old caller contracts. Reads explicitly refuse versioned
subscription envelopes, unknown schemas, malformed versions and other non-list
state. The existing atomic-write owner now rechecks the retained file under
its replacement lock immediately before replacing it. An already-running
contract-aware daemon cannot overwrite a newly encountered incompatible state
document through registration, replacement or cancellation. Definite refusal
uses the existing persistence error and registry rollback.

This is not the historical inline-executor activation guard. It does not add
a cross-process lease, context-bearing writes, `subscriber_cwd/v1`, caller
defaults, installation adoption or an unsupported-reader retirement. Existing
writer/lifecycle custody remains required. P/V/G5947-3/4 and the parent remain
open; the next source stretch is ordinary startup/rollback and already-running
historical-writer transition protection before enabling the map.

## Validation

- The new real-filesystem packet reproduced 12 unsafe-overwrite failures
  against the unchanged writer. With the guard, the selected storage,
  acknowledged/legacy delivery and lifecycle packet passes 155 tests.
  Cold refusal, passive adoption, final-replacement interleaving, unchanged
  bytes, registry rollback and legacy-list positive controls are exercised.
- Nine actor-free unit cases pass and are positively admitted in the required
  unit manifest. Full-file strict checks pass for all three changed Python
  files against Linux and Windows targets; Ruff F/E9 and the installation
  contract guard pass.
- The optional full Windows-native unit portfolio stops during collection on
  a separate extended-path bytecode-attribution failure, reproduced with
  Python 3.11 and 3.14 and tracked in #13294. This is not a passed full native
  packet or a waiver of required Linux CI.
- First-touch behavior uses empty, test-owned state roots and real atomic
  storage. No installer/bootstrap behavior changes; a full clean-room install
  is not claimed. No forge or external operational venue is necessary for
  this local storage contract, and none was exercised for this slice.

## Performance

Every write adds one local read/JSON decode of the current collection under
the existing replacement lock. It adds no process, network request, tree scan
or history read. Caching that read would miss an incompatible replacement,
which is the failure boundary being repaired.

A native Windows local-temporary-volume comparison alternated 100 completed
writes per arm at 10 and 1,000 subscriptions, with zero errors. The comparison
uses the unchanged atomic helper without its optional guard versus the guarded
subscription writer. At 10 entries (1,441 bytes), median/p95-nearest-rank
milliseconds were 5.71/23.65 versus 9.01/39.23; at 1,000 entries (147,783 bytes),
53.40/81.51 versus 74.10/151.96. Means were 7.90/14.75 ms and 54.73/81.43 ms;
maxima were 31.06/131.69 ms and 117.88/190.55 ms respectively. Individual
samples are retained by the validation owner. These are warm paired synthetic
measurements on a shared host with incidental concurrent validation, not an
installed-daemon latency budget or tail qualification; 100 samples do not
establish p99. Linux native timing remains unmeasured.
