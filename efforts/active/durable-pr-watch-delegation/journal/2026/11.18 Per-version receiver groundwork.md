## Merged source boundary

This is the first runtime expansion following reviewed #13310, not completion
of the historical transition or P/V/G5947-3/4. The outer version-2 receiver
accepts only active state version 1 (the existing legacy list) and executor
admission epoch 1. Its existing writer preserves opaque unselected partitions,
selected extensions and the recorded epoch, even after the last subscription
is removed. There is no envelope publisher, migration command, active version-2
map, cwd capability or caller-default change.

The generation is a source-owned, monotonically ordered admission epoch of
the actual executing implementation, separate from package/build provenance.
An incompatible future epoch must advance this constant in its own code.
It is not a total ordering of package releases, a selection stamp, or an
environment override. Existing governed invocation validation still establishes
the actual immutable interpreter/module slot. Epoch 1 cannot restart against
epoch 2, even if an old retained partition would otherwise be readable.

Cold legacy serve and self-boot check before resident admission/spawn; restart
checks before acquiring custody or requesting predecessor shutdown. Governed
ensure checks before starting its transaction and again under that guard.
Writer adoption already reads through the final native lease, and activation/
resume now rechecks disk admission before effects. Passive construction remains
effect-free; it does not become an active owner without adoption/activation.
This is state-executor admission, not an installation-readiness or
current-selection veto.

The process-local atomic lock now spans the final read/modify/write. The final
byte recheck refuses a concurrently changed document before replacement;
another partition cannot be overwritten by a stale pre-serialization snapshot.
Existing definite-failure and uncertain-durability behavior remain distinct.
The native writer lease remains necessary; this does not add a competing
cross-process lock.

### Review corrections

The first source review identified two real high-severity classes. A caller's
early restart read could become stale before incumbent shutdown, and standard
JSON float decoding could round opaque values or turn a finite exponent into
infinity. Restart now carries its executor epoch to the existing shutdown
operation; the incumbent checks requester compatibility and current state
under its own persistence custody before changing shutdown flags. A newer
requester may still stop an older compatible owner, and ordinary stop keeps
its existing semantics. An unaware peer ignoring an additive field remains
part of the unqualified historical transition, not new enforcement credit.

The decoder now refuses a number unless its decimal value round-trips through
the supported float representation. Precision-loss, exponent-overflow and
underflow controls first failed as expected, then passed with the correction;
ordinary float-valued deadline data and large exact integers remain supported.
Refusal occurs before replacement and follows the definite-write-failure path.

The revised packet passes 353 native source/CLI cases and 24 actor-free units.
Three existing actual-entry tests also pass, distinguishing an ephemeral
controller from both real foreground daemon entries. The initial CI daemon
coverage guard found that a runtime typing alias obscured its canonical
admission import; that adapter is now type-checker-only, preserving the direct
runtime import and the unchanged guard.

A subsequent review found the same admission class at the registration-value
boundary: a supported envelope could contain a malformed selected entry and
stop the incumbent before the successor's strict restore failed. One shared,
effect-free registry validator now governs all versioned owner reads, including
cold start, self-boot, governed ensure, restart and delayed activation. The
writer supplies that same validator to the existing atomic storage owner for
the prior state, replacement candidate and final-state recheck. The lower-level
codec refuses versioned writes without a semantic validator. Neither a
shape-only read nor a cached successful validation licenses a later write or
shutdown. Legacy-list behavior is unchanged.

The final focused packet passes 358 native source/CLI cases and 28 actor-free
units, including malformed-entry shutdown/resume refusal, unchanged in-memory
registration on write refusal, and missing/current/candidate/final validator
controls. Valid native-lease pending-state adoption remains a positive control.

## Repeated-write cost

The writer adds one initial full-document read/parse before preparing a
replacement, in addition to the prior final-boundary read. The lock spans
that read, serialization and replacement. This is necessary to preserve
unselected partitions and reject delayed snapshots; an earlier cached
document cannot authorize a final write. There are no extra processes,
pollers, network calls or persistent history records.

On one shared Windows host, 100 alternating warm samples per arm and size
completed without errors (600 total writes), including float-valued timeout
metadata with the reviewed numeric decoder and actual strict registry
validation on the versioned arm. At 10 legacy entries, prior/new list p50 was
3.75/4.62 ms and nearest-rank p95 was 4.72/6.01 ms; the new versioned arm was
5.65/6.62 ms. At 1,000 entries, prior/new list p50 was 24.49/35.17 ms and p95
was 59.44/70.66 ms; the versioned arm was 88.30/132.91 ms. This includes three
effect-free strict validations per versioned write; ordinary legacy writes do
not acquire that work. Complete samples, means/maxima, source digests and opaque-state
assertions are retained with the owning qualification packet. These samples
do not establish p99, fleet tails or a dedicated-host latency budget.
