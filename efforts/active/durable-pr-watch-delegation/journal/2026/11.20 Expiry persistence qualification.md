## Bounded retained-acceptance slice

P5947-1/V5947-1/G5947-1 remain the existing expiry acceptance, not a reopened
#6019 outage-expiry defect. This source-only slice adds focused controls for
the current registry, poller, persistence and delivery owners; no runtime
implementation, protocol or installation code changes.

Four pure registry cases cover both delivery contracts, independent subscriber
filters and deadlines, timeout versus legitimate terminal-transition precedence,
and exactly one outcome without retiring another subscriber.
Six real daemon/persistence cases cover legacy and acknowledged expiry during
provider failure, each with successful storage, definite write refusal and
uncertain acknowledgement after actual replacement.

The definite-failure controls pause at the next actual persistence attempt:
unchanged durable bytes and zero notifications must remain observable until
that write is allowed. At notification, legacy removal must already be on
disk; acknowledged delivery must already have the exact pending payload and
original registration identity on disk. Completion must leave one notification,
no pending state, no active registry key and no departed poller.
The uncertain branch follows the existing owner's behavior rather than adding
legacy replay.

## Validation and fixture corrections

The contained canonical runner passes 133 cases across `test_watch_expiry.py`,
`test_watch_delivery.py`, `test_watch_registry.py` and `test_watch_contract.py`
in 20.78 seconds (55.25 seconds including preparation and cleanup), with no
warnings or skips. This combines the new ten controls with the existing
delivery, restart, strict-state and transition cases. Whole-file strict typing
passes for the new file on Linux and Windows; Ruff F/E9 passes.

Initial runs exposed fixture mistakes, not a runtime defect: acknowledged
delivery retries persistence without another provider fetch, and a health read
cannot inspect a transaction deliberately paused while holding its persistence
lock. The fixture now pauses the real retry write and reads only the unchanged
disk bytes, notification list and prior error field while it is blocked. No
production behavior, timeout or runner budget was changed to obtain a pass.

The pure registry cases are the local unit tier. The daemon cases exercise the
real first-touch private storage and existing delivery scheduling boundary.
No provisioning path changed, so this slice adds no installer clean-room
scenario. No external provider, live service, installation, migration, rollout
or retained-resource cleanup was exercised.
