# Bounded native-read concurrency

Back to [Durable PR-Watch Delegation](../../README.md#goal).

## Source slice

The existing observer's native snapshots can own captured subprocesses.
An embedding with a constrained process allocation needs to reduce simultaneous
reads without increasing per-read capture, request or deadline budgets.

The optional `native_read_concurrency` selection now reaches the existing
ReplayObserver executor and pending-read admission through WatchService and the
standalone local-host configuration. It accepts integers 1..4; omission preserves
four and sends no new keyword through the legacy caller path. Explicit local-host
selection qualifies the actual executing service/observer keyword support before
state or provider effects. Unsupported support refuses without fallback.

Inventory and retained-member reconciliation quotas and order remain unchanged.
No additional executor owner, cache, queue, poller, credential mechanism or
automatic live selection is introduced. Existing native join/drain and writer
custody remain the lifecycle boundary.

This closes part of the PR-service vision's
[efficient and fair observation](../../../../../visions/plugins/agent-pull-requests/README.md#efficient-and-fair-observation)
intent through the existing operation. The
[version-skew-safe contract pattern](../../../../../docs/patterns/service-contract-evolution.md)
governs selected API qualification and the receiver-first rollout.

## Validation and remaining acceptance

Focused source controls exercise selected/default executor and pending limits,
strict refusal, unchanged fairness, retained native-read custody through cancelled
or timed-out drain, actual host-to-service-to-observer composition, both local
profiles and prior executing-core refusal. The existing bounded plugin and
standalone runners own their synthetic fixtures. Changed Python files pass
whole-file strict checks for Linux and Windows; the complete standalone project
also passes its admitted strict check.

Source support does not establish a released or installed selection, useful
production latency, complete provider capture or absence of process pressure.
Normal review, required CI, merge and release precede any separately authorized
adoption. Full parent Plan/Validation and all existing integration, migration,
provider and consumer gates remain open.
