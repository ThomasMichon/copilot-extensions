## Reviewed intent and implementation

The bounded T3 contract merged in #13488 as
`9f4c77f85ff2dcd24363afa9b135280b927e1fbc`, after current-head Copilot approval
and all required checks. Both parent plans remain open; the contract does not
authorize a retained-host migration or complete terminal retention.

The implementation adds explicit local `adopt-terminal` handling over the
existing selected workspace configuration. It shares the actual service writer
lease, finite PID/deadline checkpoint and existing terminal adoption
transactions. A running service or failed drain keeps the transition excluded.
Replay, conversation, review/unknown-attempt and cache state remain unchanged
apart from the explicitly adopted storage extensions.

Preflight validates the service/namespace binding, conversation layout and
existing cache descriptor/layout before adoption. Terminal capacity admission
remains with the original storage owner. Optional retained terminal mappings
require already-adopted prepared-review/acquired-mapping prerequisites: this
path does not create per-action slots after other adoption progress.
Fresh provisioning keeps its existing construction; ordinary serving never
migrates retained state.

Interrupted or uncertain replacement can leave a complete partially expanded
envelope. Explicit retry revalidates that same retained volume and continues
idempotent adoption. Neither the command nor retry provisions missing state,
rolls back extensions, compacts payloads, retires cache objects, acquires native
evidence or settles delivery/effect identities.

## Focused source qualification

The transition and existing terminal-host packet passes 37 cases. The new
controls include the actual CLI subprocess, a populated cache and original
unknown verdict beside an unacknowledged head-change event, actual competing
lease ownership, an actual service whose admitted disk work outlives failed
drain, binding/cache/capacity/mapping refusal, expiry, partial adoption,
lost replace result, explicit retry, selected/unselected strict readers and
mapping rollback refusal. Cache objects, original replay payloads/positions and
unknown effect identities are compared across transition and fresh-reader
construction.

Strict analysis passes all 52 service source/test files at Python 3.10 on Linux
and Windows analysis targets. Windows analysis is not native Windows execution.
Focused tests and strict analysis share a one-CPU/one-GiB/64-task finite
containment job with verified cleanup. The initial test environment lacked the
new module; refreshing the declared standalone test package resolved collection.
Two strict-analysis findings were corrected before the final passing packet.
The first PR guard then rejected a changefile naming the distribution rather
than the standalone release component. Correcting its target to `services/pr`
preserves the tested runtime bytes and supplies the actual release intent.

The service CLI/reader changes are source-qualified through the isolated test
installation. They are not an installed production command, live-provider
retention, cross-host fencing, arbitrary external-reader exclusion, whole-system
body-free proof or operational migration. T3, the workspace companion and the
full parent acceptance remain open.
