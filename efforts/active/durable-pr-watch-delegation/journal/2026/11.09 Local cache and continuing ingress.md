# Supported local cache and continuing subscriptions

Stage 3 under #11783/#6007 and the reviewed
[M1 contract](../../repository-cache-events-m1.md).

The explicit Linux Unix HTTP profile now uses the same standalone foreground
host, WatchService writer/admission/drain and canonical handler lifetime/budgets.
Kernel UID-to-principal mappings select static targets/consumers; neither
headers nor bodies synthesize Gateway identity. The local profile constructs
no connector and reads no Gateway proof/access references. Existing connector,
watch/report/workspace defaults remain.

Supported `list`, `query`, `subscribe`, `inspect`, `events`, `acknowledge`,
`cancel` and finite `follow` commands use that actual local HTTP front door.
Queries and subscribers do not acquire a forge or read the state file.
Continuing registrations retain immutable request intent, original IDs,
independent delivered/ACK positions and post-cancel/expiry pending reconciliation.
History gaps require explicit baseline recovery. Byte/count backpressure retains
unsettled data and reserves metadata headroom so ACK can make progress.

The strict continuing layout is positive fresh
`repository_cache_version:2`, not automatic adoption/migration of version-1
cache data. Existing prior/current/rollback readers refuse incompatible state
without recreation. The namespace-owned ReplayStore envelope/lock/atomic writer
remains the only persistence owner.

A coupled source trace found that Fleet's actual ForgeScope still rejected
Gitea even though native snapshot/credential consumers accepted it. The existing
worker/controller/recipient scope schema now accepts Gitea bearer observation
material. No credential issuer, verifier or enrollment was added: external
custodians still verify actual permission/expiry/revocation. Both real typed
credential CLI renewal and TLS/PoP ownership fixtures cover Gitea, alongside
existing GitHub/ADO cases; native consumers enforce the matching bearer profile.

## Independent source-review corrections

PR #11866's first independent review identified five concrete boundary failures:
unbounded stalled response cleanup, count-only query paging, subscription before
first observation, inactive follow pagination, and erased CLI error reasons.
All five are corrected with focused regressions. Real foreground qualification
also exposed local requests contending with the existing observer transaction;
admitted operations now wait for that same custody only inside their original
deadline, never extending expiry or adding a writer. Actual local-client
contention and stalled-socket expiry/withdrawal controls qualify the fixes.
The installed-process vertical is separately retained for the next serial source
stage, not counted as reviewed/merged merely because its local fixture passed.

The second independent review confirmed those five resolved, then identified
quadratic full-cache serialization during trimming and a previously missed
follow-window overrun. Trimming now encodes total/payload once and subtracts
settled event sizes with exact JSON separator accounting. A 1,000-event
regression bounds full-cache encodes independently of eviction count.
The original monotonic client deadline now reaches capabilities, event/ACK
requests and socket send/receive, including trickling reads; no ACK starts
after the window. Actual stalled HTTP phase fixtures and client controls pass
9 cases, core/schema/retention controls pass 18, and admitted standalone strict
typing passes 26 physical files on both configured platforms.

The third review's heading said no open issues, but its body retained two
previously missed Medium findings; it was not treated as clean approval.
Listener withdrawal now aborts and joins owned clients before waiting for
server closure, including a partial-header peer with a 30-second operation
budget and a 2-second withdrawal assertion. Both OS credential readers decode
Linux UID/GID as unsigned fields; actual client/server boundary fixtures cover
UID 3,000,000,000. A related local adoption check now revalidates the private
serving-user root without permission repair or credential/provider probes.
Current focused transport controls pass 3 cases; standalone local/client
controls pass 12, with strict analysis remaining green on both platforms.
