## Result and scope

An operator-authorized isolated Linux installation of the released
`repository-local/v1` service passes the GitHub installed-running lane.
The actual supported native reader, foreground host and local CLI discover a
real PR in a dedicated synthetic GitHub repository, observe later head changes
and deliver continuing events through independent subscriptions.

This is not another synthetic native executable or an injected Gateway handler.
No Core/Gateway deployment is required for ingress. It is also not a claim that
the whole machine is a clean-room environment: the application venv and durable
test state are fresh on an existing Linux host.

The class approval bounds each run to one foreground PR service and 30 minutes.
It separately permits temporary nonpersistent use of the existing selected
account credential and synthetic fixture commits/draft-PR updates by the
qualification driver. The service remains an observer. No credential enrollment,
shared-service replacement, production-state migration, review vote, merge or
retained-resource cleanup is included. Original private approval evidence and
target-specific execution records remain with the qualification owner; this
public record grants no operational authority.

## Reproducible consumer flow and observed exits

Use the [local profile's supported configuration and commands](../../../../../services/pr/LOCAL.md)
with an authorized test repository and its actual credential custodian:

1. Provision fresh dedicated state and select the installed native contract.
   The native GitHub configuration selects the forge origin
   `https://github.com`; the typed credential's effective REST scope is
   `https://api.github.com`. The Unix ingress socket is a short child of the
   dedicated state root.
2. Launch the actual foreground host. Query through the local CLI until
   complete native inventory and the real PR head are present. This trial's
   native inventory completes in two pages; empty readiness is not the exit.
3. Register two finite 900-second continuing subscriptions from cursor zero.
   Read both baselines and ACK one independently. Have the separately
   authorized fixture driver advance the PR head, then observe and deliver
   the real change through the cache.
4. Stop with joined drain and restart over the same state. Retry the original
   request identity and verify the original registration identity. Original
   unacknowledged event IDs and payloads remain unchanged and ordered for both
   consumers. An active consumer may append a later event; immutable original
   delivery does not mean freezing the entire future batch.
5. Advance the fixture again and use the supported `follow --ack` client.
   The finite 45-second follow returns the actual new head in change events,
   not merely an older pending event. ACK remaining deliveries and cancel both
   registrations; both cancellation responses report `cancelled`.
6. Stop and join the foreground, credential helper and transport. Both
   sequential foreground instances exit zero; both original SDK lifecycle
   receipts settle with `process-exit-observed`. Ingress is absent after stop,
   the credential helper joins, and the trial's artifact scan finds no
   persisted credential.

The run uses the SDK's own test lifecycle, an isolated registry, a renewed
300-second lease and an 1800-second hard maximum. It makes 104 per-request
credential acquisitions with no credential-adapter error; that is an
acquisition count, not a measurement of total forge HTTP requests or a
performance guarantee. No foreground instances overlap.

Earlier failed qualifier attempts remain failed: a socket outside the dedicated
state root was refused before service startup; an API-host-versus-forge-host
input mismatch produced honest unavailable coverage; and an over-strict test
assertion rejected a legitimate appended event despite preserving the original
delivery. Their cleanup receipts are clean. The final passing run changes
qualifier inputs/assertions, not the released application binaries.
