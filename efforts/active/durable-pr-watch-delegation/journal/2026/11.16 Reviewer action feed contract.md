overlapping IDs instead of treating them as successful empty or partial
history. It continues through server-clamped short pages to an empty page.
The existing typed credential request budget and capture owner remain in
force; no second HTTP client or request owner is introduced.

The native version-1 snapshot adds nullable review-page coverage and the PR
mutation timestamp already acquired by that provider. The PR-service decoder
retains the additive fields; older snapshots leave coverage unknown.
Review established that Gitea filters other users' pending drafts after
pagination, so an empty page cannot prove exhaustion. This prerequisite is
deliberately narrowed to strict acquisition and additive unknown coverage.
Gitea continues to report `null` until authoritative pagination metadata is
qualified through the same transport owner. Valid team-only review requests
retain their request state without inventing an individual reviewer. These
are source limitations, not permission to classify unknown history as an
initial or handled review.
Coverage does not prove atomic head/review consistency, reviewer policy or
the cause of a PR mutation. Other providers remain explicitly unqualified.

This closes neither the cache-backed query nor its storage/adoption exit.

stretch must preserve existing complete envelopes and unresolved events while

qualification, establish authoritative review-page exhaustion; the existing
