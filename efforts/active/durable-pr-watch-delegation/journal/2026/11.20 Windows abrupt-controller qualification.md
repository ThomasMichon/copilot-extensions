## Bounded current-owner evidence

The contained native Windows packet now exercises real abrupt child exit,
not an injected exception followed by ordinary owner closure. Six cases exit
with `os._exit` after preparation, durable seal staging, original-lease release,
the original-file move, barrier installation and sealed-phase publication.
Each checks the actual interrupted topology and original inode before cold
recovery. Recovery uses the historical path only before its move and only the
new barrier lease afterward; it never opens the retained inode as another lease.
Legacy bytes remain identical, isolated subscription state is absent, and
readiness, notification, provider and activation effects stay disabled.

Canonical contained execution of `tests/test_watch_sealing.py` passes
12 cases with one Linux-only skip. The six added cases use the unchanged
30-second per-test and 300-second packet/plugin limits, a 10-second child
deadline and headless captured subprocesses. Whole-file strict typing passes
the changed test on Linux and Windows. No runtime source, public interface,
installation, live service or retained-resource state changes.

This is not complete historical-runtime/startup-family qualification,
host power-loss durability, native Linux exchange/interruption, an actual
boot crossing, final import, ordinary entry integration or map/cwd activation.
Those gates remain open under P/V/G5947-3/4 and the broader Active parent.
Normal review and required CI remain mandatory before merge; source qualification grants no
installation, reboot, shared-service operation, migration or rollout.
