# Filtered population deadline headroom

## Source correction

The filtered observer previously qualified the native command and then requested
60 seconds of population work with a separate 60-second capture timeout. Both
could consume the observation authority before result validation and replay
publication. A native partial result was not proof that the service could
publish it within the original lifetime.

The observer now projects its original remaining authority onto one monotonic
deadline shared by its repository reads. Each population pass uses the earlier
of that deadline and its existing 60-second maximum. Qualification and capture
share the existing `OwnedExecutionBudget`, with separate native startup/output,
exact cleanup and replay-publication headroom. New work refuses when less than
one native second remains. This narrows execution; it does not extend authority,
change filters, make incomplete coverage complete, or release unsettled cleanup.

This closes a bounded reliability gap under #6007 and the existing
filtered-population intent, not the broader effort. The retained-cache adoption
work in #13565 remains separate. No service schema, native CLI syntax, descriptor
version, installer, deployment or provider support changes.

The simple end-to-end checks use actual fixture subprocesses, the existing

They use no backend, credentials or existing service. Clean-room installation
is not exercised because no bootstrap, installer or state-layout behavior

## Review correction and external lane

The first review on #13582 identifies a coupled fairness defect: advancing a
query cursor before capture admission can skip alternating native query
branches when a shared deadline permits only one repository per cycle. The
new deterministic two-repository controls reproduce offsets `0,2` and `1,3`,
including an admitted failed read. Capture admission now advances the cursor
only after the existing authority and remaining-budget checks; both repositories
subsequently receive `0,1`. Actual native timeout controls also distinguish
qualification refusal from an admitted failed capture.

The second review also finds that the final interest checkpoint can block after
the native allowance was calculated. Two deterministic controls reproduce the
stale allowance and admission despite lost headroom. The allowance is now
finalized inside native admission, after that checkpoint and before the cursor
notification; the same controls require a shortened allowance or no launch and
no cursor advancement. Neither the absolute authority nor cleanup reserve grows.
