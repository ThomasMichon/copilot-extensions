# Filtered population deadline headroom

## Source correction

The filtered observer previously qualified the native command and then requested
60 seconds of population work with a separate 60-second capture timeout. Both
could consume the observation authority before result validation and replay
publication. A native partial result was not proof that the service could
publish it within the original lifetime.

The observer now projects its original remaining authority onto one monotonic
deadline shared by its repository reads. Each population pass uses the earlier
of that deadline and its existing 60-second maximum. Qualification and capture
share the existing `OwnedExecutionBudget`, with separate native startup/output,
exact cleanup and replay-publication headroom. New work refuses when less than
one native second remains. This narrows execution; it does not extend authority,
change filters, make incomplete coverage complete, or release unsettled cleanup.

This closes a bounded reliability gap under #6007 and the existing
filtered-population intent, not the broader effort. The retained-cache adoption
work in #13565 remains separate. No service schema, native CLI syntax, descriptor
version, installer, deployment or provider support changes.

## Validation and limits

- The original implementation failed all three initial regressions, including
  the real observer's inability to publish when a fixture rejected its oversized
  native allowance.
- The final contained Windows packet passes 11 controls: exact scope/input
  lifetime, unsupported drivers, invalid responses, insufficient lifetime
  without launch, qualification consuming capture time, qualification/capture
  timeout settlement, partial-result membership publication, coalescing,
  withdrawal and sponsor compatibility.
- The expanded native/discovery/observer packet passed 265 controls with 10
  existing platform/explicit-lane skips. Its sole failure was a new timeout
  fixture expecting population admission after qualification had already
  consumed its allowance. The final focused packet isolates the two real
  timeout boundaries without increasing its eight-second deadline.
- Whole-file strict MyPy passes all five changed Python files under both
  Linux and Windows analysis, targeting Python 3.10. The legacy native boundary
  was annotated and its now-redundant protocol casts removed for this ratchet.
- Ruff's `F,E9` checks and the runtime install-contract gate pass. Required CI
  and independent review remain publication/merge gates.

The simple end-to-end checks use actual fixture subprocesses, the existing
native capture owner, ReplayStore, observer and subscription membership query.
They use no backend, credentials or existing service. Clean-room installation
is not exercised because no bootstrap, installer or state-layout behavior
changes. Native Linux execution and real-provider comparison are not claimed;
the Windows host's source tests and cross-platform type analysis do not prove
either. No additional live-provider trial or rollout is authorized by this
source correction. All broader Plan and Validation Plan outcomes stay open
under their existing owners.
