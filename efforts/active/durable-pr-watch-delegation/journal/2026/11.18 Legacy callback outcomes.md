## Source behavior

The existing delivery owner no longer silently discards legacy callback return
outcomes and exceptions. Its existing daemon status response adds optional
`legacy_callback_history`, with returned protocol
`legacy_callback_history/v1`. It records the latest 128 finished local attempts
in completion order and counts evictions. Repository and subscriber display
identities are capped with explicit truncation; registration identity stays
exact. It copies neither callback argv/output nor exception diagnostics.

Zero return is `completed`, not acknowledgement; a nonzero return is `failed`.
Timeout, exception and absent/non-integer result remain `unknown` with bounded
reason codes. These results do not prove absence of downstream effects.
History is process-local, resets on owner restart and is not a durable delivery
receipt. Missing/empty/evicted history is not proof of success or nonexecution.

Legacy registration/stdin and one-attempt best-effort scheduling are unchanged.
Acknowledged immutable pending events, persistence-before-attempt, bounded
backoff, ACK and replay retain their existing owner. No new request fields,
saved-state schema, installer or downgrade restriction is introduced. Old
status readers may ignore the additive diagnostic; new readers discover its
optional protocol from the actual running owner's response.

The changed Python files now carry complete annotations required by the
whole-file strict ratchet, including existing test fixtures. Dynamic JSON and
fixture keyword boundaries remain explicit; no typing exemption or project
admission change was added.
