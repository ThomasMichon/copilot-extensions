# 2026-11-07 - Worker decline claim settlement

## Outcome

A Dispatch-allocated worker can now decline its assigned task in the isolated
whole-stack lab. The real worker CLI reaches the decline boundary after the
actual allocator claims the task. The task returns to QUEUED with no bound
agent, the unassignment is recorded once, the reservation settles, and the
workspace's relationship to the task is closed by its existing owner. Only the
session's own claim remains on the workspace roster.

## Defects fixed

- Decline finalized the workspace before Dispatch confirmed the unassignment.
  The workspace's own claim on the task then blocked finalization forever.
  Decline now commits the requeue first, settles only the exact claim, and
  only then runs normal finalization. Unrelated obligations still refuse.
- Closeout and settlement replay the workspace owner through serialized local
  subprocesses, which could outlast the default read timeout. Only those two
  requests extend their read phase.
- The supervisor's closeout and the worker's settlement could reconcile the
  same claim concurrently, and the loser reported the claim as retained.
  Settlement is now serialized per claim and re-reads after a failed attempt.
- Relationship write and close refusals now retain the owner's bounded reason
  (refused, unroutable, absent, launch failure or nonzero exit) instead of a
  generic "unconfirmed" result.

## Lab fidelity finding

The retained refusal reason exposed the lab's own gap: the workspace owner
discovers claim providers only through enabled marketplace copies under the
user's Copilot plugin directory. A host provisioned only through each plugin's
native installer has no such copies, so no provider is registered for the
task namespace and the close is correctly refused. The lab now seeds the
marketplace copies and settings before native provisioning, matching real
installs. Whether native-only hosts should discover providers is a separate
question and is not changed here.

## Review hardening

Review of [#11486](https://github.com/ThomasMichon/copilot-extensions/pull/11486)
(merged as `2a38d6cd30`) added three refusals: settlement is admitted and
tracked by coordinator drain, a governed task pinned to a worktree refuses
decline instead of requeueing with an unsettled claim, and the worker refuses
before posting a decline while another allocation's claim is still unsettled.

A follow-up makes the worker's disposition wait tolerate lost reads. A
transport failure, server error or invalid response while waiting for the
requeue is an unconfirmed observation, not a refusal: polling continues until
the existing deadline, then records the blocker with the last failure and
retains custody for a rerun. Confirmed client errors still stop immediately.

A further follow-up for
[#11490](https://github.com/ThomasMichon/copilot-extensions/issues/11490)
recovers a decline after a replacement placement has replaced the current
assignment. A rerun whose task is no longer claimed at its generation reads a
new read-only recovery route that returns the exact original binding and
workspace only behind its committed closeout receipt, then settles and
finalizes that binding without a second decision or requeue. Replacement
placement itself still requires the original claim settled first, so the
recovered case is a committed settlement whose reply or finalization was lost.
Synthetic coverage: rerun twice after replacement placement converges with an
unchanged task, and other native, generation or worker identities find nothing.

## Limits

This qualifies bounded decline in a synthetic lab only. Permanent
finalization, real-model/forge use, mixed callers and production cohort
admission remain open, and both parent efforts remain Active.
