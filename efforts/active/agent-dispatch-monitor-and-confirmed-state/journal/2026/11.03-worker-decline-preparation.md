# Worker decline preparation

Coordination: [#9709](https://github.com/ThomasMichon/copilot-extensions/issues/9709).
Parent: [monitor and confirmed-state effort](../../README.md).
Contract: [worker decline preparation](../../../../../plugins/agent-dispatch/docs/pool-worker-decline.md).

## Source boundary

The current native worker can explicitly decline its allocator-owned claim,
retaining exact generation, reservation/startup revision, scoped exclusions
and explanation before workspace closeout. The decision is separate from
startup failure, worker acceptance and legacy yield. A failed closeout can
record an exact-worker blocker without changing routing or freeing capacity.

Existing start, startup supervision/retry/exhaustion and reservation
release/retirement boundaries preserve this pending claim. Identical current
replay does not renew clocks or alter its immutable decision. Explicit
terminal task disposition preserves historical evidence without wedging
normal retirement. Retirement implementation moved mechanically to the
existing release mixin to keep the changed modules within their source cap.

This closes part of the existing
[pool-owned lifecycle intent](../../../../../visions/plugins/agent-dispatch/README.md#pool-owned-assignment-startup)
and follows the provider-first
[service contract pattern](../../../../../docs/patterns/service-contract-evolution.md).
It adds no timer, independent assignment owner or automatic caller migration.
