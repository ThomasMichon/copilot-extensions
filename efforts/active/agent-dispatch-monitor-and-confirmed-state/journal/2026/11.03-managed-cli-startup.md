# Managed CLI allocator and first-prompt integration

The next #9709 source slice closes the managed CLI caller gap without relabeling
CLI workers as ordinary ACP or inventing a second allocator. Existing
supervision selects its actual per-label backend, places a `cli` assignment,
refreshes the allocator's current generation and records its owned workspace
before acquisition. The first prompt evaluates that claim and requests
affirmative `start --pool-generation`; Bridge supplies the actual native
identity. Legacy unprojected CLI startup keeps its evaluation-claim prompt.
Script and restricted backends remain outside the qualified caller.

Managed CLI launch requires the executing coordinator's explicit start support
before placement and again before acquisition. Unbound explicit placement retains
its older provider compatibility. A missing capability, changed driver,
generation, hold or launch instance retains the original claim instead of
launching through a fallback. Workspace preparation remains with its existing
owner; the extracted composition preserves legacy provenance and pairing.

Contained allocator, placement-client, acquisition and supervisor controls pass
432 tests. This includes actual API claim/start transitions and constructed
acquisition requests, not a real CLI launch. The first test run caught an
over-broad compatibility change: enforcing explicit start on every direct
placement would reject a previously supported provider. Enforcement now lives
only in instance-bound CLI placement, preserving that existing compatibility test.
Ruff and the 13-plugin install-contract gate pass.
An additional 172 ordinary startup, invocation, retry and deferral tests pass.

No publication/allocation seam or installed runtime was changed by these source
tests. Remaining work includes complete configured-definition adoption, actual
allocator-before-spawn and CLI/mixed-native acceptance, structured decline with
owned closeout, bounded affirmative suspended recovery, finalize-before-submit,
and whole-workload continuity. Both source and operational completion gates
remain open.
