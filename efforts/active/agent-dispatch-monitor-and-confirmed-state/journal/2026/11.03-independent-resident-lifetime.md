# Independent native lifetime for shared Linux residents

Consumer adoption exposed a concrete lifecycle prerequisite: a POSIX session
does not escape its launching systemd unit's cleanup cgroup. Restarting a
supervisor can therefore terminate unrelated residents that it lazily started.
The bounded shared repair is tracked in
[#10231](https://github.com/ThomasMichon/copilot-extensions/issues/10231).

The existing `agent-procutil.spawn_daemon` owner now uses an independent
transient user scope for durable Linux launches originating in a systemd
cleanup unit. Scope admission precedes execution and preserves the launch PID,
literal argv, environment, cwd, logs and instance receipt. Unsupported native
admission does not silently inherit the caller's lifetime. Existing Windows,
non-systemd POSIX, explicit non-breakaway and contained-test paths remain.
No persistent unit, restart policy or competing daemon manager is introduced.
This closes the platform-native-lifecycle intent through the existing
service-lifecycle-supervision pattern.

The contained shared-launch selectors pass **139** cases. Actual MCP lazy-start
and cutover callers pass **64**; monitor launch/cutover callers pass **109**.
The standalone Bridge bundle selectors pass **4**, after correcting its
incomplete current helper closure rather than dismissing that failure.
The admitted actor-free packet passes **3,870** controls, including fourteen
mapped source controls for scope selection and compatibility.
All bounded runs report verified cleanup.

Two separate finite native fixtures prove the actual lifetime distinction:
retiring the caller unit kills its bounded control, while the same resident
continues ticking in its own scope. Literal values survive and the renewable
test-instance owner settles exact cleanup afterward. Contained tests do not
escape their runner for this proof.

These are source and isolated native results, pending review and merge.

The first current-head review of #10234 found four genuine compatibility
defects: the real POSIX containment fixture also ran on Windows, relative PATH
lookup could probe and launch different binaries, probe timeout did not enter
MCP's existing direct-bridge fallback, and the native fixture unconditionally
used a flag absent before systemd 254. The same-PR correction limits the real
fixture to POSIX, shares absolute cwd-bound native-runner resolution, converts
probe timeout to an admission refusal and gates the fixture flag too.
The source CI also caught the unregenerated caller-lifetime archive; its owning
generator now refreshes all fourteen affected copies, with synchronization
verified rather than bypassed.

Corrected shared controls pass **141** cases; the full actor-free packet passes
**3,873**, including sixteen mapped scope controls. The corrected native fixture
again proves independent survival and settled cleanup. These corrections are
pending current-head review and CI; no incumbent resident migration is claimed.
