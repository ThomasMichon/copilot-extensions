## Source integration

The actual coordinator's whole `RegistrarSources` now composes with existing
liveness-GC iterations; each existing singleton master separately publishes
its complete effective machine/environment definitions. No host-local master
becomes a competing whole-cohort writer. `AGENT_DISPATCH_POOL_PUBLICATION=1`
selects both owners, with the default remaining off. The source composition
reuses the existing active-route/drain, pointer-lock, original-request,
singleton, read-future and shutdown owners. It adds no daemon, timer, executor,
queue, lease or identity registry.

The coordinator retains one actual projection through caller timeout or
cancellation and counts its real lifetime in the existing drain gate.
Preparation and final write admission retain the actual source/queue targets.
Known no-effect refusal permits a later fresh attempt; possible accepted
effects recover their original history first. The master shares one reconcile
deadline across preparation, source reads, sending and safe discard, refuses
fresh sends after exhaustion, and bounds source-lock contention behind a
still-running sender.

This closes part of the vision's
[pool-owned assignment/startup](../../../../../visions/plugins/agent-dispatch/README.md#pool-owned-assignment-startup)
source delta. It follows existing-owner supervision, graceful drain,
bounded-call and version-skew patterns. No wire field or CLI flag is added;
existing running-peer metadata negotiation still precedes transport writes.
Old or rolled-back unsupported providers withhold this feature without
inventing a legacy write fallback. Default-off construction retains prior
behavior.
