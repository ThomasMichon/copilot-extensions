# Local coordinator-owned decline closeout

The local source boundary extends the existing worker-decline preparation and
own-worker finalization providers. It closes part of the assignment/startup
amendment's atomic decline routing/requeue work, not the complete ordinary,
remote or installed/native lifecycle matrix.

Worktrees exposes explicit read-only closeout discovery and observation through
its selected runtime's existing `record` command. The reader locks and checks the
exact project/worktree incarnation, complete Dispatch allocation, native head
and preservation state, then compares the actual clean checkout with its
finalization snapshot. The observer never finalizes a foreign workspace and does
not require the observer process to impersonate the worker.

The coordinator's control-only closeout route accepts the original decline
binding, never worker-supplied finalized JSON. It derives the local host,
project and path from its retained reservation and performs bounded owner reads
outside SQLite. An unchanged final transaction applies the original exclusions,
queues the next task generation, advances task-wide cooldown without erasing
history or a later due time, and releases only the logical pool assignment.
Native capacity stays accountable in `RELEASING` until normal retirement.
Exact historical replay neither probes again nor announces a later task as
queued. Optional finalized workspace carry is suppressed after retirement;
explicit/required targets are not silently unpinned.

## Validation

- 453 Dispatch controls pass across decline, placement, startup policy,
  coordinator transport, supervision, queue claiming, reservations and retries.
- 233 Worktrees controls pass across own-worker admission/finalization,
  observation and exact metadata reads, including a fresh selected-CLI
  discovery process and actual isolated Git checkout mutation after finalization.
- Both periodic container runs use the bounded test path and verify cleanup.
  Native source/host boundaries are substituted where needed; these are not
  installed/native qualification.
- Touched Python lint, changed-module ceilings, install-contract and
  documentation consistency checks pass. Currently admitted strict typing
  scopes pass on Linux and win32; neither changed plugin is wholly qualified.

The mixed-boundary controls cover old/missing/malformed observation support,
nonlocal or unknown host refusal, held/steered/replaced claims, mutation during
the owner read, concurrent closeout, unchanged replay, retained capacity,
fake-clock catalog renewal after cooldown, new pool selection and preservation
of explicit workspace constraints.

## Remaining work

This is provider-first local integration. Ordinary worker client/CLI/prompts
and supervisor closeout invocation, selected remote-host transport,
no-managed-worktree applicability, complete configured-cohort qualification,
suspended recovery, finalize-before-submission and the parent validation gates
remain open. No installed runtime is updated or lane activated by this source.
