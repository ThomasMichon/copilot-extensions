## Boundary

The existing task-detail snapshot now includes its durable queue identity and
an audited assignment event. An optional query selects the original assignment
instead of substituting the latest worker. Both facts share the task's current
SQLite disposition snapshot; an indexed lookup avoids reading the full history.
Only the direct worker-claim audit qualifies this event form. An allocator's
pool-placement actor does not establish the later worktree assignment; its
original workspace-binding integration remains open.

The existing explicit local/central claim callbacks understand Worktrees'
canonical bound retained-relationship encoding. The original queue, task,
assignment event and worker must match. Only completed responsibility, or
current unbound queued work with a later same-worker unassignment, produces
exact retirement proof. Missing tasks, unsupported providers, wrong queues,
changed workers, submission and other lifecycle states retain the obligation.
The callback does not start a service or fail over to another writer.

The [provider reference](../../../../../plugins/agent-dispatch/docs/task-obligations.md)
owns the wire shape and compatibility details. No task state, completion policy,
ordinary assignment caller, native lifetime or Worktrees claim mutation changes.
The existing Worktrees claim ledger remains the intended owner; this adds no
parallel responsibility ledger or dispatch-attempt field.
