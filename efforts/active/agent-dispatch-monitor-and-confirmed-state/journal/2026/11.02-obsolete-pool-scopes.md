# Obsolete configured pool scopes

The existing catalog snapshot now derives its required scopes from the whole
complete configured-cohort observation. It retains every enrolled scope and
its original definitions, generation, revision and expiry, while top-level
candidate definitions and readiness checks exclude obsolete scopes.
Missing or invalid current members still block the complete catalog. Explicit
empty intent yields no candidates; uncertain observations and legacy
unprojected catalogs preserve their existing conservative behavior.

This is source-owned exclusion, not execution retirement. No original scope,
generation, history, task assignment, reservation or native/effect binding is
deleted or reset. Already-assigned workers retain their original claim/start
path. Retry selection remains pinned to their pool, and accountable capacity
and exclusive keys remain held across removal and re-addition. Re-addition
requires publication against the new cohort revision. Accepted original-result
replay does not renew freshness or reintroduce a removed candidate.

Contained source validation covers the real SQLite, HTTP response/readers and
placement owners: current missing/unavailable members; obsolete pending,
unavailable and expired publications; exact execution environment identity;
explicit empty intent; unchanged original tables; stale/unfenced publisher
refusal; generation succession; accepted replay; retained native acceptance,
retry/capacity/exclusive custody; and concurrent withdrawal versus placement.
The six affected selectors passed together with 334 tests, including the new
withdrawal controls. Focused source typing, lint, documentation consistency and
the install contract passed.

No new schema, scope registry, route, RPC prerequisite, timer or executor is
introduced. Old providers may retain their conservative obsolete-scope blocker;
callers must preserve that refusal rather than fall back to legacy spawning.
Ordinary publication/allocator/initial-prompt and mixed-driver migration remain
open, the cadence stays default-off, and this does not establish installed or
native qualification. Review and merge are still required for this source
slice.
