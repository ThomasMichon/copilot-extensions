# Managed ordinary allocator instance integration

This source slice connects the existing ordinary supervisor caller to the
globally selected registration/machine/environment instance. It advances
[#9709](https://github.com/ThomasMichon/copilot-extensions/issues/9709), not the
entire parent completion gate.

## Source boundary

The existing master passes explicit instance custody to its same-runtime child.
The ordinary caller negotiates additive placement and reservation-query support
against the running coordinator. Global selection remains transactional; the
caller cannot filter candidates down to its preferred instance. Another
instance's win refuses before claim/reservation insertion. Active replay is not
fresh launch permission. Immutable reservation bindings scope lifecycle queries
before limits while retaining unbound legacy/manual behavior.

Preparation reads back the original placement and current claimed generation
before constructing the existing ordinary seed. Wrong host, owner, driver,
generation, hold or missing read-back retains custody rather than creating or
resending. Configured ordinary capacity and retry admission remain provider-owned;
the independently admitted CI-repair path retains its legacy failed-spawn budget.

Automatic allocation has a separate default-off opt-in. Disabling it preserves
instance-scoped reconciliation; it does not erase retained assignments or
reenable a fenced legacy admission path. The
[runtime reference](../../../../../plugins/agent-dispatch/docs/pool-claim-start.md#managed-ordinary-allocator-opt-in)
owns flags, protocol details, compatibility and unsupported-driver behavior.

This closes part of the existing
[Dispatch vision](../../../../../visions/plugins/agent-dispatch/README.md):
pool-owned placement before attachment, independent instance capacity and
visible waiting. It reuses the established single-writer reservation owner and
version-skew-safe contract pattern; no registry, schema, scheduler or executor
is added.

## First review corrections

The current-head review identified three concrete gaps, corrected on the same
source slice:

- Restricted interrupted-start recovery retains its backend-owned claimed-task
  checks; ordinary pool preparation no longer rejects that legitimate claim.
- An unprojected cycle never upgrades to pool placement after a concurrent
  projection. Passing instance authority requires the already-negotiated
  configured mode and enabled allocation; the existing transactional legacy
  fence handles projection races.
- A versioned data-authorized health observation positively identifies an
  unprojected queue without requiring a configured control token. Configured,
  unknown or malformed observations remain fail-closed.

The corrected affected run passes 457 cases across five selectors, including
actual managed restricted recovery, default control-token-free supervision,
mid-cycle projection with allocation on/off, and unknown/configured refusal.
Cleanup is verified. The restricted HTTP fixture now preserves real response
headers so capability checks exercise the provider rather than a lossy adapter.
This run overlaps the earlier evidence; it is not added to that total.
