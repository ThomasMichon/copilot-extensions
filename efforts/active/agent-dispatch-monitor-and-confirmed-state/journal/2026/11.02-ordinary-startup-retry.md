## Source boundary

The existing pool startup retry/complete transaction can retain an ordinary
ACP Bridge ID alongside the distinct native UUID, original assignment,
generation, revision, machine, workspace and allocator. CLI callers keep their
original wire form and exact-live transport. Ordinary callers additionally
negotiate `ordinary_same_native_retry` and the advertised driver before effects.
No new schema, retry registry, executor, timer or service is introduced.

Existing supervision observes ordinary full session identity on the recorded
machine and uses Bridge's native-bound ordinary send/receipt operation. It
does not substitute the live-CLI inbox or issue another evaluation claim.
Unknown original effects permit receipt observation only, never blind replay.
Three completed failed/rejected attempts or the persisted startup/decision
deadline fence the claim back to `QUEUED` while retaining `RELEASING` capacity.
Only affirmative worker start resets counters.

Late original retry receipt completion is independent of task acceptance,
submission/completion and exhausted-generation cooldown. It preserves those
outcomes and the original `local-body` handle without freeing native capacity.
Busy-turn rejection is a startup outcome, not a worker's semantic decline.
