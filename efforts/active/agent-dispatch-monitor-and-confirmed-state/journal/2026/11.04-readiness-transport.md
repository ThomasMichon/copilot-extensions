## Separate provider contract

The existing Worktrees record owner exposes the nonfinalizing observer through
a distinct `agent-worktrees.dispatch-worker-readiness` version-1 contract.
Independent observation and own-native/cwd observation retain the exact task
claim and active workspace. Neither existing finalized-closeout descriptor nor
ordinary record metadata changes meaning. Strict complete requests bind the
worktree, allocation, native session, creation nonce, head revision and original
task responsibility. Partial/mixed requests refuse before observation.

The [provider reference](../../../../../plugins/agent-worktrees/docs/dispatch-worker-closeout.md#selected-runtime-readiness-transport)
owns the invocation and compatibility contract. This closes a bounded provider
prerequisite toward
[submission-retains-worktree-responsibility](../../../../../visions/plugins/agent-dispatch/task-outputs-and-review/README.md#submission-retains-worktree-responsibility).
It follows the existing
[service-contract evolution](../../../../../docs/patterns/service-contract-evolution.md)
pattern: expand the selected executing provider before migrating callers.
There is no equivalent legacy-finalization fallback and no retired old syntax.

## Validation and remaining work

The bounded container packet passes 312 controls across readiness, existing
closeout and exact record reads, with cleanup verified. The real parser reaches
the actual observer for both operations, and a fresh selected Python process
describes the separate readiness contract without worker-cwd dependence.
Changed native/head, dirty checkout and wrong retained claim refuse without
changing responsibility. Discovery, partial/mixed forms, invalid operations,
unknown flags and unchanged legacy descriptors retain their distinct behavior.

Independent review identified unnormalized Git and subprocess probe exceptions
at the record boundary. These now return the existing structured refusal instead
of escaping without JSON. Four regressions exercise both exception classes at
checkout snapshot and ref probes, retaining the task claim and releasing the
observation lock. The initial assertions omitted the existing JSON envelope
version; they were corrected without changing the output contract. The corrected
packet passes 316 controls with bounded cleanup verified.

Ordinary consumers are not changed. Conditional worker/coordinator negotiation,
independent observation outside SQLite write transactions, locked proposal and
task-state rechecks, manual/absent-worktree applicability, same-native post-stop
rejection and non-circular decline remain open. Participating-writer/cohort and
installed/native qualification remain separate. No runtime is updated or
restarted, and ordinary assignment claim admission stays disabled.
