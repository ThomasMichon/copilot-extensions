## Existing owners, one retained request

The direct claim transaction retains its original workspace, queue, worker,
generation and request on the actual assignment audit event. Allocator
placement retains the requirement on its original reservation without inventing
a worktree. Actual workspace attachment records the creation nonce and actual
worker assignment before protection can be acknowledged. The allocator's
placement actor is never substituted for that worker.

Worktrees reserves and binds the outbound task relationship through its existing
claim ledger, with the original expected creation nonce. Dispatch checks the
ground-owner response, then rechecks its assignment before publishing success.
Interrupted writes retain the same request for reconciliation. Pending
protection blocks execution, including a queue reopened without its writer.
Retained SQLite guards prevent older queue code from forgetting the requirement.

Recovery version 2 extends the existing callback with the original assignment
event and worker, including pending subjects. Completed task responsibility or
confirmed unassignment to unbound queued work permits verified close.
Submission, abandonment, dead-letter status and runner/lease expiry do not.
Cancellation with an absent claim first replays the original reserve and closes
it, retaining a tombstone against a delayed in-flight reserve.

The creation parser preserves the nonce already present in Worktrees' original
output. Required workspace retries always revisit their owner even when stored
project/path facts match. Legacy reservations cannot adopt a new incarnation.
Source capability negotiation and control-authorized reconciliation remain on
the existing coordinator; no second task or obligation ledger is introduced.
The [provider reference](../../../../../plugins/agent-dispatch/docs/task-obligations.md)
owns the detailed wire and compatibility contract.
