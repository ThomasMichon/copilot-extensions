# POSIX retained-owner construction

Back to the [active effort](../../README.md).

Running correlation qualification exposed a provider-construction prerequisite:
the actual Bridge CLI and daemon declared session-origin support, but the
selected POSIX installed slot had no immutable retention bootstrap. Dispatch
correctly retained its baseline transport rather than pretending it could pin
that provider. Current labels cannot supply missing session birth evidence.

The shared attached-construction shell adapter now has an explicit
`--retain-helpers` completion option. Fresh Bridge shell construction selects it
before publishing completion, matching the existing PowerShell selection.
Unchanged callers keep their previous behavior. Historical completed Bridge
slots are reused without bootstrap backfill or changed completion identity.
No new HTTP/CLI service contract, automatic enrollment or runtime rollout is
introduced.

The native POSIX regression extracts the actual installer boundaries, builds a
real environment, completes it through the real construction owner, invokes its
identity-pinned retained launcher, then verifies unchanged identity on reuse.
Together with existing completed-slot admission controls, the corrected isolated
selection passed 66 cases; 46 platform-specific cases were skipped, not qualified.
The first selection exposed historical-slot reuse refusal; preserving that
baseline corrected the regression instead of changing its expected outcome.

This closes a source prerequisite, not this effort's running correlation,
recovery-state or installed-cohort acceptance. Managed producer enrollment and
fresh full owner-join qualification remain separate.
