## Retirement versus execution admission

The independent-process test in
[`test_task_relevance_concurrency.py`](../../../../../plugins/agent-dispatch/tests/test_task_relevance_concurrency.py)
races the real queue's relevance transaction against both `claim_one` and
`reserve_spawn`, using separate Python processes and one SQLite database.
If retirement wins, the task is abandoned without an accepted claim or
reservation. If claim wins, the stale report fails its revision fence.
If reservation wins, the report records closeout responsibility rather
than treating the task as resource-free.

Reservation admission must precede workspace/native preparation. The
corresponding queue controls in
[`test_task_relevance.py`](../../../../../plugins/agent-dispatch/tests/test_task_relevance.py)
also retain pending preparation and historical assignment custody. These
controls establish the source transaction's ordering; they do not prove
every installed driver or production cohort has adopted that admission.

## Stale observations and unrelated source state

The same queue controls reject a foreign repo/source/origin scope and a
stale task revision or generation under the acceptance lock. A newer
`needed` or `unknown` report invalidates an older closure observation
without changing the task. Reopening does not silently clear an already
accepted original-owner closeout.

The actual HTTP/emitter composition in
[`test_emitter_relevance.py`](../../../../../plugins/agent-dispatch/tests/test_emitter_relevance.py)
changes claim state, registration or source observation while the source
check is running. The stale report cannot abandon the task. Timeout,
command failure, malformed output, missing/duplicate observations and a
foreign task observation produce no report POST. An empty open-object
listing alone is not closure evidence.

The actual registrar-source controls in
[`test_task_relevance_sources.py`](../../../../../plugins/agent-dispatch/tests/test_task_relevance_sources.py)
additionally refuse superseded, ambiguous or incomplete source declarations,
without relying on eventually mirrored registration rows.

## Validation and remaining work

This is a documentation-only reconciliation of existing reviewed source
controls, not a new test execution or native result. The linked test modules
define the reproducible assertions under the repository's existing test
runners. Documentation consistency and link checks cover this update.

The remaining unchecked items retain their original scope: owner recovery
and requeue, full cohort attribution, closeout acknowledgement/lifecycle,
receiver publication and rollback qualification, busy/suspended/unavailable
owner coverage, restart/lost-response composition, actual native/workspace
outcomes and compatibility. No production task is retired, no writer or pool
is enabled, and no deployment is implied.
