# Managed command-emitter grant carrier

Back to the [active effort](../../README.md).

## Source integration

Periodic enrollment requires the coordinator's original managed creation
ledger, not a task's caller-supplied source fields. Command emitters now have an
opt-in authoring seam that reads an existing owner-supplied grant after the
domain command finishes. Discovery output stays credential-free.

The carrier uses the existing producer-status, exact dedup lookup and
managed-create HTTP operations. It refuses mismatched emitter/repository/source
or retired generations. A matching live fenced dedup occupant is observed
without changing or replaying its original creation request when discovery
advances. A new task requires the domain's stable occurrence request id.
Grant issuance, storage and production enrollment remain with their current
owners. No new daemon or RPC is introduced.

This closes a source-adoption prerequisite for the existing periodic caller,
not the aggregate rollout, cohort or closeout gates. The
[carrier guide](../../../../../plugins/agent-dispatch/docs/managed-command-emitters.md)
records default-preserving behavior and the rollback refusal.

## Bounded validation

The isolated current-HTTP and baseline emitter selection passed 67 tests,
including real managed creation/receipt inspection, observation of a changed
candidate without another POST, terminal release followed by a new occurrence,
foreign/stale grant and dedup refusal, prior exact-lookup refusal, resolver
diagnostic secrecy, and both periodic-tick and registered side-load wiring.
Named grant-resource resolution and shape-validation errors are redacted before
any command or HTTP write; actual missing-path controls retain that guarantee.
Ruff and the install-contract guard passed; documentation consistency passed.

The source packet does not qualify a production source adapter, native grant
resolver, installed supervisor generation or any new running enrollment.
Those remain separate from this source result.

## Supplier relocation

The grant reader's executable/script operands now use the same supplier
qualification owner as discovery, side-load and relevance commands. Persisted
declarations retain named repository resources rather than an absolute path
into the former supplier checkout. Real filesystem relocation controls cover
both direct executable and interpreter-script forms, preserving literal data
arguments and resolving the current registered root at execution.

The expanded emitter/supplier/path-origin packet passes 140 tests. Its first
run exposes a missing fixture prerequisite in the existing headless-supplier
case: hosting admission now resolves the selected execution harness through
Worktrees. That case supplies the fixture metadata receiver and asserts the
registered-only query targets the execution harness, while retaining the real
repository hosting-policy check. No production admission is bypassed.

## Worker dependency validation

Worker Save and activation now validate the managed grant reader's executable
and script through the existing dependency owner before persistence. They do
not execute the reader, and refusal diagnostics omit reader arguments and
local paths. Controls exercise missing executable/script for both Save modes
and an available script that must remain unexecuted during activation.
The expanded emitter, supplier, path-origin and worker-instance packet passes
241 tests with one existing optional skip. This closes the configuration
validation gap, not production grant enrollment or the aggregate effort.
