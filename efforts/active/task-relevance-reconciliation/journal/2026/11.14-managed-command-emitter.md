# Managed command-emitter grant carrier

Back to the [active effort](../../README.md).

## Source integration

Periodic enrollment requires the coordinator's original managed creation
ledger, not a task's caller-supplied source fields. Command emitters now have an
opt-in authoring seam that reads an existing owner-supplied grant after the
domain command finishes. Discovery output stays credential-free.

The carrier uses the existing producer-status, exact dedup lookup and
managed-create HTTP operations. It refuses mismatched emitter/repository/source
or retired generations. A matching live fenced dedup occupant is observed
without changing or replaying its original creation request when discovery
advances. A new task requires the domain's stable occurrence request id.
Grant issuance, storage and production enrollment remain with their current
owners. No new daemon or RPC is introduced.

This closes a source-adoption prerequisite for the existing periodic caller,
not the aggregate rollout, cohort or closeout gates. The
[carrier guide](../../../../../plugins/agent-dispatch/docs/managed-command-emitters.md)
records default-preserving behavior and the rollback refusal.

## Bounded validation

The isolated current-HTTP and baseline emitter selection passed 65 tests,
including real managed creation/receipt inspection, observation of a changed
candidate without another POST, terminal release followed by a new occurrence,
foreign/stale grant and dedup refusal, prior exact-lookup refusal, resolver
diagnostic secrecy, and both periodic-tick and registered side-load wiring.
Ruff and the install-contract guard passed; documentation consistency passed.

The source packet does not qualify a production source adapter, native grant
resolver, installed supervisor generation or any new running enrollment.
Those remain separate from this source result.
