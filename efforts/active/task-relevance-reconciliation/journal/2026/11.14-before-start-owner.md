# Original pool-body closeout before affirmative start

Back to the [effort](../../README.md).

## Reproduced boundary

A source can close after its allocator has created a protected workspace and
native body but before the worker accepts the goal. The queue retains the
CLAIMED task, reservation and bound relationship, and its original-goal fence
correctly prevents a later start. Previously, closeout captured only the task's
accepted owner fields. Those fields were still empty, so even a body satisfying
the existing pool-start identity checks received no closeout wake.

The regression uses supported placement, workspace binding and native recording,
without calling start. It first proves that the existing pool-start check
recognizes the original worker/native, then fails on the absent closeout target.
This is not evidence that an arbitrary historical or incomplete body is known.

## Bounded correction

For an unaccepted allocator claim, capture a closeout target only from its
current unreleased, unexhausted pool assignment and a created, SPAWNED original
body with completed startup. Reuse the existing pool-start workspace/native
checks and the protected relationship's original resource references. Missing,
fenced, released, retired, cooling, concluded or conflicting evidence stays
explicitly unconfirmed.

The captured binding adds `owner_phase: before_start`. That names the closeout
recipient, not an accepted task owner: raw task owner/native fields, attachment
history, generation and CLAIMED state are not fabricated or rewritten.
Acceptance records the existing durable steer and one linked original-body
wake. Delivery and the scoped worker HTTP routes retain their normal native,
reservation, token, authority and unknown-send checks.

The original worker can settle its exact claim through independent readiness,
finalize through its existing workspace owner, and acknowledge abandonment
without ever starting the obsolete goal. The terminal transition has a narrow
internal exception for that independently guarded acknowledgement. An ordinary
worker transition on an unaccepted allocator claim remains refused; the change
does not make the worker the task's accepted owner.

This closes an existing task-relevance vision gap, not new intent. It adds no
command, request field, public mutation route, daemon, cleanup authority or
second owner registry. Target capture performs task/reservation/worktree-scoped
queue reads once at new obsolete-closeout acceptance. It adds no subprocess,
network call, fleet scan or periodic recapture.

## Validation and remaining gates

Focused source controls exercise original-body capture without start, linked
wake admission, claim readiness, guarded acknowledgement and terminal replay.
A real coordinator HTTP fixture accepts the original scoped token for only
the closeout routes while generic task authority remains unavailable. Negative
controls retain incomplete, fenced, released, retired, cooling, targeted,
exhausted and generation-mismatched bodies; later holds, native retirement and
missing phase evidence refuse readiness.

The initial four-file regression selection exceeded its unchanged 60-second
sub-suite execution limit. Its anonymous progress is not a reusable named pass.
The narrowed original-body and existing captured/legacy-owner selection passes
20 cases with eight unrelated cases deselected, under the same execution and
resource bounds. No time, resource or effect allowance was increased. A test
that attempted to rewrite an immutable workspace nonce was removed after the
existing database trigger correctly refused the attempted setup; that trigger
was not weakened.

Thirteen separately selected existing readiness, liveness and acknowledgement
controls also pass, including the strengthened refusal of an ordinary worker's
abandonment before acceptance. A further five-case selection runs the governed
ordinary creation/delivery composition through original-body closeout targeting,
then verifies the original Bridge/native wake selection alongside existing
ordinary and suspended-owner delivery. Its external send is substituted; it is
not actual native delivery. These selections overlap and are not additive
coverage totals.

Changed-source lint, the runtime installation contract, release metadata and
documentation consistency pass. The admitted strict typing portfolio passes on
both analysis targets; Dispatch remains outside that admitted portfolio.
The existing actor-free unit source/node/coverage closure is unchanged. No
SQLite, process or native case is added to required unit-only CI.

These are contained source/HTTP controls with synthetic external observations,
not actual native finalization or production adoption. Native wake, full
workspace/session conclusion, source closure during incomplete startup,
uncaptured legacy bodies, reuse/reassignment and broader recovery remain open.
Older receivers may retain this additive target but cannot be assumed capable
of acting on a before-start closeout; preserve its original request and pending
custody rather than replaying the goal, dropping metadata or substituting a
worker after rollback. Independent review, required checks and actual running
qualification remain separate.
