## Hosted lifetime implementation

The actual service lifespan awaits `TaskRunner.stop()` before releasing its
daemon admission. The runner settles its native ownership transitions, but
leaves detached workers alive for adoption; its drain always returns clean
because it assumes no in-process indexing exists. The service drain endpoint
combines that result with read draining. Those guarantees cannot be reused
for an effects-running point thread.

The next additive boundary is an explicit Python `PointWorkerHost` async
context, with one active dispatch and caller-owned connector/client lifetime.
Cancellation of run, stop or context exit joins the original synchronous
dispatch before unwinding. A timed-out or cancelled drain observer never
cancels the worker. Stop closes admission permanently; a successful drain can
be rolled back with resume. The owner performs no queue transitions itself.

This closes a specific lifetime prerequisite, not service integration:
TaskRunner's legacy scheduling and drain remain unchanged. Actual configured
host selection, shared-queue coordination, ordinary v2 admission, detached
recovery and cutover wiring remain open. No execution capability is advertised
and no runtime rollout is performed.
