## Hosted lifetime implementation

The actual service lifespan awaits `TaskRunner.stop()` before releasing its
daemon admission. The runner settles its native ownership transitions, but
leaves detached workers alive for adoption; its drain always returns clean
because it assumes no in-process indexing exists. The service drain endpoint
combines that result with read draining. Those guarantees cannot be reused
for an effects-running point thread.

The next additive boundary is an explicit Python `PointWorkerHost` async
context, with one active dispatch and caller-owned connector/client lifetime.
Cancellation of run, stop or context exit joins the original synchronous
dispatch before unwinding. A timed-out or cancelled drain observer never
cancels the worker. Stop closes admission permanently; a successful drain can
be rolled back with resume. The owner performs no queue transitions itself.

This closes a specific lifetime prerequisite, not service integration:
TaskRunner's legacy scheduling and drain remain unchanged. Actual configured
host selection, shared-queue coordination, ordinary v2 admission, detached
recovery and cutover wiring remain open. No execution capability is advertised
and no runtime rollout is performed.

## Queue cancellation ownership

The queue/service trace found a concrete conflict before scheduling can be
composed: explicit point application owns the source writer while its row
remains parked, but generic cancellation previously treated every parked row
as idle. It could revoke the claim during native effects. The ordinary service
constructor still creates only the detached legacy runner, whose immediate
drain result is not an in-process lifetime guarantee.

The supported `TaskStore.cancel()` operation now uses the same source writer
for v2 work, refusing busy or same-thread reentrant cancellation without
changing queue state. An additive `allow_reentry=False` option preserves
ordinary nested writer behavior while preventing an executing callback from
revoking itself. Legacy queued cancellation keeps its existing path. Once
execution settles, a failed parked claim can still be cancelled and explicitly
retried with the same pin and retained named acquisition.

## Explicit queue consumer

The explicit `PointQueueConsumer` composes exact whole-scope FIFO selection
with the joined host. The caller schedules finite batches (one task by default)
and owns connector/client lifetime; the consumer creates no polling loop,
timer, child or resident task. Every instance starts paused. A nonzero dispatch
result, exception or cancellation pauses it until explicit resume, preventing a
failed parked pin from becoming an unbounded retry loop. Reconstructed
consumers also require explicit resume before using retained recovery.

Selection is read-only and excludes legacy/v1, other bindings and terminal
work. The worker's current-snapshot check, configured pinning, source writer
and durable completion remain authoritative. Selection runs off the event
loop, with admission checked again afterward: drain/stop during a blocked
read cannot admit late native effects. Active batch reentry and premature
resume refuse. Drain/stop retain the host's truthful joined-effect semantics,
without pretending an in-process thread is an adoptable detached process.
