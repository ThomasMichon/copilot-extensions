## Selected boundary

Issue [#13342](https://github.com/ThomasMichon/copilot-extensions/issues/13342)
covers unrecognized WIQL, PR-list and thread-list responses silently becoming
empty acquisitions. The explicit full collector derives deletion candidates
from returned entry paths, so an unknown response must not certify absence.

The connector distinguishes explicit arrays and documented serialized defaults
from unknown envelopes. WIQL's optional result collections use
`EmitDefaultValue=false`; its `QueryType` does not. A recognized query type can
therefore accompany omitted/null empty collections, while an unrecognized
object is refused. Collection-only query results and legacy bare PR/thread
arrays remain supported. Invalid collection records or selected query references
refuse acquisition without erasing parsed-record observations. Query union,
deduplication and provider ordering remain intact.

The two response parsers have a small dedicated module rather than growing the
connector past its source-module cap. This is a vision-closing correction to
the existing source-ingest contract, consistent with the patterns' right-sized
surface and explicit-failure principles; it adds no service, protocol or
configuration.

## Qualification and remaining gates

Before correction the focused regression had 15 failures and eight passing
controls, including uncontrolled null-collection handling. After correction,
the five Azure DevOps modules pass **103 tests** with verified cleanup.
The tests exercise the actual full collector with private SQLite path state,
require refusal instead of a deletion manifest, preserve unrelated source
paths and checkpoint state, retain valid empty/default shapes, and count parsed
records even when acquisition is refused.
Whole-file strict analysis passes all five changed Python files on the configured
Linux and Windows targets; native execution was Linux. High-signal Ruff,
formatting of the two new Python modules and the 13-plugin install contract pass.

This closes only the selected malformed-response boundary. It does not provide
immutable query membership, durable acquisition progress, budgeted resumable
full reconciliation, provider-complete field validation or consumer rollout.
The parent Plan and Validation Plan remain unresolved beyond this slice and
the effort remains Active.
