## Selected boundary

Issue [#13342](https://github.com/ThomasMichon/copilot-extensions/issues/13342)
covers unrecognized WIQL, PR-list and thread-list responses silently becoming
empty acquisitions. The explicit full collector derives deletion candidates
from returned entry paths, so an unknown response must not certify absence.

The connector distinguishes explicit arrays and documented serialized defaults
from unknown envelopes. WIQL's optional result collections use
`EmitDefaultValue=false`; its `QueryType` does not. A recognized query type can
therefore accompany omitted/null empty collections, while an unrecognized
object is refused. Collection-only query results and legacy bare PR/thread
arrays remain supported. Invalid collection records or selected query references
refuse acquisition without erasing parsed-record observations. Query union,
deduplication and provider ordering remain intact.

The two response parsers have a small dedicated module rather than growing the
connector past its source-module cap. This is a vision-closing correction to
the existing source-ingest contract, consistent with the patterns' right-sized
surface and explicit-failure principles; it adds no service, protocol or
configuration.

the effort remains Active.

## Documented PR offset-pagination qualification

The PR-list adapter now sends `$skip`/`$top` for every configured query rather
than depending on continuation headers. Offsets advance by raw response length;
only an explicit empty page terminates. A short server-capped page cannot
certify exhaustion. Filters remain query-local, with identity union/deduplication
across queries. A positive integer page size is validated before network acquisition.
Oversized pages and later nonempty pages adding no new query-selected identities
refuse rather than loop or certify a prefix. Each query buffers its selected
records until traversal completes, preserving the existing failure boundary.

Unconditional page requests avoid the validator-only cache's missing-body
problem. Unexpected 304s, later HTTP/JSON failures, invalid records and
cancellation cannot return a completed inventory. Parsed observations remain
visible before validation/deduplication. The documented wire API correction
does not change fresh description hydration, selected query metadata or
comment acquisition.

The new headerless regression selection reproduced **18 failures** before
correction. A further focused red control proved that treating a short page as
terminal loses records when the server caps its response below `$top`.
The final nine-module Azure DevOps, continuation, HTTP and accounting
selection passes **217 tests** with verified cleanup, covering short, exact and
empty listings; full-document and ID-only query unions; cancellation; repeated
and cyclic pages; oversized responses; and actual full-collector checkpoint and
foreign-path preservation on later failure. Strict whole-file checking passes
all seven changed Python files for configured Linux and Windows targets;
native execution is Linux only. High-signal Ruff, new-test formatting and the
13-plugin install contract pass.

This closes a provider-wire correctness gap under the existing good-citizen
ingestion vision and explicit-failure pattern. Mutable offsets still do not
give concurrent-edit stability, immutable membership, durable query progress,
bounded accumulated memory or resumable reconciliation. Both parent Phase 3
requirements and the broader Validation Plan remain open; no rollout is claimed.
