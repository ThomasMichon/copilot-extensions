## Selected correctness boundary

Issue [#13309](https://github.com/ThomasMichon/copilot-extensions/issues/13309)
tracks the unsupported assumption that PR creation/closure time is an update
watermark. The documented
[project listing API](https://learn.microsoft.com/en-us/rest/api/azure/devops/git/pull-requests/get-pull-requests-by-project?view=azure-devops-rest-7.1)
applies `minTime` to creation or closure, defaulting to creation. It cannot
certify later description or review-comment changes.

The selected minimal correction refuses a nonempty timestamp when PR queries
are configured, before work-item or PR acquisition. It removes the private PR
timestamp parameters and creation/closure post-filter rather than retaining
an apparently usable but incomplete update path. Explicit full discovery,
missing-marker legacy discovery, ID-only listing and work-item-only timestamp
discovery retain their existing query, identity and body/comment behavior.
No implicit full-history fallback or new deletion authority is introduced.

The ordinary legacy engine already persists this connector's null
`current_commit()` result. Its subsequent rounds therefore take full acquisition,
not the direct timestamp optimization. This correction does not make that
existing path delta-bounded or claim a newly observed ordinary-engine omission.
It closes a false-success contract, consistent with the agent-index vision's
complete, observable acquisition boundary.
