## Existing evidence and new control

The existing pending-crawl test exercises the deterministic revert failure
with substituted embedding/storage. The existing native ownership packet
separately covers actual process exclusion, queued contenders and crash
release. The new control joins durable alias state with an actual native
content/vector/path store and five separate contained worker processes.
It changes no runtime behavior or ownership mechanism.

Both aliases first complete revision A. One then completes B, storing a
temporary first file. C restores that file's A content and changes a second
file. Actual Git confirms the stale alias's net A..C omits the first path,
although B is still present in the shared store.

The stale alias refuses before provider acquisition. Reopened native owners
retain exact content/vector table versions, source-state bytes, path
checkpoints and raw stored vectors. An explicitly requested full operation
on this synthetic store restores C content, removes stale B vectors and
publishes C for the repaired alias and canonical family. The other alias's
B cursor is preserved, not silently copied forward.

Only inference is substituted; Git, queue admission, worker execution,
native storage and state publication are real. Engine startup and fetch
are disabled and every child traps HTTP sends. This is not a service/canary
operation, live repair, cursor reset, expiry or takeover.

## Validation and remaining gate

The final native control passes in 22.75 seconds, 30.49 seconds including
preparation and verified cleanup, under the existing 150-second plugin,
180-second outer and 3-GiB bounds. Ruff passes. Strict whole-file Python 3.10
checking passes the complete test and executed child helper for Linux and
win32; this is not native Windows execution.

Review caught two valid fixture defects: inherited Git overrides could redirect
operations despite `git -C`, and a late environment assignment did not override
the configuration class's import-time clustering default. Both Git and worker
launches now remove inherited `GIT_*` settings and ignore global/system Git
configuration. The case deliberately poisons repository, worktree, index and
configuration overrides with owned temporary targets and requires those targets
to remain absent. Explicit `cluster_enabled=False` is supplied to both
configuration constructions, and every actual worker must report zero
clustering attempts. The final execution and strict results above include
these corrections under unchanged resource limits.

The [testing guide](../../../../../TESTING.md) owns the explicit selector and
limits. The case stays in the existing T3 manual/periodic lane rather than
expanding required unit CI. It is vision-closing qualification of the
existing good-citizen checkpoint/recovery behavior, not a new protocol,
runtime layer or deployment requirement.

The receiving effort retains the complete source-ownership contract,
including surviving immutable workers, mixed-generation alternatives,
cutover/adoption/GC and independent operational/data owners. The canonical
incremental and consumer Plan/Validation Plans retain ten open items each.
No activation, ordinary caller migration, historical affected-data repair or
rollout occurs.
