## Application slice narrowed before delivery

The proposed explicit receiver was removed from PR #13421 rather than qualifying
only its happy path. A path-database ledger alone cannot prove retained deletion
history after ledger loss or a LanceDB-only backup restore. Projection evidence
also needs complete raw canonical metadata and duplicate-detecting vector reads,
including provenance, under prepared point indices and the configured model and
path-database owners. Existing row decoders and vector convenience lookups do not
provide those guarantees.

Preparation must pin its exact parent before any derived writes, perform
embedding outside store exclusion, then revalidate parent, checkpoints and
projections before publication. Known pre-writer preparation refusals must stay
retryable without being mistaken for interrupted native effects. These are
coupled application/recovery requirements, not additional checks that can be
claimed from the removed receiver's injected-failure tests.

The retained slice supplies pure content/version comparison, transactional
v8-to-legacy downgrade refusal and premature-completion refusal. The ordinary
application fences remain unchanged. The native receiver and its qualification
tests are not shipped; no applied-version table or application-attempt lifecycle
is introduced. Issue #13386 and the parent Plan/Validation Plan retain ordered
application, durable deletion/backup recovery, bounded complete projection reads,
model/path ownership, preparation races, crash reconciliation and read isolation.

The narrowed recovery/prepared selection passed 106 controls with nine existing
skips. All three pure ordering contracts, whole-file Python 3.10 Linux/Windows
strict checks, scoped Ruff F/E9 and runtime install contracts passed. The
required eligible-unit packet and aggregate checks remain independent merge
gates. No native ordered application or backup-restoration qualification is
claimed from these results.

The retained-parent downgrade check decodes caller-supplied expected bytes
before acquiring SQLite writer ownership and relies on the existing exact
payload CAS before refusal or replacement. Completion reuses one selected row
and decoded envelope for the component guard and legacy completion checks.
This avoids another full acquired-content decode under writer exclusion on
every page publication or completion. The final 106-control selection includes
an independent-writer probe during expected-parent decoding; strict Linux and
Windows type checks and scoped lint also passed on this revision.
