# Bounded GitHub hinted acquisition

Issue [#14679](https://github.com/ThomasMichon/copilot-extensions/issues/14679)
selects an existing Phase 3 recovery obligation, not a new client-admission
layer. The GitHub connector's exact hinted acquisition previously returned all
requested items in one call. A later-item failure therefore repeated complete
earlier items, despite the shared engine already having a hinted-page journal.

## Provider boundary and selected control

GitHub's mutable issue timeline does not satisfy the existing immutable
`SnapshotPage` contract. Wrapping its offsets in that type would incorrectly
certify coverage and permit absence-based deletion. The current bounded poll
and explicit caller requirement already refuse unsupported acquisition modes;
neither supplies a hosted full snapshot. The existing lifecycle/configuration
coordination issue #1843 is not an acquisition-repair implementation owner.

The selected control instead composes `GitHubConnector(..., paged_hints=True)`
with the existing hint/page negotiation and pending-crawl owner. One unit
finishes one exact issue or PR and one fresh comment page, accepting at most
100 comments. Larger declared discussions refuse before acquiring comments;
any continuation link or incomplete page also refuses. This bounds logical
acquisition requests, not bytes, retries or elapsed time. The existing direct
API and default connector selection remain unchanged.

A continuation binds the full hint envelope, base checkpoint and actual
connector recovery identity. Acknowledged items survive connector, path-owner
and source-state reconstruction. Interrupted work reacquires its one item,
and completed acquisition replays through the original recovery owner without
provider work. The polling checkpoint does not advance and no tombstone is
inferred. No source lock, queue, wire contract or publication owner is added.
