# Provider request-purpose measurements

## Shared HTTP and built-in GitHub accounting

- Add a finite request-purpose breakdown to the existing round-local work
  counts: metadata, identity pages, item bodies, comment pages and explicit
  unclassified traffic. Every metric sums to the unchanged aggregate HTTP
  metric; retries, unsuccessful response bytes, 304s and JSON parse failures
  retain their request's classification. Nested runs remain isolated.
- Request owners provide an optional local keyword, never an HTTP parameter,
  header or external-provider capability. The closed vocabulary rejects
  arbitrary labels before requesting or recording them; it cannot expose
  endpoint paths or principal identities as metric keys. Existing callers
  default to unclassified. The additive result remains work-count version 1.
- Classify GitHub principal/installation probes, listings, targeted issue/PR
  retrieval and comment pages, including legacy listing helpers. Purpose
  describes why a request is made, not exclusive response contents: listings
  can include item bodies. Parsed identity/comment counts and transports
  outside the shared HTTP boundary are still separate obligations.
- The focused transport, work-count, GitHub and actual worker packet passes
  116 tests. It checks aggregate compatibility, retry/error/byte behavior,
  POST and continuation payload preservation, nested scope isolation and
  unsupported-label refusal with no requests or recorded private label.
- Extend the existing opt-in native hosted matrix rather than creating a
  new required exhaustive lane. Its transport independently records attempts,
  completed responses and decoded bytes. Saved purpose totals must agree at
  100/10,000/100,000 unrelated items, through interrupted acquisition and
  journal resumption, alongside the retained store/query/projection controls.
- The four native profiles pass in both layouts with one/two models. Exact
  purpose attempts, completed responses and payload bytes match the fixture
  transport in every round and at every corpus size, including a request that
  fails before returning a response. Existing clean-reference, stale-vector,
  source isolation, checkpoint and finite native/process-I/O controls remain
  passing. Focused typing, Python lint, install contract and documentation
  consistency also pass.
- This is vision-closing measurement work under the original per-stage
  contract. It changes no acquisition, checkpoint, source-lock, provider-wire,
  embedding or recovery decision. A small existing HTTP keyword-mapping type
  annotation is made explicit so touched-source typing passes without a
  behavioral change.
- The entire measurement/compatibility/reconciliation matrix remains open.
  Classifying one built-in HTTP connector does not establish semantic counts
  for every provider or qualify consumer adoption, release consumption or
  authorized serving.
