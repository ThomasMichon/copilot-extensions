# Named-point native corpus qualification

## Scope and method

The opt-in Linux T3 `test_native_azure_devops_point_matrix.py` composes the
actual finite `PointQueueConsumer`, configured Azure DevOps acquisition caller,
worker, native point-domain store and explicit named reader. Two injected
models use real Markdown chunking and the synthetic provider's exact revision
and comment-version endpoints. Ordinary v2 execution remains unadvertised.

The existing scoped content/vector mutation and ingestion-index preparation
owners seed 100, 10,000 and 100,000 unrelated content rows, corresponding vectors
in both models, and path checkpoints. Setup is outside measurement. The ordering
ledger contains only the selected components: this is not 100,000-entry ledger
qualification. Each size executes first application, equal-version duplicate,
superseded claim and completed local retry, for both live content and an applied
comment tombstone.

## Observed work

All logical counts and measured native query counts, scanned rows and read I/Os
are equal across the three sizes. Native measurements include diagnostic plan
replay and the explicit named read after completion.

| Case | Content queries / rows / read I/Os | Tombstone queries / rows / read I/Os |
|------|----------------------------------|------------------------------------|
| First application | 122 / 125 / 169 | 84 / 86 / 121 |
| Equal-version duplicate | 73 / 101 / 108 | 50 / 73 / 78 |
| Superseded claim | 34 / 46 / 68 | 24 / 34 / 48 |
| Completed local retry | 32 / 44 / 68 | 22 / 32 / 48 |

First application uses eighteen fixture HTTP requests and two body reads,
writing three chunks per model for live content or two with the comment
tombstone. Equal-version duplicate retains the same eighteen requests/two body
reads but does no embedding or native projection rewrite. The strictly older
whole claim uses two eligibility requests, no body reads or embedding, and no
native projection rewrite. Completed retry performs no HTTP, body, embedding
or native projection rewrite.

Native table versions and logical receipt stay unchanged for the latter three
cases. Whole-checkpoint enumeration is trapped. Total native row counts remain
the seeded count plus the selected rows, and sampled raw content, both models'
vectors and path checkpoints remain byte-identical. Polling bytes stay unchanged
and no pending prepared acquisition survives completion.

Linux process I/O is reported separately, not certified constant. In the first
fully instrumented observation, content completed-retry `rchar` grew from
1,152,245 to 3,067,494 to 3,529,027 bytes; first application grew from 8,737,913
to 13,588,406 to 16,054,047. These include cached/native diagnostic reads and
metadata/queue traffic, not just physical disk reads. The fixture records
wall/process-CPU time without asserting a whole-operation CPU/memory bound.
Existing shared-engine counters do not fully instrument point-checkpoint
publication; their zero write count is not evidence that no checkpoint was
written on application.

The final two cases pass in 95.47 seconds (102.78 including preparation and
cleanup), covering all twenty-four measured rounds under the unchanged
150-second plugin and 180-second supervisor limits. Cleanup is verified.
Whole-file strict Python 3.10 checking passes for Linux and win32; Ruff F/E9
and the thirteen-plugin install contract pass. Native Windows/macOS remain
unqualified. The local documentation scan still reports only two unrelated
ignored scratch drafts outside this diff; required clean CI remains a gate.

## Remaining boundary

This vision-closing qualification adds no production code, admitted unit node,
capability declaration, provider activation or rollout. It does not complete
the canonical count matrix: ordering-ledger scale, process-byte growth,
clean-reference acceptance across the broader delta/recovery matrix, ordinary
service cutover, complete event delivery, current-discussion coverage, PR/thread
coverage, lost-event repair, full reconciliation and consumer adoption remain
separate.

After review and merge, trace the measured process-byte growth through existing
native/index metadata owners before selecting a correction or broadening this
fixture. Do not infer constant total cost from constant query-row counts, enlarge
the existing test caps, or turn a finite count packet into ordinary activation.
