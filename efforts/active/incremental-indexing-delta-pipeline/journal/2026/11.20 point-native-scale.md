# Named-point native corpus qualification

## Scope and method

The opt-in Linux T3 `test_native_azure_devops_point_matrix.py` composes the
actual finite `PointQueueConsumer`, configured Azure DevOps acquisition caller,
worker, native point-domain store and explicit named reader. Two injected
models use real Markdown chunking and the synthetic provider's exact revision
and comment-version endpoints. Ordinary v2 execution remains unadvertised.

The existing scoped content/vector mutation and ingestion-index preparation
owners seed 100, 10,000 and 100,000 unrelated content rows, corresponding vectors
in both models, and path checkpoints. Setup is outside measurement. The ordering
ledger initially contained only the selected components; the later
ordering-ledger qualification below extends that original scope. Each size
executes first application, equal-version duplicate,
superseded claim and completed local retry, for both live content and an applied
comment tombstone.

## Configured executor cancellation and readiness corrections

The implementation review identified two real lifetime mismatches. Loop-wide
Task cancellation can cancel `to_thread` wrappers while their underlying threads
continue, allowing construction to outlive cleanup or shutdown to outlive its
owner. Opening and cleanup now use context-preserving executor Futures, which
the existing settling primitive can join through loop-wide Task cancellation.
Four native controls cover caller-only and loop-wide cancellation during both
phases and require context-variable preservation and one joined cleanup.

Readiness cached for a whole service context can become stale when an engine
expires between tasks. The existing readiness helper is now scoped to each
execution, while a context-wide model set retains only started-engine cleanup
ownership. A native two-execution control expires both fixture engines between
distinct missing targets, requires readiness again, and checks one stop per
owned model. The actor-free dispatch substitute and readiness assertions follow
these semantics without adding unit nodes or native effects to unit CI.

The first combined correction run passed 14 cases but timed out in the existing
governance-wakeup case; its single isolated retry passed. Source inspection
showed that the test could notify before the runner cleared its wake Event,
then exhaust its eight-second assertion before the normal ten-second backoff.

## Asynchronous context-exit review correction

The current-head review found that inline cleanup alone protects the native
context but not arbitrary caller-owned asynchronous exits. Cancellation while
such an exit awaits could interrupt cleanup and still record a successful stop;
startup rollback could likewise lose its local stack. The correction uses a
shared cleanup Task that defers direct cancellation, including before its first
step, on both paths. Outer callers retain cancellation through the existing
settled join. Concurrent stops observe the actual cleanup result rather than a
