## Selected correctness boundary

Issue [#13339](https://github.com/ThomasMichon/copilot-extensions/issues/13339)
tracks full-body work-item batches accepting missing, duplicate, unexpected
or malformed records. The legacy explicit full crawl derives its current path
inventory from returned entries; accepting an omitted requested identity can
therefore manufacture deletion evidence. Metadata-only batch validation does
not cover that later body response.

The connector requests the provider's `errorPolicy=fail` and independently
requires exactly one integer-ID record with a fields object per requested
identity before reading that batch's comments. Provider order, query semantics,
supported work-item timestamp filtering and parsed-record observations remain
unchanged. An invalid response refuses the acquisition, rather than retrying
silently or returning a partial inventory.

This closes a concrete incomplete-source safety gap in Phase 3 and the
validation matrix. It follows the existing agent-index complete-acquisition
contract; no new snapshot protocol, cursor owner or deletion authority is added.

## Qualification and remaining work

The focused synthetic transport regression reproduced 15 missing-refusal
failures, including the actual full-crawl collector, while two valid reordered
batch controls passed. The corrected four-file Azure DevOps selection passes
**78 tests** with verified cleanup. It covers both full discovery and the
supported work-item timestamp path, rejects boolean identities and malformed
fields, preserves parsed counters on refusal, and prevents an incomplete full
acquisition from returning a deletion manifest. Whole-file strict analysis of
all three changed Python files passes on the configured Linux and Windows
targets; native execution was Linux. High-signal Ruff and the 13-plugin install
contract pass.

This is not immutable hosted membership, resumable query acquisition, bounded
whole-history discovery, complete model/source isolation qualification or live
provider/consumer rollout evidence. Those parent Plan and Validation Plan gates
remain open, and the effort remains Active.
