# Explicit point binding through service entry

Parent: [Incremental Indexing Delta Pipeline](../../README.md).

## Existing gap and bounded correction

The accepted point-component composition is available through
`build_app(point_service_factory=...)`, but the synchronous `server.serve`
entrypoint supplied no factory. An embedding host therefore had to assemble
another ASGI launch path to use the same selected service.

The entrypoint accepts and forwards the existing optional factory. Construction
still belongs to the task runner, passive startup defers it until promotion,
and every selected service starts paused. Default CLI callers supply no
factory. This closes a shared-engine extension-seam gap without serializing
callbacks, adding a selector or activation endpoint, or changing the existing
request-admission contract.

## Focused qualification

The opt-in native entrypoint control keeps `serve`, `build_app`, the actual
task runner, configured executor/reader, queue and native stores. Only the
socket and Uvicorn driving loop are substituted; provider responses and
inference use the existing synthetic fixture. Four cases cover active/passive
entry and valid/overlapping storage selection.

Valid selections stay paused without provider requests or model readiness;
explicit activation applies the retained claim and the selected reader
qualifies its result. Context shutdown closes both model clients and the
connector and stops only the model engine the context started. Invalid active
startup propagates refusal, and invalid passive promotion returns 503 without
installing a legacy runner or opening connector/model clients. All cases close
the owned socket.

The initial read assertion raced terminal queue publication against the
worker's still-owned native exclusion and correctly received a busy refusal.
Waiting for the existing dispatch owner to settle, rather than retrying or
weakening native exclusion, corrects the test. The final focused run passes all
seven entrypoint and existing routing/cleanup controls with verified supervisor
cleanup. The controls remain in the explicit integration lane, not required
unit CI.

The existing routing fixture needed typed signatures and a direct import when
its factory stub was updated for the optional argument. Its final three cases
pass independently. Whole-file strict Python 3.10 Linux/win32 targets for all
three changed Python files, Ruff and the thirteen-plugin install contract pass;
this is not native Windows execution. The existing server source pin is the
only unit-inventory change: node selection, coverage targets and the
300-second packet budget are unchanged. Two unrelated CRLF-materialized input
files prevent the raw local whole-packet verifier; their canonical LF bytes
match admission. No source was normalized or repaired to bypass that condition,
and actual required CI remains a separate gate.

## Remaining parent gates

The canonical Plan and Validation Plan remain Active. This bounded correction
does not select a point source in the default CLI, persist service selection,
automatically activate reconstructed work, reconcile partial native effects or
certify restore currentness. Broader provider/event/polling/repair coverage,
total-cost qualification and independent consumer acceptance remain open under
the same owners. No live provider, installation, activation, repair or rollout
operation was performed.
