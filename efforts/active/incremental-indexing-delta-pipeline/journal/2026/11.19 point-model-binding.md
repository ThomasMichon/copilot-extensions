# Retained point model/table ownership

Point-domain schema preparation now retains the complete configured content
table and model-ID/vector-table/dimension map in the existing protocol-2
receipt. The map has its own strict versioned shape. Its first publication
requires the existing owning writer with empty retained and native inventories;
prepared tables without a binding are not adopted.

The existing source exclusion spans each point receipt's current-state read
and atomic replacement. Saves cannot drop or replace a retained model map,
including through a stale facade or while another writer owns the domain.
Bootstrap compares the complete configured mapping under that same operation
before registering models or creating schemas. Same-dimension table swaps
therefore refuse, not just incompatible schemas.

Every selected `MultiModelStore.register_model` checks the current durable
binding before returning even a cached handle. Other facades cannot introduce
aliases, content-table collisions or changed dimensions. Model name/revision,
query policy and engine placement stay with the embedding-profile/coverage
owners; table ownership does not freeze those independent policies.
Protocol-1/default registration retains its existing behavior.

All 183 selected native model-binding, point-domain, nested-failure,
source-aware-store, component-application and bounded-vector controls pass
through the bounded supervisor with descendant cleanup verified. Existing
read fixtures that fabricate protocol-2 receipts now supply their synthetic
configured model map; production refusal is unchanged. Whole-file strict
Python 3.10 Linux/win32 analysis and Ruff pass for all six changed Python files.
The install contract passes for 13 plugins. These are not native Windows,
live-provider or large-unrelated-corpus measurements.

Two pure receipt controls are added to the existing required unit admission,
with its exact source pin refreshed. They check malformed/ambiguous ownership
and refusal of changed, dropped or improperly initialized bindings. Required
CI execution remains independent of the native result. The local documentation
count scan finds two unrelated untracked scratch drafts with obsolete counts;
they are neither changed nor published.

This closes a model-ownership prerequisite under #13386, not the effort's
remaining application or acceptance gates. Existing point mutation still
refuses. Any future selected mutator needs its configured model identity and
must recheck the binding at the actual effect boundary, along with canonical
input, applied coverage and publication ownership. No preflight result becomes
a write permit. Current queue-owner qualification, every named target's durable
applied/higher-covered result, whole-claim completion without poll advancement,
restore compatibility and consumer/count qualification remain open.
