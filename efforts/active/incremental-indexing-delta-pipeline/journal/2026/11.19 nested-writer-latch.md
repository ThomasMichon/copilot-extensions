# Caught nested source effects remain uncertain

The point-mutation review exposed a shared writer-owner defect: a nested vector
upsert can delete old vectors, fail during insertion, and have its exception
caught inside the outer writer. Previously that outer writer then cleared
uncertainty and published the incomplete projection as clean. Two native
regressions reproduce that result before the fix, through the ordinary vector
API and a private selected-domain fixture.

The existing source writer now retains an owner-local effect sequence and
failed-effect latch. Its existing persisted effect and reconciliation-seal
boundaries advance the sequence. A nested exception after a new boundary
latches the outer writer; normal outer exit refuses before publishing clean,
even if the exception was caught or a later nested no-op completed.
A caught pre-effect refusal does not poison an earlier completed write.
The durable dirty/uncertain receipt and existing reconciliation owner remain
unchanged; there is no rollback, new repair authority or protocol change.

All 176 selected native nested-failure, source-aware-store, point-domain,
component-application and bounded-vector-provenance cases pass through the
bounded supervisor with descendant cleanup verified. The focused cases also
retain a failed reconciliation seal and refuse implicit reads/retry after
partial effects. Whole-file strict Python 3.10 Linux/win32 analysis and Ruff pass
for both changed Python files. This is not native Windows execution.

The existing source-writer unit-admission hash is refreshed for these bytes,
without changing admitted nodes, coverage targets or effect permissions. The
exact actor-free packet remains a separate required CI gate; native results do
not substitute for that execution.

This closes only a prerequisite for #13386 and the existing partial-write
recovery requirements. Durable model/table ownership, real point mutation,
