# Incremental indexing storage journal - 2026-10-26

Continuation of the [earlier journal](10.26%20incremental-indexing.md).

## Prepared bucket/model input

- The cluster sweep currently enumerates every canonical item and model table.
  A source predicate alone would still scan data without a prepared source
  index. Added an opt-in bucket reader requiring a completely prepared source
  B-tree, explicit canonical-row budget and selected models' prepared point
  indices, rather than disguising that scan as small output.
- Reused the established scalar preparation owner, physical-row/tail and segment
  budgets, existing writer exclusion and witnessed maintenance transitions.
  Original chunk-ID imports remain compatible; full representation and cluster
  defaults are unchanged. Strict canonical decoding, complete-stream validation
  and existing vector validation precede reusable item input.
- This is vision-closing under good-citizen ingestion and the shared engine
  seam, following the existing fail-loud and bounded-work patterns. It is an
  in-process additive API, not a new CLI/provider protocol or source/coverage
  authority. The architecture and focused bucket-reader reference own the
  runtime behavior; no setup, dependency, configuration or rollout change is
  introduced.
- The bounded six-file selection passes 154 tests, including actual cold/warm
  source and vector plans with 100, 10,000 and 100,000 unrelated rows. Both
  query branches use scalar indices, scan exactly two selected data rows and
  stay below 64 reported I/O operations per query. Actual item reads reject
  global enumeration, per-file scans and unselected model reads. Strict stream
  failure/closure, budgets, missing/incompatible preparation, restart,
  update/delete, logical reuse and unchanged full-repair controls pass.
  Changed Python lint/types, install, documentation and module guards pass.
  This is Linux native evidence; no other platform or live store is qualified.
- Phase 4 remains open: affected-bucket generation tracking and transactional
  partial cluster replacement still need implementation and qualification.
  The immutable-adapter, full operation-count matrix, qualified release,
  consumer consumption and separately authorized rollout gates remain open.
