## Transactional cluster-slice artifact boundary

- Added optional version-1 artifact manifests bounded to 256 slices and 64 KiB.
  Per-bucket unique totals avoid double-counting items appearing in multiple
  model slices. The existing source owner still governs input generations;
  artifact receipts add no cursor, source lock or checkpoint authority.
- A complete opt-in publication can seed slice coverage. Partial publication
  compares the previously observed receipts inside one SQLite write transaction,
  changes only selected cluster/member rows, then republishes bounded coverage.
  It refuses changed coarse bases, unselected receipt changes and stale
  artifacts. Conflicting cluster identities cannot replace unselected rows.
  Rows and both receipts roll back together on interruption; the existing
  source-aware dirty latch is deliberately retained on failure.
- Artifact/global-coverage triggers revoke slice receipts, including an older
  coverage-aware full writer replacing an already empty artifact. Missing,
  corrupt, unknown-version or oversized metadata cannot authorize partial
  publication. Older global-only readers and full writers retain their path.

  selected T3 native SQLite matrix at 100, 10,000 and 100,000 unrelated clusters:
  two selected updates each require fewer than 4,096 VM steps and preserve
