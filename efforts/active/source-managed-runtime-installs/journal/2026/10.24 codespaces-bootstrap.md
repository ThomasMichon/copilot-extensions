## Bounded inventory and custody

Continue the same #7758 execution participant and canonical foundation/queue
after the qualified fixed recipes in #8625. The complete Active ROOT,
normal/repair/schema, source/adopter/native/deployment and maintenance owners
remain intact. Deduplication found no competing bootstrap adoption; preserve
#6909's open canonical snapshot qualification and #6928's watchdog work.
Neither prerequisite is replaced or awaited by this bounded publisher change.

The existing CodeSpaces bootstrap first stamps in the foreground, then
reconciles drift from its own installed payload through an age/PID lock and
background native installer. It does not select the deployment manifest's
source as SSH does. Its actual hook deadline is 15 seconds; provider registration
(10 seconds) and session guidance (45 seconds) are separate hooks.
CodeSpaces' native stamp layouts, required-context declaration and config-derived
Connection Owner behavior remain those qualified by the fixed recipe.

The payload does not yet declare the standalone foundation as a canonical
dependency. Recipe fixtures supplied it separately. Add the existing
`agent-update-driver` canonical source reference so the normal materializer
ships a complete independent foundation and its dependency closure. Do not
discover Manager, another plugin or a PATH-named driver at runtime.

The bootstrap scripts are plugin-owned, not generated from one template.
`tools/check-bootstrap-sync.py` classifies intentional families; declare this
driver-backed variant rather than copying it into unadopted siblings. Retain
the old detached-CWD contract test against an unchanged legacy-family member;
the new CodeSpaces path owes its own originating-project/native-CWD evidence.

## Proposed implementation and validation

1. Preserve killswitch/context exits and healthy no-op detection. On cold stamp
   or real drift, pass only the actual installed payload, default legacy root,
   originating project and fixed `stamp`/`provision` action to its packaged
   native first-use adapter. Remove the age/PID guard and direct installer
   launch, not the canonical installer's inner safeguards.
2. Retain live source/publication admission and own no-self/pinned semantics.
   Refuse nested custody, copied/snapshot source, unsupported installation
   hints, missing/skewed foundation and malformed declarations before queue,
   plugin or installation writes. No foreground fallback or recursive enqueue
   behind the same owner.
3. Return exactly `{}` inside the existing 15-second deadline. Put the
   bounded native launch acknowledgement in diagnostics, explicitly not
   durable request acceptance. Verify ordinary queue receipt and final result
   separately, including nonzero/failed-candidate outcomes.
4. Use the existing manual native portfolio on Windows and Linux. Exercise the
   actual materialized hook, Python-free first stamp, exact source/root/project,
   caller Job/group loss, concurrent cold submitters and healthy hook/CLI
   reentry. Prove installed CLI/module/distribution identity, immutable
   completion and failed-candidate preservation without source dependence.
5. Supply isolated adopted disabled-Owner configuration and intercept native
   registration probes; retain the qualified recipe's enabled/disabled/unknown
   service-body adapter coverage without touching host registrations. Execute
   provider/guidance hooks independently after bootstrap refusal and confirm
   their declared output and own artifacts remain available.

Keep heavy cold-download/process matrices out of required PR CI; add only
bounded smoke/structural coverage there and explicit manual native lanes.
Record unit, simple consumer, first-touch and hosted-native evidence separately.
No native macOS proof is inferred from Linux.

Selected snapshots, primary/payload command adoption, explicit installers,
cells/custom roots, live serving identity and #6909 acceptance remain separate.
No borrowing, connection, credentials, host registration, installed-host update,
enrollment, rollout or finalization is authorized by this source proposal.

This closes the existing Installer/Plugin Service Model single-owner intent
and follows thin adapters, independent payload packaging and cross-platform
patterns. It adds no standing intent, queue, scheduler, arbitrary-argv executor
or source-selection authority. Clear ordinary proposal review and merge
before implementation; then implement and qualify, not a planning-only stop.
