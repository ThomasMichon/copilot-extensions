### Reaper release-time signal custody

- The next review found a release-time signal race: normal release removed the mutex directory before clearing its ownership flag. A peer could acquire the just-freed pathname, then INT/TERM could make EXIT cleanup remove that peer's replacement.
- Added deterministic release/reacquire/signal controls for both INT and TERM across all three implementations. All six first failed because the peer's replacement directory disappeared. Normal release and cleanup now relinquish custody before directory removal. A signal in that interval may leave the old directory for the existing bounded-refusal path, but never licenses removing a peer's replacement.
- All 27 strict-shell lock cases pass on native Windows Git Bash. Linux passes the same 27 controls plus the actual generated POSIX concurrent-first-use case and all five complete retained/payload Bridge/Dispatch no-flock cases (33 passes, two platform skips). Supervisor cleanup is verified without increasing limits. Budget Guidance's affected generated shim is refreshed; existing per-plugin changefiles cover this same-PR correction.
