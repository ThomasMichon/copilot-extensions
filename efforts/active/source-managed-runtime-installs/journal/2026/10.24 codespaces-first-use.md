# CodeSpaces fixed-recipe prerequisite - 2026-10-24

[Back to the effort](../../README.md). Agent-recommended Phase 4b proposal,
not implementation, publisher adoption or parent completion.

## Existing owner and bounded inventory

Continue the same #7758 installation-execution participant and existing
foundation/queue. Preserve normal/repair/schema, source/adopter/native,
deployment and maintenance custody and the complete retained parent.
Public coordination records the bounded recipe scope before implementation.
The open #6909 canonical snapshot-copy/qualification work is not superseded
or imported; this slice does not require that PR to merge.

CodeSpaces' version-2 required-context declaration omits `provisionMode`,
which means snapshot, and names its bespoke native runtime gates. It has
its own `AGENT_CODESPACES` controls and default legacy root. Windows `stamp`
publishes a versioned snapshot and binstub; POSIX legacy `stamp` publishes
the binstub and original payload path. These are distinct existing contracts,
not permission to reuse SSH's compound stamp-to-snapshot recipe.

Both native `provision` paths build/activate the runtime, migrate config,
write the deployment manifest, verify real module launch and reconcile the
config-derived Connection Owner. Enabled configuration can register/start a
Windows user task or systemd user unit; disabled configuration removes its
existing registration; unknown leaves it unchanged with a warning. Neither
installer declares Vault's `NoService`/`--no-service` option. Preserve that
behavior and do not invent a client-only production mode.

## Proposed implementation and validation

Extend only the fixed recipe roster and its own projected context. Admit
canonical installed payload/default legacy root, reject snapshots and
copies for now, clear inherited action/payload/validated hints, preserve
exact source/project/publication admission and freeze under the existing
queue-owned live-PID native staging shape. Run only the actual fixed native
`stamp` or `provision` action under borrowed execution custody. No new queue,
schema, scheduler, executor, arbitrary argv or foreground fallback.

Use the existing manual native qualification portfolio, not exhaustive
required PR CI. Qualification must cover:

- Python and native no-write source/publication/no-self/pinned/nested/
  custom-root/cell/unsupported-declaration/client-only refusals before
  acquisition, queue or plugin writes.
- Own context projection and ambient-hint clearing; exact canonical options,
  request identity/coalescing and nonzero result retention under the same owner.
- Actual materialized native stamp and cold construction, immutable installed
  CLI/module/distribution identity and failed-candidate selection preservation,
  with isolated configuration explicitly disabling the Connection Owner.
- Actual installer service-reconciliation branches with isolated native
  registration adapters for enabled/disabled/unknown outcomes, preserving
  config queries, exact launch arguments and existing-registration behavior.
  Adapter observations are not real host registration or serving evidence.
- Python-free native caller loss/concurrency and ordinary durable receipt/result,
  plus retained Vault/Pull Requests/SSH recipe controls where shared code changes.

Selected snapshots, compound actions, generated primary/payload commands,
bootstrap, explicit installers, cells/custom roots and real service deployment
are separate later acceptance. No borrowing, connection, credentials, installed
runtime update, enrollment, host registration or rollout is authorized.

This closes part of the existing Installer/Plugin Service Model execution-owner
intent and follows the single-owner, thin-adapter and cross-platform patterns;
it does not add standing intent or a competing installation authority.
The proposal must clear normal review and merge before implementation.
