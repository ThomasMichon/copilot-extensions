CodeSpaces' version-2 required-context declaration omits `provisionMode`,
which means snapshot, and names its bespoke native runtime gates. It has
its own `AGENT_CODESPACES` controls and default legacy root. Windows `stamp`
publishes a versioned snapshot and binstub; POSIX legacy `stamp` publishes
the binstub and original payload path. These are distinct existing contracts,
not permission to reuse SSH's compound stamp-to-snapshot recipe.

Both native `provision` paths build/activate the runtime, migrate config,
write the deployment manifest, verify real module launch and reconcile the
config-derived Connection Owner. Enabled configuration can register/start a
Windows user task or systemd user unit; disabled configuration removes its
existing registration; unknown leaves it unchanged with a warning. Neither
installer declares Vault's `NoService`/`--no-service` option. Preserve that
behavior and do not invent a client-only production mode.
