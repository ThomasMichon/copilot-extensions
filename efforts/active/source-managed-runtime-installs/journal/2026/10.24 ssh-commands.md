## Implementation and caller-loss boundary

The shared generated primary now delegates cold SSH invocation to its exact
selected snapshot's tagged dispatcher. The payload dispatcher preserves
governance and healthy dispatch, but replaces cold status/trace/outer-lock
publication and foreground installers with the packaged native foundation.
Custom roots/cells, managed publication, no-self-provision, pinned reads,
nested ownership and missing/skewed support refuse before cold writes.
Original arguments, failure status, source/root/project and service-less
native options remain unchanged.

An initial implementation sketch would have made the command wait for stamp
and then submit provision. That cannot satisfy caller-loss acceptance:
destroying the observer during stamping would strand a stamp-only operation.
Instead the fixed SSH-only `stamp-provision` selection creates one ordinary
request whose existing participant custody encloses both canonical actions.
There is no queue schema, arbitrary argv, parallel executor or recursive
submission. After stamping, the existing source/provenance/publication reader
must admit the exact selected snapshot. Its complete admitted input graph is
compared with the request's frozen inputs before a second canonical freeze and
native provision under the same custody.

The first lightweight graph assertion correctly exposed the expected
difference between payload and stamped source: SSH writes three top-level
publication sidecars and omits top-level tests. Compare all other canonical
input bytes; never compare only the version, receipt or marketplace source.
The following test attempt caught its own helper import creating bytecode in
the source. Keep read-only source assertions and disable bytecode in that test
process rather than weakening the no-write invariant.
