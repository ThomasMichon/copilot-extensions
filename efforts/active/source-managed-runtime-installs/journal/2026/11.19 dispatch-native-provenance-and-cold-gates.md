## Separate cold visibility gate

Static tracing finds a 900-second ordinary-receipt observation and additional
900-second fixture settlement waits. Child output goes to fixture-owned logs;
failure diagnostics are normally exposed only after an assertion or process
exit. An outer aggregate termination can therefore leave the active phase
unreported. This identifies an observation gap, not a proved missing adapter
or a causal explanation.

Diagnostic-only source adds bounded fixed phase names and elapsed times through
the existing pytest capture manager. Capture is suspended only for each short,
immediately flushed diagnostic print and restored before native operations.
The source retains native handles, pipes, caller-Job ownership, assertions,
packet identities, limits and the direct running-observation/caller-loss seam.
These markers are not qualification evidence; any later native observation
still requires fresh source review, CI and the existing execution-admission gate.

The diagnostic source next enables only the existing Windows `cold-original`
cell's built-in pytest whole-protocol faulthandler observation at 60 seconds,
with `faulthandler_exit_on_timeout=false`. The standard runner preserves these
options; ordinary capture and native streams, handles, caller-Job ownership,
case identities and every existing deadline remain unchanged. The one-shot
traceback is an observation point, not a 60-second test deadline, process exit,
new profile or qualification result. A later admitted run could distinguish
capture restoration from framework finalization, foundation/queue/custody
polling or pinned-owner waiting. No such run is part of this source change.

The pure control passed on Windows and Linux: actual pytest received the
60-second non-exiting configuration, dumped a teardown stack during a controlled
finite 61-second finalizer wait, kept ordinary FD capture enabled and then
completed normally. The standard-runner option-propagation control and all four
workflow/collection guards passed through the existing contained test facilities.
Strict checks for the three changed Python files passed Linux and Windows
targets, along with Ruff and documentation consistency. These are diagnostic
mechanism checks, not a cold-installation retry or native qualification.
