The next actual consumer is not interchangeable with prepared provision:
both native Bridge bootstrap drift branches invoke `install`; there is no
`init` wrapper. Windows `install` applies immutable content admission and,
when construction/activation is needed, publishes commands/config/manifest,
reconciles the task and starts the service. Its exact healthy-content path
is a no-rebuild/no-restart return. Prepared `provision` instead only
reconciles the task. POSIX maps both actions to the existing `do_install`.
Changing the bootstrap to submit `provision` would silently narrow its
Windows behavior.
