## Bounded next-adopter prerequisite

After the actual merged Vault bootstrap slice, continue the already-reviewed
owning-plugin first-use integration with Pull Requests. Its canonical native
installer accepts stamp/provision but not Vault's service-selection option.
Its POSIX compatibility action/force/root environment hints cannot silently
become additional queued options, and its no-self-provision control retains
presence semantics.

The existing installer-engine sync owner supplies the canonical input freezer.
The same two fixed native front doors validate the exact owning recipe and
publication source before acquisition; the existing ordinary queue executes
the fixed native installer from frozen inputs. Context projection is
plugin-specific and keeps Vault's request identity unchanged. Client-only
selection for Pull Requests is explicitly unsupported before queue/plugin
writes, not an invented installer option.

Qualification covers canonical materialization, read-only inspection, real
stamp publication, actual native cold provision, retained healthy selection
after a failed candidate, installed command use after source removal, and the
existing caller-loss boundary with both fixed identities. Windows and Linux
use the existing opt-in foundation portfolio without changing its budgets.
This prerequisite does not adopt any ordinary Pull Requests command,
bootstrap, cell or explicit installer publisher. Broader source/adopter,
normal/repair, maintenance, native and deployment gates remain open.

## Native consumer findings and local qualification

The actual frozen-input stamp exposed two real native-consumer boundaries
before ordinary publisher adoption. Windows' mode reader launched another
PowerShell process with literal JSON, losing its probe quotes. Both mode
readers also assumed only their historical installed-payload staging layout;
an owned frozen input therefore conflicted with its original payload identity.
The Windows reader now passes typed parameters to the same native helper
in-process. Both readers reuse their complete ordinary-tree/byte comparison
before consulting the original owning source, including for frozen inputs;
the flags only locate evidence and never waive governance.

The actual materialized Windows stamp now succeeds through the canonical
queue, retains the frozen-source pointer and produces no runtime generation.
The six native plugin cases cover Python-free governance and valid/altered
copied inputs. Canonical installer sync, all thirteen install contracts and
eleven focused sync/materialization regressions passed. A combined local
first-use run exceeded its 600-second aggregate bound without an assertion
failure before completion; qualification continues with per-file cleanup and
the existing explicit native portfolio rather than treating that timeout as
a pass or changing a production deadline.
