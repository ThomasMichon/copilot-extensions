## Reviewed scope and implementation

The selected-snapshot prerequisite follows the reviewed next slice from #8606.
It does not adopt the ordinary SSH command publisher. Python and native
admission use the existing selected-snapshot provenance and deployment readers,
same fixed stamp/provision actions, frozen inputs, foundation and canonical
queue. SSH retains its own native runtime gate, value-based no-self-provision
control, default legacy installation and service-less options.

The bootstrap now explicitly retains its canonical-installed-source publication
boundary. Expanding the recipe must not incidentally make a retained snapshot
an accepted bootstrap publisher. Ordinary copies and custom roots remain
unsupported.

Actual retained restamping exposed an old receipt copied into a new private
candidate. The canonical writer correctly refused its obsolete snapshot
identity. As in the Pull Requests installer, legacy SSH copying now omits that
sidecar from the new candidate only; it leaves the accepted source untouched
and uses the existing writer for the new receipt. Source-runtime identity
copying retains its existing complete-input behavior.

## Validation in progress

The bounded local recipe matrix passed 64 cases. Its materialized fixture
initially refused the changed installer's stale generated human-output
declaration; after regenerating that one canonical declaration, actual
materialized stamp and retained restamp passed. Bootstrap controls passed
27 cases with two Linux-only skips on Windows; checkout-stamped dependency
closure passed one case. Touched Python lint and the 13-plugin install
contract passed.

The earlier hand-assembled Python import environment was invalid and stopped;
it is not a passing qualification. A combined recipe run exhausted its
480-second aggregate envelope before rendering fixture errors and is not a
pass either. The focused canonical runner produced the actual diagnostic and
verified its correction.

The existing manual `ssh-recipes` portfolio is extended in place to qualify
actual native Windows/Linux selected-snapshot provision with the installed
payload unavailable, failed-snapshot preservation, installed command/
distribution/module identity and bootstrap source-boundary controls.
Hosted execution and PR review remain pending at this point.

The first hosted Linux attempt completed the actual selected-snapshot install
and rejected the deliberately broken candidate at the ordinary health gate,
but the new test incorrectly expected the underlying import exception in
the top-level result log. SSH's existing native installers report a canonical
health-gate diagnostic instead. The assertion now requires that exact
failed-version diagnostic and the failed request's exact selected-snapshot
source, alongside the existing nonzero result, preserved healthy selection
and completion bytes. The failed run is not credited as qualification.
Required CI also exposed missing release entries for four existing transitive
driver consumers; their changefiles are added without changing those callers.

The next required-CI attempt passed the changefile step but failed Bridge's
historical HTTP-48 closure validation. The preparation helper retained only
HTTP-47's exact checkpoint, while the offline guard also validates HTTP-48
and HTTP-49 captures. A shallow CI checkout cannot prove changed historical
probe bytes from today's working tree. The bounded fix prepares each distinct
exact checkpoint from those three fixed packets through the same CI-selected
credential-free HTTPS remote and validates each captured registry. It does
not refresh evidence, select packet-provided remotes, change refs/worktree
bytes or relax the read-only validator. Tests retain same-commit coalescing,
exact-object fetching, later-packet refusal and captured-metadata validation.
Its complete test file initially exposed fourteen stale closure fixtures
missing the validator's declared protocol range. The fixtures now explicitly
declare generation 47 instead of relying on an absent field; production
validation is unchanged. All 45 preparation/closure cases pass, followed by
the real preparation CLI and the offline guard over two contracts and 737
fixtures. Hosted CI still owes the fresh-checkout proof.

The parent effort stays Active. Ordinary command publishers, explicit
