## Application installation increment

The next bounded increment keeps construction, application callbacks and
publication with their existing owners. It replaces declared ordinary legacy
launchers without an incumbent-byte veto, serializes shared command targets
across different runtime roots, and verifies all selected launchers before
acknowledging startup. Pre-start failure restores captured launcher/selector

never triggers automatic callback replay.

The prepared-source adapter repairs classified damage in an existing candidate

## Final decision: preserve the single-command transaction

Independent pre-review identified a further automatic-startup path that the
existing immutable-environment guard intentionally permits: importable
`sitecustomize` modules. A real Windows canary confirmed that the batching
prototype executed such a module against an incomplete closure, then completed
the candidate. Rejecting that supported module would change compatibility;
safe batching instead needs a separately qualified startup-hook staging or
interpreter-query design. A `.pth`-only guard is not sufficient.

The selected fix therefore uses the explicitly declared 256-task/320-container-
PID allocation for this fixed Linux integration packet, with unchanged memory,
CPU, clocks and cleanup. The single-command constructor and retained transaction
shape are restored exactly to the merged implementation. This is a scoped
test allocation, not an increase to production or global supervisor defaults.
The startup canaries remain to protect the behavioral distinction that made
batching unsuitable for this increment.

The follow-up retains the resource-control handoff, transient-health classifier
and reparse-directory repair fixes, plus the portable qualification fixtures.
Application installation itself already landed in #11121. Superseded prototype
tests are removed only where the merged tests already cover those contracts;
every merged baseline test function and every admitted canonical node remains.
Earlier batching successes above are historical experiment results, not
acceptance of the withdrawn implementation.

The final atomic follow-up passes the complete Linux wheel module (60 tests,
one Windows-only skip), all three large-receipt startup cases, and 4,949
canonical tests with zero skips, all 310 coverage targets and one coverage
collection. Sampling observes 115 UV threads plus 17 other owned tasks;
