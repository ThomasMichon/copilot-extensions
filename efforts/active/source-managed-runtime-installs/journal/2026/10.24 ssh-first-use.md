## Reviewed scope and implementation

Proposal #8572 merged at `c3e1f804f3ab6f3d377258d49b6090328d931ae9`,
after approval and required CI. Implementation preserves the same native
foundation, ordinary queue, frozen-input owner and conservative failure fence.
It does not change the queue schema, source-selection policy, SSH manifest,
runtime gate, bootstrap, explicit installer entry points or maintenance owner.

SSH's declaration defaults to snapshot provisioning and names bespoke native
runtime gates. The fixed recipe validates that actual declaration rather than
copying Pull Requests' direct-dispatch shape. It admits only SSH's canonical
installed payload and default legacy root; retained snapshots, ordinary copies,
custom roots and namespaced installations remain unsupported before any
foundation/queue/plugin write. Retained-source #5379 is not closed by this work.

The adapter projects SSH's own context, retains value-based no-self-provision
semantics, rejects pinned and client-only requests, and clears inherited
action/dry-run/payload/validated hints before the fixed native invocation.
Its actual service-less installer receives only `stamp` or `provision` and
the exact admitted installation root. Frozen inputs retain the existing
`.install-stage/<request-id>-<live-executor-pid>/agent-ssh` shape so the native
installer's reaper does not mistake a queue-owned tree for a dead stage.

The manual `ssh-recipes` portfolio selects only native Windows and Ubuntu
recipe controls and the SSH caller-loss case. It does not enlarge required PR
CI or use a second scheduler. The actual materialized installer checks stamp,
cold construction, failed-candidate selection preservation and installed
CLI/module origin after removing source inputs. The controlled cold
caller-loss fixture retains ordinary receipt/result semantics and a nonzero
native result, separately from actual installed readiness.

The install-contract guard exposed three stale byte-vendored copies of
the existing canonical Darwin process-settlement fix. The canonical sync
owner regenerated only Vault, Pull Requests and update-driver's
`installer_engine_process.py`; no process algorithm was independently changed.
All thirteen adopter contracts now pass. Python F/E9 lint and the new native
portfolio-scope unit pass.

The initial combined first-use regression command exhausted its 600-second
aggregate budget without completing; it is not counted as a pass. The focused
SSH run passed 35 controls and correctly skipped cold downloads, then exposed
a missing real-payload prerequisite: SSH did not yet carry the canonical Python
input freezer. Adding it to the existing explicit Python-adopter roster and
running the existing sync owner supplied five byte-identical helper files,
without changing SSH's native installer. Both freezer projection controls pass,
and the actual materialized SSH stamp then passed in 74.76 seconds.
Ten focused retained Vault/Pull Requests identity, stamp, source and native
admission controls also pass in 107.17 seconds.
