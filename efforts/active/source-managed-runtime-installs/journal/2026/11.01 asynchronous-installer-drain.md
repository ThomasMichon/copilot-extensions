# Asynchronous Worktrees predecessor drain

Parent: [Source-Managed Runtime Installs](../../README.md), incoming-start-first
replacement and independent outgoing-owner retirement.
Bounded source coordination: #9919; existing #5453, #6925, #7944 and #7758
owners retain their independent scopes.

## Direction

Operator direction, verbatim:

> We need to remove "wait for drain" from the install flow. Drain occurs async from install

This closes the existing installer vision's separation of admitted startup from
background draining. It does not introduce another updater, resident, cleanup
worker, forced predecessor shutdown or installed-host recovery authority.

## Source boundary

Worktrees' installer opts into a shared cutover mode that publishes the
health-gated candidate, promotes it and verifies readiness without an old drain
RPC. The existing outgoing resident observes supersession and owns accepted-work
draining and self-retirement. Installation settlement attests the new generation
without joining predecessor exit. Same-owner uncertain-publication recovery
also commits a ready published successor without old health/drain/shutdown RPCs;
rollback still requires the predecessor identity it actually restores.

`retirement_pending` is truthful separation, not a retirement receipt. Resident
process-retention leases protect live generations after the installer leaves.
Existing synchronous cutover adopters and conditional writer-transfer behavior
remain unchanged unless explicitly migrated.

## Accepted-work and irreversible-publication corrections

The final revision qualifies the actual outgoing capability and runtime prefix
before changing selectors, and refuses unsafe unrouted or incompatible
incumbents rather than relying on their older immediate/grace-forced self-exit.
Capable residents wait for a genuinely ready successor and drain all accepted
work without a grace-forced exit. Discovery renewal is route-fenced, and health
advertises published readiness only after the discovery stamp succeeds.

Publication is irreversible before the intervening flipped record can fail.
Recovery retains the complete predecessor endpoint. Known failed commitments
report failure without an indefinite ready-wait under installation locks.
Retirement intent is fsynced before reference publication and selector change;
capacity is checked before mutation, interrupted writes remain recoverable,
positive exit includes readable old birth tokens, and proven rollback cancels
exact custody without releasing dev ownership. Duplicate dev release cannot
bypass its original pending retirement.

The integrated packet passes 398 Worktrees tests with 12 native/construction
cases deselected, 83 shared ZDD tests with two platform skips, and the extended
actual Windows A-B-C process control, with cleanup verified. That control stalls
promotion while an idle predecessor remains alive, holds accepted A/B work
beyond a test-only reduced grace, and observes both installer exits with no
successor subscription before independent native retirement. These results
do not qualify complete construction, incapable-incumbent migration, every
platform or installed rollout. Current-head review and required CI remain gates.

### Prepared grants and cancellation custody

Integration also separates durable prepared intent from a committed retirement
grant. An old process exiting during preparation cannot release the dev claim
or erase rollback protection. Parent-proven publication fsyncs retiring state;
cancelled state is fsynced before cleanup so a surviving record cannot replay
a revoked grant. Live cancelled code stays protected without keeping its own
resident artificially needed. Retired records are an idempotent commit outcome,
not a missing-record retry loop.

Pending dev-code retirement blocks release even without an attached claim;
cancelled attempts do not block a newly authorized release retry. Selected live
dev code independently refuses reconstruction, and reselected dev prevents
deferred claim release. The final integrated packet passes 425 Worktrees tests
with 12 native/construction cases deselected, 83 shared ZDD tests with two
platform skips, and the extended Windows A-B-C process control; cleanup is
verified. Review and required CI on the new source still gate merge.
