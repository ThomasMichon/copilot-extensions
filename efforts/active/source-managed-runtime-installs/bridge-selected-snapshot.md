# Bridge selected-source snapshot prerequisite

Parent: [Source-Managed Runtime Installs](README.md), Phase 4b.
Coordination: #7758; same Installation execution implementer.
This is **agent-recommended integration**, not another operator requirement
or a transfer of source, service, lifetime or publication custody.

## Boundary and current behavior

The qualified Bridge recipes admit the canonical installed payload/default
legacy root. Its bootstrap now uses those fixed actions; ordinary command
publishers still install directly under their outer provisioning locks.
Do not adopt those commands until their actual owning source is supported.

The installer-emitted primary command distinguishes source forms. A
source-qualified stamp publishes a canonical selected snapshot and provenance;
the primary command uses that exact retained source. Ordinary Windows stamps
also copy a legacy snapshot, but without canonical source provenance the
command prefers its exact recorded publisher while available. Ordinary POSIX
stamps retain the publisher path. These are different existing contracts, not
permission to replace a selected source snapshot with today's installed payload.

Qualify only the canonical, source-qualified, selected legacy snapshot for
the existing single `provision` recipe, alongside its already-supported
canonical installed source. Keep unreceipted legacy compatibility unchanged.
`stamp`, registration-reconciling `install` and the already-qualified bootstrap
remain canonical-installed-source-only. No ordinary command publisher is
adopted by this prerequisite.

## Implementation plan

1. Extend the existing native/Python fixed-recipe source admission only for
   Bridge `provision` from its canonical selected snapshot under the same
   default legacy installation. Reuse the canonical provenance/selection and
   staged-origin readers; preserve the required direct declaration, exact
   source/root/project, Bridge context and complete materialized dependencies.
2. Validate the actual selected source and immutable source identity at the
   existing admission/frozen-input boundaries. A substituted, unselected,
   malformed, unavailable or ordinary copied source must not become a fresh
   installed-payload request. Retain truthful explicit refusal and the prior
   selection rather than discovering another publisher.
3. Preserve source identity and lifecycle ownership through the existing
   frozen-input executor, native staging and actual Bridge installer. Reuse
   the same foundation, queue, durable receipt/result and kernel custody.
   Do not create another snapshot builder, request backend, installer,
   scheduler or foreground exemption.
4. Retain Bridge's actual platform-dependent `provision` behavior and options.
   Windows cold provision may install/start, while prepared provision has
   distinct registration semantics; POSIX uses its existing installer path.
   Do not borrow another plugin's service-less behavior or silently choose
   bootstrap's unattended `install` context. Intercept native effects only in
   isolated qualification, without starting an actual bridge.
5. Keep publication/no-self/pinned/nested and unsupported custom-root/cell
   controls before acquisition, queue or plugin writes. Preserve unrelated
   pending/failed history, completed slots and healthy installed dispatch.
   Existing bootstrap source guards must still refuse snapshot substitution.
6. Update only directly related source-admission documentation, tests and
   bounded explicit native portfolio. Exhaustive subprocess qualification
   remains outside required PR CI. Review and actually merge this proposal
   before implementing these changes.

## Validation plan

- Use the actual canonical source materializer and Bridge stamp to create a
  source-qualified selected snapshot with complete dependencies on Windows
  and Linux. Keep ordinary release-payload stamping and existing bootstrap
  boundaries as separate compatibility controls.
- With the installed publisher unavailable, submit the actual selected
  snapshot through native first-use admission, the real foundation and the
  same ordinary queue. Prove Python-free caller admission/loss, attributable
  receipt/result, frozen-input execution and joined owner/kernel settlement
  before fixture cleanup, including assertion/timeout paths.
- Exercise real materialized construction and safe installed CLI, module,
  distribution and selected source-qualified generation consumers. A copied
  payload, available interpreter or successful stamp is not installed readiness.
  Prove distinct same-package source identity without rewriting a completed
  slot or consulting the removed source checkout.
- Qualify failed candidate construction and source/selection changes across
  admission/execution. Preserve the previous healthy selection, completion
  bytes, redirects, unrelated history and native effects. Reject malformed,
  missing, unselected or substituted provenance and an ordinary copied source
  before acquisition, queue or installation mutation.
- Preserve existing canonical-installed `stamp`/`provision`/`install`,
  bootstrap source refusal and exact ordinary Bridge context/options. Prove
  live publication/no-self/pinned/nested controls and precise unsupported
  cold root/cell outcomes; valid context is not publication authority.
- Intercept registration, startup and repair effects only. Qualify the actual
  Windows/Linux installer consumers and retained preparation behavior with
  synthetic configuration/health, never host registrations, credentials,
  remote sessions or a live bridge. Synthetic effects do not prove serving.
- Require complete exact-candidate native Windows/Linux and applicable
  source/readiness/publication/lifecycle regression results before merge.
  Keep original finite runner time/storage/process bounds; partition fixtures
  instead of weakening them or omitting required cases.
