# Generic recovery and noninteractive regression inputs

Back to the [transition proposal](wheel-first-transition.md) and
[canonical effort](README.md).

These operator-provided scenario classes are generalized test inputs, not
public references to private incidents or permission to repair an uninspected
installation. Current source may already address a case; add new-flow regression
coverage rather than competing patches to another contributor's open PR.

| Case | Required observation/preservation |
|---|---|
| Incomplete same-version lean slot versus incompatible full input | Positively identify the owned incomplete candidate and construct a fresh slot; preserve durable state and a good incumbent. No new fingerprint-conflict framework. |
| Windows PowerShell 5.1/7 construction handshake | Select the supported PowerShell/Python runtime explicitly and report a concrete prerequisite at raw bootstrap/noninteractive entry. |
| Stale owned deployment manifest/publication lock | Inspect through its native owner; never blindly unlink or replay an unsettled operation. |
| Running CMD self-update rewritten during incremental execution | Stable global redirects are not rewritten by each version update; migrate outside the old executing launcher. |
| Nested installer queue self-deadlock | One execution owner coalesces the operation; an outer owner does not wait for a child queued behind its own held unit. |
| Rejected duplicate uv flags | One argument-assembly owner; preserve literal uv stderr instead of misclassifying a native parser failure as a policy probe. |
| Supported Windows package `.pth` entry rejected after successful uv setup | Use actual package validation and owned entrypoint/resource checks; do not reject supported inputs as arbitrary hooks. |
| Per-run custody entropy in source-wheel cache identity | Reuse prebuilt artifacts and uv caching without per-install custom whole-source hashing. |
| Routing PID inaccessible, stale or unknown | Birth/ownership evidence distinguishes positively stale from uninspectable. Unknown is not cleanup authority. |
| Owned logon/task launcher references a removed junction/staging source | Stable marker-aware registrations survive staging/payload removal; validate every declared consumer path. |
| S4U registration fails or never starts | Prefer the declared least-privilege native durable process owner; no default elevation, COM or scheduled-task workaround. Prove survival after caller cleanup. |
| Passive start/routing flip followed by connection reset | Verify incumbent service/state survival and explicit commit-forward versus rollback outcome through the owner. |
| Ambient Python below project requirements | Select a supported uv interpreter; do not assume an ambient launcher chooses the correct version. |
| Broken/missing binstub absent from doctor findings | Trusted raw bootstrap and explicit source input work without the old runtime command; diagnostic gaps remain visible. |
| Discarded stderr/closed child pipe | Preserve native request/phase/exit/stderr and failed container state; no false success. |
| Busy host with live worktrees/SSH sessions | Attribute load and bound parallel preparation; do not kill unrelated work to meet a deadline. |

The matrix includes clean installation and owned interrupted/legacy recovery,
not blanket root cleanup. It protects configuration, queues/databases, active
worktrees, SSH forwards, other agents and rollback generations. Unsupported
privilege, foreign ownership and unsettled live transactions are explicit
blockers.

Exercise Windows and POSIX noninteractive SSH-shaped entries where available,
without interactive TTY, profile initialization or ambient PATH dependency.
Validate real CLI and required service health, not only compilation. Retain
failed containers for inspection/disposition; successful cleanup remains exact
and caller-owned.
