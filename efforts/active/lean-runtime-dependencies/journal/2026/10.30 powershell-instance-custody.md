## Foreground calibration remains a real gate

- Two separately bounded native attempts stopped during the owned calibration
  window's foreground request, before any installer case or quiet epoch ran.
  Their exact negative artifacts and complete retirement were verified. No
  case pass, candidate-after frame or successful four-witness restoration is
  inferred from those failures; all native acceptance remains open.
- Both stopped on a zero `SetForegroundWindow` return reported as `WinError 0`.
  The documented API supplies no extended-error contract. Raw show/foreground
  events followed by immediate cleanup did not establish the missing immediate
  before/after endpoint or the operating-system cause. No access-denied,
  historical-window continuity or successful activation is assumed.
- The source-managed calibration now records the request return separately and
  checks the actual pinned visible foreground endpoint within a bounded
  sub-deadline inside the original control window. It requests once, pumps only
  its own queue, and refuses changed, missing, late or nonmatching endpoints.
  It does not attach input queues, synthesize input, force foreground policy or
  change system settings. The original raw four-witness, exact restoration,
  continuous quiet, source, resource and retirement gates remain unchanged.
- Twenty-one actor-free controls cover immediate/deferred/already-matching
  endpoints, both request return values, denied/nonmatching outcomes, stale or
  invisible targets, invalid/expired deadlines and refusal to substitute a
  local postcondition for raw calibration. The complete observer/cold-source
  packet passed 166 cases. These are policy and import controls, not native
  desktop qualification; fresh review, CI, prepared plans and actual native
  execution remain required.
