## Independent review follow-up

- #9628's first review identified four concrete defects: process-local mutex
  contention could block expiry observation, supported reconciliation results
  could overflow a single response after mutation, interactive declaration
  limits were applied after spec validation, and helper-local Job metadata
  leaked into the original shell's scope chain.
- The observer now uses nonblocking process-local record locking. Ordered
  nonce/request-correlated response fragments preserve large outcomes within
  the original deadline. Authenticated declarations resolve before spec
  construction, while an interactive request still refuses an unattended
  owner. Shell containment validates only the supplied original scope chain.
- Regressions include an actual contended mutex, valid and foreign lifecycle
  identities, 4,096-result and long-removed-path packets through Python and
  real PowerShell reassembly, malformed/truncated fragments, and Job chains at
  their metadata boundary. The focused portable packet passed 125 cases; it
  does not replace native qualification.
- The required Bridge contract guard exposed a missing test-source fingerprint
  update. Refresh only that non-semantic source binding and its rationale;
  Session Host packets, protocol generations and capture provenance are
  unchanged. MCP appends another producer-only footprint revision, preserving
  all previously published snapshots.
- Current-head independent review, required CI and native qualification remain
  open gates. No old SDK result is relabeled for this changed archive.
- A follow-up review caught two Windows installer-fixture regressions. Installer
  diagnostics again retain the failure category/type without exposing arbitrary
  exception messages; the same privacy/status contract now also executes under
  portable PowerShell. The actual native registry fixture copies the matching
  source archive and positively checks empty/held reconciliation before checking
  preserved files, rather than accepting a failed helper startup as preservation.
  The installer packet passed 57 portable cases with four platform skips; the
  coupled Windows routing/privacy/registry controls remain part of native
  acceptance. The common source archive did not change.
- A subsequent current-head review found function-local dot-source assumptions
  in the qualification callers. The actual-registry fixture now loads the
  adapter in its outer command scope and treats command errors as terminating.
  All three native-launch qualification callers that publish process births
  explicitly load the observer in their own scope too. Portable controls check
  those source boundaries and exercise the stock PowerShell scope behavior
  without launching or compiling the retained legacy native paths. The combined
  adapter/caller packet passed 74 cases with four platform skips; the common
  archive and admitted unit inputs remain unchanged.
