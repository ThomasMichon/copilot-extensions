and its terminal-result handoff. Both select the Manager-owned script;
`standalone_build.application_resources` puts that script and its callback
helpers in the Manager wheel. The same canonical build helper embeds the
declared first-party Core closure. Manager therefore already carries Core,
but the scripts currently discover finite mux creation through their selected
Worktrees interpreter, which also owns launch-plan and seed operations.

The older-runtime branch is still an intentional supported path. No retirement
floor or qualified replacement was found that would justify deleting it.
Selected-Core uncertainty does not authorize legacy retry or cleanup.

adding another required key would not work with an older receiver.
Manager's existing slot-local bootstrap retains a generation while its
invocation runs, but packaging and that short invocation alone do not prove
survival after Picker teardown, caller cleanup or package replacement.

No runtime change is justified by this trace alone, and no compatibility,
lifetime or rollback gate is marked complete. Preserve these adapters rather
than replace them with a guessed interpreter or a new handoff contract.
Continue the independently open original-owner recovery binding: its passive
inspector/store exists, while actual original lifecycle descriptor publication
and qualified provider mapping remain missing. This is source/state work,
not observer, process-retirement, recovery activation or rollout authority.
