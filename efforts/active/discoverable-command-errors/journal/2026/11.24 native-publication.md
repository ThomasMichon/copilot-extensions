## 2026-11-24 - Review the standalone failure-path exception

- The existing performance rule prohibits per-event child processes. A queued
  standalone Node adapter would require one existing native writer after
  failure, so it is not silently treated as conformant.
- Propose a narrow, review-first exception in the authoritative performance
  pattern: no ordinary-success helper or recurring reporter, no interpreter
  provisioning or collector, existing native privacy/locking custody, fixed
  causes, bounded contained completion, no operation replay, and measured
  Windows/POSIX caller qualification.
- The reason is concrete: Node's standard library cannot implement the shared
  DACL/byte-range-lock/flock contract directly. Assuming permissions or
  substituting uncoordinated append would lose existing guarantees.
- This contract proposal activates no caller. Node adoption, its actual
  performance and compatibility proof, remaining entry families, authorized
  rollout and installed discovery remain open.
