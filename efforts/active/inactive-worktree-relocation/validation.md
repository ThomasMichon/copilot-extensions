# Focused relocation validation

Part of [Inactive Worktree Relocation](README.md). Proposed acceptance, not
passed-runtime evidence. Run the smallest packet that closes the current
criterion; keep native/process/filesystem qualification opt-in rather than
expanding required unit-only CI into an exhaustive matrix.

## Proposal gate

Run the existing effort/vision structure guard for the changed README files,
documentation consistency, diff/links/public-safety checks and normal required
PR CI. Obtain the actual repository-accepted review verdict and verify merge.
No runtime logic changes in the proposal: unit runtime, clean-room installation
and live migration lanes are not exercised at this gate for that reason.

## First complete ordinary consumer

Use synthetic registered projects and actual linked Git worktrees. Start with
a stopped clean checkout and a merged/final source contribution; retain a
sentinel ignored file. Drive the real plan and move parser/process entrypoints,
then verify actual Git root/common directory, branch/HEAD/index, byte-for-byte
content, tracking identity, owner/PR association and path resolution.

Exercise same-volume and real Windows cross-volume storage. A same-filesystem
copy with mocked paths does not qualify cross-volume. A POSIX native packet
must separately verify its supported metadata semantics. Missing capacity,
permissions, platform or volume prerequisites mean an explicit remaining gate,
not a skip interpreted as passing.

Use real consumer operations after rebinding: inspect/status and mutation;
for an active synthetic contribution, the normal publication admission path
without treating a finalized record as publishable. No public throwaway repo
creation is necessary; use existing isolated provider fixtures for effectful
publication while retaining real local caller/Git-family admission.
Return the qualified supported flow before broad-case implementation; actual
adopter pilot and source installation are separate authorizations.

## Refusal, concurrency and recovery

- Read-only plan has no tracking, Git, session or filesystem writes.
- Active or uncertain session/process CWD, live execution leg, launch
  reservation, pending lifecycle mutation, foreign owner/project/environment,
  mismatched Git family/ledger, stale source revision and unsupported client
  metadata prevent effects. A negative probe is distinguished from probe failure.
- Competing launch/mutation/move and source/destination changes during
  preflight cannot cross admission unfenced. Existing owner locks remain live;
  do not test success by disabling them.
- Inject failure before/during copy, verification, Git repair, each
  authoritative pointer update and source retirement. Interrupt the owning
  process at journaled boundaries. Retry/status identifies the original
  operation; rollback/forward recovery selects one authoritative usable copy
  without replacement allocation or premature deletion.
- Re-run after lost responses and failed cleanup; preserve original IDs,
  unresolved effects and exact custody. Verify unrelated worktrees, branches,
  sessions and permission boundaries remain unchanged.

## Mixed roots and original allocation intent

Keep old-root records while changing only a synthetic project's allocation
default. Existing lookup, resume, mutation and source-publication admission
must use the retained authoritative location, while new creation uses the new
root. Repeat after supported native relocation with no default-root change.

Cover legacy and tuple records, receiving-allocation evidence, independent
companion repository overrides, completed-key replay and interrupted
creation-tail/repair. The original nonce, owner, pair and immutable receipt
must survive; a changed default never re-carves an already-started allocation.
Cross-project, physical-host/guest, symlink/namespace escape, mismatched Git
family and redirected-ledger controls must still refuse.

## Broader inactive cases

- Real staged and unstaged edits, intent-to-add, untracked and ignored content,
  file deletions, binary bytes and permissions survive exactly; no forced
  commit, clean, discard or archive. Check the real Git index and worktree,
  not only `git status`.
- Retain synthetic Copilot session IDs/history across native supported
  workspace/store updates and actual resume readers. Prove CWD/Git root and
  relevant file references resolve correctly; immutable historical snapshots
  remain interpretable. Keep an unrelated live session row and writer active
  to prove narrow ownership/transaction behavior. Unknown versions refuse.
- Move/recover supported paired worktrees with independent roots through each
  receiver's authority. Half-complete moves retain explicit pair recovery
  rather than silently splitting identity or replacing companions.
- Exercise supported symlinks/junctions/hardlinks, ACLs and other declared
  native metadata. Verify no unrelated target traversal or access broadening.
  Unsupported filesystems, submodules, locks, opaque providers or artifacts
  are actionable refusals, not skipped preservation requirements.
- A source-bound external-runner cache may select a new cache after relocation.
  Prove its owner behavior without discarding copied ignored artifacts or
  treating venv absolute paths as repaired by text substitution.

## Contract and tier boundaries

Focused unit tests cover pure admission/journal transitions; isolated real Git,
SQLite and CLI composition cover owning consumer seams. Native Windows and
POSIX packets establish actual filesystem/process behavior. Supported old/new
caller/provider and rollback controls establish declared support independently
of package versions; strict unknown syntax and unsupported relocation refuse
without replay or unrelated legacy-operation breakage.

Publish support/recovery documentation and honest remaining qualification
before broad source completion. Source PR CI, fixture success, main promotion
and installed adoption are distinct facts. Clean-room first-touch qualification
is owed if implementation adds bootstrap/schema-initialization behavior; an
available external lane must exercise the relevant consumer or be named as
unexercised. No lane authorizes real user-data movement or runtime rollout.
