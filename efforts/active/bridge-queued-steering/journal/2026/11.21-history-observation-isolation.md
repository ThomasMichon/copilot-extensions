# History observation isolation source accepted

Canonical effort: [Bridge Queued Steering](../../README.md).

## Source result

[PR #13862](https://github.com/ThomasMichon/copilot-extensions/pull/13862)
merged as `493a0c15696e81eedebe054c2711fc56fdc65761` after a current-head
Copilot approval with no open findings and successful required CI.

Controlled regressions reproduced two failures in the shared Core receiver:
a rejected history read aborted a delivery tick, and a history read that never
settled occupied the same outstanding-operation slot as native context and
input submission. Both prevented a fresh, otherwise granted compatible
delivery. These fixtures establish a source defect, not the initiating SDK
method of every reported installed stall.

The repair gives pure history observation its own bounded slot. Native context
and input effects remain serialized; an unresolved input effect still prevents
another send. Compatible delivery can continue after an unavailable history
read only through fresh native-context validation and final inbox admission.
Legacy receiving retains its history hold. Original receipt identities,
uncertainty, recovery cursor and late history reconciliation remain unchanged.

All 156 focused source/API tests passed on the published head, including
rejected and pending history, context drift, late original consumption,
legacy holds and unresolved input-effect controls. Syntax, installation
contract, documentation and mapped-consumer changefile checks also passed.

## Released and selected-native qualification

[Release PR #13869](https://github.com/ThomasMichon/copilot-extensions/pull/13869)
promoted the containing source snapshot to Main
`8abf638ba6099b8bb424a21fc145c31843d8d8ab`, including Bridge
`0.9.510-dev1` and Core `0.1.18-dev1`. Both the projected receiving module
and packaged Core copy matched the reviewed source.

The selected native Windows backend was healthy after ordinary update.
The existing interactive receiver then loaded the released extension through
ordinary extension reload on CLI `1.0.114-0`, without replacing its native
conversation. Its new worker registered that same conversation and actually
reported an outstanding, timed-out native history observation.

Two fresh owned inputs qualified the repaired boundary. The first reached
the model at a tool boundary, so I excluded it from strict idle-at-rest credit.
For the second, I ended the assistant turn and withheld further tools,
operator input and scheduled prompts through a quiet arming period. The
original message then reached the model while the receiver was at rest.
The contained sender remained running until the model acknowledged that
exact input; helper completion therefore could not be the unrelated wake
that made delivery appear to work. Each case submitted one nonduplicate
original, and both bounded helpers settled with verified cleanup.

This proves actual input progress through the selected retained receiver
despite unavailable native history, not merely registration, SDK acceptance
or a model-free fixture. The qualified frontend did not emit the unsupported
end-turn promise during the exercised post-tool sequence.

The original backend receipts nevertheless remained `sdk_accepted`, with
no recorded consumption timestamp, after both inputs were visible to the
model. I preserved that discrepancy rather than converting the private test
acknowledgement into a canonical consumption event. Exact native receipt
production remains an independent incomplete boundary.
