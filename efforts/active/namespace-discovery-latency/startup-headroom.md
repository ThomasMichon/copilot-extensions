# Native startup headroom

This is an implementation sub-plan of
[Namespace Discovery Latency](README.md), not another effort or authority.
The parent Request, ownership, release gates and completion criteria remain
binding. All implementation and validation details below are
**agent-recommended** means of executing the operator-approved follow-up.

## Objective and measured basis

Complete cold namespace discovery within the existing eight-second budget by
removing unnecessary work, not necessary validation.

The correlated command trace attributes 7.438 seconds to launcher/selection
0.841, canonical installation-mode validation 2.336, Containers initialization
0.802, the complete Worktrees state-root peer 2.890, and backend/return 0.569.
Other real invocations exceed eight seconds; this sample is not acceptance.

Three positive legacy-mode controls returned identical complete status JSON
through the canonical PowerShell and isolated Python SDK implementations.
Python saved approximately 1.34-1.45 seconds. These observations justify
investigation, not general evaluator equivalence or bootstrap authority.

The state-root command also loads portable launch preferences that its result
does not consume. Those are distinct from the required knowledge binding,
launch policy and registered checkout checks.

This closes the existing Bridge vision's bounded, honest provider-discovery
delta. It follows `docs/install-contract.md`, the canonical
`libs/installation-context/README.md` contract and the existing native process
launch/ownership patterns. It does not introduce another SDK or state resolver.

## Next independently reviewed slice: the existing state-root import closure

#8789 completes the assigned selector/two-adopter implementation, not the
eight-second objective. The retained actual legacy-frontdoor command still
takes 9.378 seconds. Its separate runtime profile attributes 1.371 seconds
to eager imports; that is not all removable work or an additive prediction of
whole-command savings. For example, an activity import includes configuration
that state-root genuinely needs.

The bounded import-closure plan was reviewed in #8818 and merged as
`a1a15d4c9e7d934d02fac5818e3f194865f4cae6`. Implementation remains open:

- Trace the ordinary CLI's existing state-root dispatch and retain its project,
  CWD, binding, configuration, output, error and conduct decisions. Use the
  existing lazy-dispatch/full-surface mechanism; do not add another launcher,
  direct-Python peer route, parser shortcut or runtime-authority bypass.
- Defer only imports belonging to unrelated command families, at their existing
  owners. Keep ordinary dispatch and compatibility re-exports/monkeypatch
  seams working. Do not copy the state-root algorithm or change configuration
  readers, source/default-branch checks, receipt algorithms or persistent state.
- Preserve the concrete open ownership boundaries refreshed after #8789:
  #8458 owns Git observation/cleanup and status-segment-cache behavior;
  #7611 owns project-config writing; #6009 owns anchor-ledger accounting;
  #8786 owns optional-map configuration. Coordination comments on the first
  three PRs identify the proposed noncompeting import work. Their actual
  implementations/imports are not repair targets; refresh new overlaps before
  editing and coordinate any genuine conflict rather than pre-patching it.
- Prove complete state-root JSON/text and bound/unbound/error parity, explicit
  repo/project behavior, pairing/conduct and unchanged ordinary command
  dispatch. A deterministic work-count contract should identify the unrelated
  modules no longer loaded; real fresh subprocesses must prove import and
  compatibility behavior. Required source/unit admission stays separate from
  effectful native tests with no coverage/hash/observer exceptions.
- Rebuild source-independent normal fixtures and use the actual deployed global
  legacy peer contract, never the slower but different payload frontdoor as a
  substitute. Measure changed startup and complete discovery separately.
  Qualify five fresh processes and five warm reads plus the real Bridge native
  reader only if the first whole-command result meets the unchanged eight-second
  bound. Retain and diagnose any failure instead of retrying an unchanged cohort.
- Reject a slice without meaningful measured benefit. If another mechanism is
  needed, return to separate owner-coordinated review; do not quietly broaden
  into installer/native-frontdoor, SDK or lifetime work. Source review/CI,
  containing release and authorized installed consumption remain distinct.

The first bounded import experiment was rejected after normal isolated builds:
three alternating fresh global-command pairs retained complete state-root JSON,
but candidate times were 2.938/2.735/2.281 seconds against baseline
2.578/2.296/2.204 seconds. Installed module origins and the absence of the targeted
unrelated imports were verified; work-count reduction did not establish useful
latency reduction. The candidate is withdrawn, not a published optimization or
an eight-second pass. No unchanged whole-discovery cohort was retried.

This remains the reviewed slice under step 4, not shipped import behavior or
another implementation assignment to the already-completed selector PR.
Any different mechanism, including the existing Docker preflight, still requires
its own measured trace, ownership check and separate reviewed plan.

## Validation plan

| Tier | Required evidence |
|------|-------------------|
| Pure units | Actual handler/config behavior; unchanged default callers; complete binding/output equivalence; no unused preference read; only deterministic effect-free cases enter the canonical unit packet with full source enrollment. |
| SDK/dispatcher contracts | Equivalent typed outputs and refusals for ready legacy and namespaced state, missing/corrupt/foreign receipts, source/cell mismatch, stale generations, maintenance/deactivation and relevant ownership states. No success-shaped fallback. |
| Bootstrap contracts | A trusted bootstrap is selected independently of the unadmitted runtime; absent Python retains native bootstrap; refusal is terminal; no implicit installation, network acquisition or package-site execution. |
| Native Windows | Real PowerShell 5.1 and pwsh processes, argument fidelity, stdout/stderr, no visible windows or foreground changes, cold and failure paths, and settled caller-owned work. Keep native integration outside the effect-free release-unit packet. |
| Simple end-to-end | Actual canonical launchers, runtime-gate evaluator, provider command and Bridge native-reader boundary; bind code/interpreter/command identities to each result, including successful empty inventories. |
| Fresh environment | Disposable no-Python/cold-native and prepared-source fixtures preserve first-touch behavior. Use the existing clean-room lane where applicable, not a preprovisioned fixture relabeled as fresh. |
| Linux compatibility | Existing isolated Docker lane for the changed pure/config contracts and relevant source-install compatibility; unchanged POSIX dispatch remains unchanged. Do not boot a held remote venue as a substitute. |
| Release and consumption | Source merge, containing qualification, Main helper adoption and actual authorized running state are separate receipts. Existing control/integration owners retain their gates. |

Record the applicable tier's exact outcome and a concrete reason for any
unavailable lane. Failed or skipped cases remain distinct from passes.
No deadline increase, coverage reduction, effect exemption, disabled provider,
forced rerun, tag rewrite, installed patch or custody reset is permitted.
