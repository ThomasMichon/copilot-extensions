# 2026-11-02 - Private inventory creation ownership

Related public coordination: #7028 and umbrella #8403.

The retained Manager callback exposed a new-root creation mismatch: parent and
Git-Bash child have the same TokenUser but different TokenOwner values.
Ordinary directory creation inherited the parent's default owner, so the
child's existing owner guard correctly refused its first actual reservation.
This is not legacy state, a borrowed runtime failure or permission to admit
arbitrary owners.

The shared source fix creates missing private directories, locks and staged
record/cursor files with TokenUser as owner in the creation security descriptor.
Existing paths retain their original security and existing admission policy.
The runtime anchor remains borrowed/read-only. Handle conversion retains
binary bytes and noninheritance; native bindings remain lazy so portable
registry imports stay ctypes-free. Generated source archives use the same
canonical implementation; no installed application or host ACL is changed.

The canonical promotion packet admits 25 actor-free creation controls,
including failure/resource handling and unchanged existing-owner admission.
Actual Windows creator/binary controls and the retained same-user,
different-default-owner Git-Bash consumer callback remain required; Linux
skips or a source archive are not native qualification. Their execution must
use fresh test-owned inputs and the existing bounded native owner.

The existing native owner subsequently ran both exact Windows SDK selectors
against source `7f091b462b6a668ac72ebdbe0c51733c300e89e5`: two passed, none
skipped, with the parent's TokenUser differing from TokenOwner. The shared
package and archive match the committed source. An initial import-order
failure was followed by a fresh control that preimports the complete candidate
SDK and verifies its origin before the normal guarded portfolio imports.
The original containment, 300-second group and 30-second item bounds remain;
both attempts confirmed owned cleanup. This is creator/binary qualification
only, not the full SDK packet, desktop acceptance or callback latency proof.

Review identified a concurrent cold-cache mismatch: the lazy layout factory
can return distinct ctypes classes to simultaneous first callers. Both native
creation signatures now accept the security-attributes address as `c_void_p`,
so valid structure pointers do not depend on Python class identity. Actor-free
controls replace the layout between creations; two additional contained
Windows selectors force concurrent cold misses and interleaved calls.
The earlier two-selector result remains historical; the revised creator and
concurrency selectors require a fresh candidate under the same native owner.

The retained Git-Bash callback remains open. Its immutable slot imports its
own vendored SDK, and its current composer has no test-package override.
Qualification therefore requires reviewed complete-source integration through
the existing application/fixture owner, preserving the application bytes and
Main seed. A test-runner PYTHONPATH or partial slot overlay is not that path.

This entry records implementation and remaining qualification, not a merged
source result, release, installed rollout or completion of Phase 5.
