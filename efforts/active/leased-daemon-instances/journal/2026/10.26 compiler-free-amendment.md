## Windows original-parent lifetime building block

Direct source tracing found a path resolver and signed-executable bootstrap
selection, not a complete admitted helper handoff. The read-only evaluator
selector still compiles interop. None is treated as permission to acquire
another Python or remove an existing compiled implementation prematurely.

The private shared `_windows_parent_job` startup primitive pins its actual
direct parent's process handle and creation identity. It duplicates a
non-inheritable strict kill-on-close Job handle into that exact parent, assigns
the sacrificial helper itself and closes the helper-local Job handle before
return. Only the original parent retains continuing Job custody; its exit
therefore retires the helper and all descendants in the kernel without a
Python watchdog or post-start target assignment fallback. The existing atomic
target-Job implementation still owns application execution and settlement.

Portable controls cover ordering, exact-parent refusal, invalid birth values,
parent exit/unknown waits and native-call/handle-close failures. Failed
duplication output is not treated as handle custody, and self-assignment makes
any subsequent failure terminal rather than permitting another transfer.
The hardened, network-disconnected owned-process regression packet passed
177 tests with 20 explicit platform skips. The final focused portable packet
passed 40 controls. Native Windows then passed all 45 focused controls on
CPython 3.12.13: the fixtures pin the helper, atomic target and real grandchild
before requiring kernel retirement after parent exit and explicit Job closure,
twice each; stale parent birth refuses before application spawn. All three
processes were confirmed gone before observer cleanup. The earlier native
packet failed at an observer string/raw-FILETIME mismatch before reaching
retirement; a format-checked adapter corrected that test without weakening
handle or full-precision identity checks. The retained report and identical
runtime/native-fixture source hashes were independently checked.

All sixteen complete source archives were regenerated by their canonical
owner, with release declarations for the shared library and affected consumers.
No existing PowerShell wrapper, interpreter acquisition, installation-context,
operation-lock, update-driver or daemon protocol switches in this building-block
slice. Interpreter/complete-source admission, bounded shell framing, actual
native desktop qualification, source review and merge remain open. These
