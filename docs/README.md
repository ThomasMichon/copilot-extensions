# Documentation — Start Here

copilot-extensions supplies reusable toolkit components. Your chosen plugin
set, repositories, accounts, policies, and venues turn them into a harness.
Read only the path your task needs; component references remain authoritative.

## Adopter reading path

| Step | Question | Page |
|------|----------|------|
| 1 | What is the toolkit? | [Root README](../README.md) |
| 2 | How do I load a capability and verify it? | [Installation](installation.md) |
| 3 | What should I select, and what does it require? | [Capabilities](capabilities.md) |
| 4 | How do I integrate it with my repos? | [Adoption and hypothetical deployments](adoption.md) |
| 5 | Who owns each setting and state location? | [Configuration](configuration.md) |
| 6 | How does the running system compose? | [Architecture](architecture.md) |
| 7 | How do I assemble or audit an opinionated harness? | [Harness runbook](harness-runbook.md) |

For interactive configuration, follow the illustrated
[Configuration workbench walkthrough](configuration-workbench.md).

For a specific plugin, go directly to the [reference index](reference-index.md)
or the [marketplace roster](../.github/plugin/marketplace.json). Installation
does not imply adoption; a successful local workflow does not prove a remote
venue or another platform works.

`docs/plans/` holds planning material; a plan, milestone, or screenshot is not
proof that its subject is shipped. Confirm present-tense support in the owning
plugin's references and implementation.
