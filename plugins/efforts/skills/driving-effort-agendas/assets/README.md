# Agenda example assets

The existing `agenda.example.json` / `cursor.example.json` pair is a legacy
version-1, finite count-limited template. The `agenda.deferred.example.json` /
`cursor.deferred.example.json` pair uses the compatible legacy version-2 deferred
frontier. Adapt canonical references, exits and lane identity before explicit
adoption; keep cursor/board revisions and entry positions consistent.

These numerical limits are not defaults for semantic revisit judgment and never
imply an Operator decision. Legacy admission still enforces them strictly.
Do not relabel either pair as cursor 4 or reinterpret the version-3 migration
refusal marker as executable state.

`init.context-qualified.example.json` is a full request-2 fresh initialization
for the declared source CLI (`init --mode context-qualified`). It creates board
2/cursor 4/store generation 2 with explicit resource caps; it is not migration.
`revisit.context-qualified.example.json` supplies the context/judgment/approach
part of a productive revisit. `revisit.metadata-only.example.json` is a deliberate
negative proposal: metadata/reference/text changes do not make the unchanged
input novel. Construct the surrounding update with IDs and revision from actual
managed reads, not placeholder attempt identifiers.

The [source CLI walkthrough](../references/context-qualified-commands.md) and
dedicated source-CLI guidance test own these worked examples. Keep synthetic
evidence distinct from actual work acceptance and replace source/scope/lane
placeholders only for an explicitly owned assignment. The [skill](../SKILL.md)
and [context qualification](../references/context-qualified-continuations.md)
preserve review, authority and independent resource limits.
