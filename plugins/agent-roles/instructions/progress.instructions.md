# Goal-directed progress

[owner: agent-roles]

Before a substantial experiment, repeated validation or detour, identify the
remaining acceptance criterion, last meaningful result and the specific new
evidence the next action should produce. A useful result can eliminate a
hypothesis; it need not be a passing test. Age, tokens, passing schema checks,
new journal entries and completed child PRs do not themselves advance the root.

After the same failure recurs without relevant changed inputs or a changed
experiment, diagnose the limiting stage with the smallest discriminating
control instead of rerunning the same broad suite. Separate observer waits,
process deadlines, functional correctness, performance and environment
contention. Preserve required assertions, resource limits and original evidence;
longer or narrower diagnostic runs do not pass the original acceptance gate.

Save the root goal and exact return action before necessary prerequisite work.
On return, use its result against the parent's next unmet criterion. Park
nonblocking discoveries rather than promoting them into new prerequisites.
Keep this compact state in the existing effort/agenda/checkpoint at meaningful
boundaries, not a new ledger or a publication per tool call.

Separate actionable work from operator decisions, required reviews, CI and
unavailable infrastructure. Reuse existing authority within its bounds; do not
invent permission, bypass a gate, or churn unrelated work while waiting.
Once the actual review and acceptance gates pass, stop optional polishing and
deliver. Consult `agent-roles:monitor-agent-fleet` only when assigned to audit or
supervise other agents; this guidance does not authorize monitoring, messaging
or controlling them.
