# Triage Issue Backlog (Persistent Role)

Run supervised issue triage, not an implementation queue. The main agent owns
intake, research assignments, acceptance and **one publication stream**.
Existing contributors retain their issues, PRs, plans and resources. Dispatch
is optional: this is the manual, agent-driven counterpart of an adopted
registrar triage task, not permission to start or replace that task.

For duplicate/overlap clustering and canonical receiving toward a finite queue
target, use [consolidate-issue-backlog](../consolidate-issue-backlog/SKILL.md).
That distinct role preserves whole requirements before separately authorized
source retirement; individual triage does not grant bulk closure.

The skill owns the reusable procedure. Target severity, routing, attribution,
privacy and allowed provider effects come from their rightful owners.
Read [guidance and adapters](references/guidance-and-adapters.md) at activation
and [evidence and continuity](references/evidence-and-continuity.md) before
acceptance, publication or recovery. Fill [the charter](assets/CHARTER.md).
The [synthetic scenarios](assets/scenarios.json) are contract walkthroughs,
not live qualification or operational state.

## 1. Resolve a casual request into one durable charter

Resolve the named repository/backlog, provider, organization/project, and
filter through existing target and provider owners. Do not require an operator
to supply implementation paths. A request such as "Example Controls backlog,
Widget issues only" must become the provider's exact supported query scope;
an unresolved name or filter blocks that intake, not permission to broaden it.

"Persistent" means continuous intake, including new matching issues, until the
operator stops or accepts a transfer. An empty pass is not completion.
A finite request instead records its cohort/time bound and terminal census.
Default to **read-only assessment** without an original grant covering writes.
Reuse applicable standing authority and settled choices; do not ask again just
because another cycle or context started. Ask only for a missing consequential
scope, policy or authority decision.

Resolve the **executing harness**, the **bound knowledge workspace**, and the
**target space** separately. Read applicable owner guidance and scoped addenda;
record source locations, revisions, applicability, conflicts and absence in the
charter. Persist the filled charter in the existing authorized planning/state
home, not in a stateless harness or another contributor's worktree.
One charter owns this target/filter run; addenda are inputs, not parallel runs.

## 2. Reconcile ownership and qualify intake

Read existing assignments, discussions, linked PRs and efforts through their
owners before assigning research. Match provider-native issue identity and
overlapping behavior, not just a title, label or file name. Keep a current owner,
live-idle session, suspended work, input hold and unknown occupancy distinct.
Age or an ended PID does not prove abandonment. Local bookkeeping is not a
distributed reservation. Never clear another owner's claim to make room.

Verify repository-scoped identity and actual provider capabilities before
reads/effects that need them. Credential-mint warnings, mismatched identities,
missing required bindings and source-health errors hold the affected action;
do not switch the global account or use ambient authentication.

Acquire complete, paginated intake and discussion with recorded query scope,
coverage and capture time. Partial enumeration is unknown, not an empty queue.
Compare material report changes and recorded revisit conditions with accepted
history. Missing `triaged`, a timer, restart or routine publisher metadata alone
is not new bug evidence. Refresh newly eligible items through the **same**
ownership, freshness and capacity predicate used to assign them, before taking
a fetch limit; held rows must not starve later eligible work.

## 3. Assign bounded evidence work

Use the host's existing native Task/agent tools for in-session work; Bridge is
only an optional cross-boundary transport. An adopted Dispatch owner may supply
deduplication, reservations or suspension without becoming mandatory.
No SDK driver, new queue, installed watcher, daemon or permission broker.
An explicitly selected effort-local helper may cache data and render reports,
but does not launch models, publish remotely or establish native ownership.

Choose a conservative concurrency limit from the original grant and actual host
capacity; default to **one** research worker if none is specified. Use host model
preferences unless the operator explicitly chose a model. A model's name or
budget is not qualification. Refill eligible independent work promptly within
the recorded ceiling, rather than treating a batch as the run's end.

Give each worker one issue, the exact reviewed revision, relevant guidance,
exclusions, artifact destination, evidence gap, time bound and stop condition.
Default to roughly ten minutes of bounded investigation, not forced completion.
Workers are evidence-only; they do not fix, create efforts, post, label or close
issues. No nested delegation without a separate assignment.
Use a fresh Task for an unrelated issue or independently changed assessment;
retain a handle only for a genuine same-assessment follow-up.
Bind actual returned handles to assignments; planned launches and local rows
are not running workers. Never poll native Tasks that emit completion events.

## 4. Investigate and accept evidence honestly

Investigate before requesting contributor input. Read the report, existing
work and relevant source/callers through the owning domain adapter. Record
actual source pins and what they prove. A current source checkout is not the
affected installed payload. Static source, synthetic tests, release inclusion,
installed readiness and live behavior are separate evidence.

Keep facts, hypotheses and unavailable checks distinct. Use target-owned
severity and classification, not another backlog's labels. Unknown impact
stays unknown. Uncertainty does not establish needs-effort, duplicate, fixed or
non-repro; a short proposed diff does not establish small-fix risk.
Complex supported work may be an effort candidate, but this role does not create
a replacement plan or admit implementation.

Read the worker's full artifact and verify its assignment, source revision and
retained hash where supported. Independently check the evidence against the
remaining route-specific criterion, not the worker's success footer.
Refresh material input and ownership before acceptance; movement invalidates
the old result's current applicability, not its historical evidence.
Keep required evidence gaps **partial** even when the worker's turn has ended.
Record disposition, responsible next action and a concrete revisit trigger.
Do not mark an issue triaged merely to satisfy an evaluator.

## 5. Publish useful findings through one owner

The main agent is the sole publisher unless a distinct adopted publication
owner is explicitly selected in the charter. Workers submit proposals only.
Read-only mode records findings privately; live triage performs only originally
authorized, target-supported effects. Triage is not a fix, closure, assignment,
upstream filing or rollout grant.

Refresh relevant input/ownership, persist the exact intent, use supported
provider preconditions, then read the effect back. Do not invent atomicity for
a read-then-write fallback. Keep one useful owned summary, updating it in place;
never edit another contributor's words or post unchanged status chatter.
Preserve unrelated labels/fields and the target's adopted taxonomy.
Existing-owner deferrals normally need no new public comment.

Reconcile an unknown write outcome under its original identity before retrying.
A verified post with failed local bookkeeping must not be posted again.
Keep the canonical summary ID before excluding that verified owned effect from
later material-change comparison. Publication and local acceptance are separate.
Preserve the originating tracker; dependency provenance does not silently move
a report upstream. Public artifacts never acquire private links or context.

## 6. Revisit, recover and end under the parent gate

Persist accepted outcomes before advancing discovery progress. Wake on material
contributor evidence, relevant linked-work results, selected investigations,
operator decisions or due checks. Compare the delta before spending another
research turn. Repeated inconclusive passes need a discriminating new evidence
request or owner decision, not endless identical analysis.

Use one existing observation owner: coalesced provider events/watch if available,
otherwise one native scheduled prompt or bounded shared polling fallback.
Record cadence and latency; default an otherwise unspecified idle backstop to
15 minutes, adapting through the existing owner. Back off errors and unchanged
observations. Never add per-worker pollers or an OS service/scheduler.
If native wake support is unavailable, report the continuity limitation rather
than pretending a persistent collector exists.

Maintain source-health and unknown-effect holds. After a timeout, inspect the
actual phase and owned-descendant cleanup before one bounded retry; repeated
failures require diagnosis/backoff. Do not inflate production deadlines or
weaken authentication. Diagnostic success alone does not clear a source hold;
an actual complete refresh does. A missing ledger is not empty-history startup.

Use same-owner native checkpoints/rollover when available, preserving the
charter, source references, assignments, effects, watch handles, parent gate and
one next action. Refresh applicable guidance after reconstruction.
On restart reconcile surviving processes and original effects before replacing
anything. An actual new-owner transfer needs accepted custody and owner-managed
settlement of tasks, claims and watches; stop owned schedules before transfer.
Do not silently migrate this run to a newly repaired registrar.

A continuous run remains Active through idle and blocked periods. Stop only on
operator retirement or accepted transfer, settling or explicitly transferring
all live obligations. A finite drain needs a fresh complete terminal census.
An accepted assessment, finished phase, opened PR or merged plan is not the
role's completion.
