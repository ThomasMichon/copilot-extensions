# Evidence, publication and continuity

Return to [the role](../SKILL.md).

## Per-issue record

Persist these semantics using the existing state owner's format, not a new
distributed database or provider-independent reservation service:

| Record | Required meaning |
|--------|------------------|
| Identity | Provider, target, native issue/work-item ID; query/filter scope |
| Input | Material revision, source capture time, complete discussion/link coverage, source pins and unavailable fields |
| Assignment | Actual worker handle and bounded scope; original owner and overlapping claims/PRs/plans; local versus native occupancy |
| Assessment | Complete or partial **triage assessment**, not whether a turn ended or software was fixed; target severity/classification; facts, hypotheses, unavailable checks, disposition |
| Next action | Responsible owner, one discriminating action and evidence/event/due-time revisit |
| Publication | Intended effect, reviewed input, permitted actor, actual effect ID/readback, owned summary ID, unknown-effect state |
| History | Prior accepted revisions/results, attempts, invalidations and explicit transferred obligations |

Useful dispositions include ready-for-delivery, needs-investigation,
needs-contributor-input, waiting-on-existing-work and needs-operator-decision.
They do not create labels or dispatch releases. A ready assessment still needs
separate sequencing and implementation admission. Route to the target's actual
classification contract rather than imposing this vocabulary on its evaluator.

Require route-specific evidence: a duplicate needs the same cause/reproduction,
not similar words; fixed/non-repro needs affirmative conditions and correction
proof; upstream needs implementation ownership and permitted traceability;
small-fix needs affected callers and bounded consequences; effort work needs
supported complexity, not unresolved cause alone. If severity or a required
check is unknown, withhold the completion marker and record the partial gap.

Do not use parent labels, a stale PR status, a current source HEAD, a helper
receipt or a synthetic control as proof of original impact, installed behavior,
release, deployment or actual acceptance. Preserve tests/review/rollout gates
without starting them under an evidence-only assignment.

## Separate proposal, acceptance and effect

1. A worker returns source-bound evidence and its exact artifact/receipt.
   A submitted result is neither accepted nor published.
2. Main verifies the complete artifact, assignment/revision and integrity where
   supported, compiles cited evidence and checks the route's unresolved criterion.
   Re-read the relevant owner/input boundary, not the entire investigation again.
3. Record accepted evidence durably before discovery advances or local occupancy
   settles. A current-input mismatch keeps the historical result but triggers
   delta reassessment; do not relabel it current.
4. For an authorized write, retain original intent before effect, then provider
   readback and local acceptance separately. Keep unknown IDs null and unknown
   effects held, never inventing a successful send or replacement action.

If a post succeeded but local validation failed, reconcile the original effect
instead of posting again. Verify its exact owner/ID before excluding it from
future material revisions. Update the canonical summary in place; lifecycle
claim messages remain owned by the reservation capability, not the summary.
Do not copy private payloads or local paths into public-facing findings.

An existing open PR/effort from another contributor is an ownership constraint,
not a request for a competing repair PR. Keep actionable feedback with that
original work when separately authorized, or record a quiet deferral. A missing
source pin can justify a specific clarification after investigation; it does
not prove the bug absent. Upstream filing and closure require their own scope
and privacy checks.

## Productive revisits and honest reporting

Distinguish material evidence from a coordinator's repeated progress comment.
On a due check, compare current source/owner/result with the accepted record
cheaply. No meaningful change and no discriminating next step means no worker
or public edit. Coalesce pending observations/launches; native completion events
already wake main and do not justify worker polling.

If the same bounded investigation leaves the same gap, name its rightful input
owner or choose a different discriminating read. Do not repeat source research,
ask the contributor for already available information, or turn uncertainty into
an effort solely to empty the agenda.

Report unique issues seen, complete assessments, partial assessments,
ownership deferrals and verified mutations separately. An exhausted paginated
census is not a transactional snapshot. Define coverage before backlog-wide
rates, contributor counts or efficiency claims; retained metadata is not full
discussion coverage. A private HTML report can be a stable projection, but its
local readback is not proof of cloud synchronization. Raw payloads, databases,
credentials and private runtime paths stay in the approved private state home.

## Holds, errors and responsibility

Retain a closed, charter-selected hold vocabulary with an owner and revisit:
input, existing-work, policy/approval, source-health, unknown-effect and capacity
are different conditions. A failed backend read is not a successful business
deferral. Successful identity verification is not complete source freshness.
Record query/identity/discussion/cache/report and cleanup phases separately.
A watcher output of "still running" is not failure or permission to launch a
duplicate. Missing data/history is not zero work, free capacity or fresh startup.

After a failure, inspect the original attempt and exact owned process/cleanup
receipt. Preserve an unresolved descendant or remote effect before retrying.
Use a bounded discriminating retry and owner-supported backoff for transient
errors. Repeated same-boundary failures need profiling/isolation; do not
increase production deadlines, remove safeguards or select alternate accounts
to manufacture a passing result. A longer **diagnostic-only** observation is
not qualification under the original budget.

## Continuous ownership and transfer

The canonical charter remains Active while idle, awaiting input or blocked.
An assessment, batch, skill PR or completed setup phase does not retire it.
When new work or relevant input exists, keep selecting the next eligible issue
without re-prompting; do not create a detached SDK worker to achieve persistence.

Same-owner rollover preserves native workers and shells, but reloads guidance
from its durable sources. Store no blanket "all guidance loaded" receipt.
Restart may have lost shells while native/remote work or provider effects remain;
inspect real survivors/handles before rearming one observation owner.
An old PID's absence never clears a distributed reservation.

Before actual transfer, preserve original grant/limits, current source/addendum
references, canonical summary IDs, pending actions, all actual worker/watch
handles and unresolved cleanup. Agree the receiving owner and scope.
Quiesce or transfer owned work through its owners; always stop owned native
schedules before handoff. Reconcile pending provider effects under their
original IDs. Neither a message ACK nor a new charter title transfers custody.

Migration to registrar-driven operation is a separate accepted handover:
verify the receiving task's selected target/filter, source/authority and
evidence format; retain the old ledger and unknown effects; confirm the old
publisher/watch is retired or transferred before admitting its replacement.
Do not erase local history or reset counts to make a repaired registrar look new.
