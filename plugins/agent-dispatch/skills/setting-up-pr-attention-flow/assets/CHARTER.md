## Acceptance and refusal walkthrough

Record actual adapter results and unknowns, not hypothetical success.

- [ ] Complete paginated initial/final census; partial results remain unknown.
- [ ] Positive concurrency target, prompt refill/authorized expansion, genuine
  work/capacity shortage and no overlapping same-PR reviewer.
- [ ] Missing original grant/task binding cannot become fabricated authorization.
- [ ] Missing required consent/provider precondition blocks its affected effect;
  providers without server fencing use the documented non-atomic fallback.
- [ ] Unknown old-owner custody/effects cannot authorize replacement or replay.
- [ ] Official retained-review carry, head/base changes and discussion-only updates.
- [ ] Unknown post/native ID, dismissed/wrong-actor review and original readback.
- [ ] Original-reviewer follow-up, actual context-loss recovery/replacement and
  reserved uncertain nudge retain prior findings, replies, receipts and unknowns.
- [ ] Automatic, agent-consent, authorized direct-self and human merge handling.
- [ ] Actual watcher cursor or single bounded polling owner, honest observation
  clocks, bounded backoff and no duplicate collector/unchanged reviewer relaunch.
- [ ] Native same-owner checkpoint versus explicit accepted new-owner transfer.
- [ ] Actual merge, owned effect/resource settlement and full parent gate.
- [ ] Empty continuous census does not complete; finite drain needs full proof.

Static documentation tests do not qualify runtime, clean-room or live-provider
effects. Missing adapter proof remains a named blocker or repository-permitted
review-only/manual handoff; no new daemon, scheduler or administrative bypass.
