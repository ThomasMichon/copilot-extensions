# Containers native admission and removal controls

The [suite testing guide](../../../TESTING.md) owns runner and isolation
mechanics. `test_managed_command_gate.py` runs actual Bash and PowerShell gates
with real prepared UV, a 3.10.20 application and an independent 3.11.18 helper.
Eighteen raw/materialized controls per native shell retain current/LKG/newest
and namespaced selection, readiness and invocation metadata, Legacy argument
forwarding, stdin, both streams, exit status, runtime/state roots and inherited
descriptors. Successful paths run twice with poisoned ambient Python/selectors
and shadow commands, while payload and slot bytes remain unchanged.

Missing UV/provider/capture refuses before application entry or provisioning.
Those controls use the existing explicit helper selector to isolate application
admission. Test-only observation counts native UV work without replacing UV:
one application lookup per Bash call; PowerShell additionally performs the
existing helper version check and helper lookup.

The path-gated Ubuntu/macOS/Windows jobs require every applicable case and report
without skips within eight-minute deadlines. Retained publication-policy,
evaluator/transport and readiness-import controls run separately.
Fresh-provision controls restore prepared UV after their setup-only refusal
stub, then require global command admission for both legacy and selected-cell
bindings. Namespaced
installation management retains Bash 4.4+ on macOS, selected after the command
packet runs under system Bash; canonical management under Bash 3.2 is not
qualified by the synthetic context decisions.

Inert modules and context decisions perform no Docker, Podman, backend, relay,
credential or service operations. This is not installed-host adoption, complete
command-latency measurement or qualification of other child producers.

The retained macOS global-stamp path also qualifies the existing Python fallback
transaction check on both Containers and Machines. It compares native
`os.fstat(8)` with the no-follow named lock rather than Darwin's descriptor
filesystem metadata. Six POSIX controls retain successful admission and
replaced-file/symlink refusal; native-flock behavior, persistent inode,
legacy-receipt refusal and close-only lock lifetime are unchanged.

## Native explicit setup

`test_installer_bootstrap.py` runs eighteen cases per native shell across raw
and materialized layouts. Repeated Inspect/Prepare samples record actual UV
work and timing, with poisoned ambient Python and foreign selectors. Missing UV,
the exact helper request or its prepared interpreter refuses without acquisition.
The cold-UV control substitutes a fixture-owned inert downloader, not an actual
network or user installation. Source-reader controls enter the real installer
and stop after isolated identity selection; independent application construction
creates and probes a real managed Python 3.11 environment without dependencies.

The path-gated POSIX command jobs require all eighteen cases and four repeated
reports without skips. The existing Windows Index/native-engine carrier runs
both PowerShell hosts (38 cases, eight reports), leaving the near-full Containers
Core job unchanged. Existing eight-minute budgets are preserved. These are native
source boundaries, not complete installation latency, installed fleet readiness
or production setup. `test_runtime_profile.py` separately retains profile intent,
immutable reuse, failed-candidate cleanup, source mutation and source stamping.

The prepared helper's native owners have different warm behavior: Bash Prepare
reaches `uv python install`, while PowerShell reuses an existing exact interpreter
without installation. The setup controls preserve those owner-specific work
counts rather than requiring a redundant Windows acquisition.

Twelve POSIX `test_installer_index.py` controls compare caller and payload UV
defaults through the actual canonical pip reader, retaining both relative and
absolute caller site prefixes and explicit pip configuration files. Relative
`PIP_CONFIG_FILE` paths remain caller-relative even when a different file exists
in the payload. The reader runs in the same payload context as
dependency installation, so an unrelated caller's default cannot suppress the
governed pip bridge or replace a payload's own default.

The raw constructor fixture retains its existing local `installer-engine.ps1`;
bootstrap support still belongs to the canonical helper/request owner rather
than that file's presence. The additional per-PowerShell-host control executes
the constructor's actual environment block. Null selection overrides must remove
keys, not retain empty strings: newer Core/.NET retains those empty values and
UV rejects an empty boolean selector. The native Windows packet also builds
the real managed environment under both PowerShell hosts.

## Prepared-only finite removal

`test_uninstall_bootstrap.py` invokes the real isolated legacy helpers with
prepared managed 3.11.18, private UV, poisoned PATH Python and inherited selector
hints. A repeated removal/idempotent pair retains durable/unknown bytes and
requires four actual UV calls with two acquisition-free managed lookups.
Missing UV refuses before helper/transaction entry; unavailable process
observation refuses without changing original runtime bytes. The POSIX utility
PATH retains `ps` for the existing guardian's real process-group settlement,
but omits flock so the same admitted interpreter exercises the fd-lock path.

The retained suite keeps real cleanup, all six kernel-custody variants and
actual responsive/stale broker and SSH-closure refusals. Its shared fixture
materializes the actual selected consumer, not Machines' different closure.
POSIX filesystem controls use a closed inert module and fixture-owned
observation, with an explicit unavailable-census negative control. They do
not qualify the production global process census; Windows retains its actual
current-user census. No production observer, lease or cleanup policy changes.

The path-gated native workflow requires 19 focused cases on each POSIX host
and 37 on Windows without skips: prepared-only/refusal, retained cleanup/kernel/
transport and activated-runtime metadata selection. Both Windows PowerShell
hosts run in the existing Index/native-engine carrier, whose spare budget
avoids extending the nearly full Containers Core job. This is a carrier, not
an Index implementation change or a full Windows Bash installer contract.
No runner or eight-minute job limit is added or enlarged.

Windows additionally requires stalled version/find selection to retire both
the actual selector root and its child before the calling PowerShell host
exits, under both shell engines. Those fixture deadlines are reduced from
thirty to eight seconds, never enlarged. A real selected venv inside the root
must refuse before the finite helper runs even though its actual base is
external; fixture-only observation records the real probe's original prefixes.
An older reader without the callback contract refuses before invocation.

Reproduce the repeated work report with
`tools/run-tests payload-invocation --test-file tests/test_containers_uninstall_bootstrap_source.py --allow-explicit-tiers --junit-dir <owned-output>`.
`containers_uninstall_bootstrap` records both elapsed samples, actual UV work,
offline operation and the process-observation scope. Those fixture timings are
not complete installation teardown or native tail measurements. No Docker,
Podman, production installation or service operation is part of these controls.
